# 原生解算器 vs Rapier 2D：獨立解算對照（Issue #101 PH-Rapier-2，第一步）

> **地位**：隔離實驗。不接入每日生態循環、Day0、存檔或日誌；`engine/` 沒有任何修改。所有場景都是合成世界（`synthetic: true`），不是臺中西屯花園。
> **不宣稱**：本頁不宣稱哪一方「比較準」或「比較快」；只列出下面實際跑過的量測。

## 1. 比較什麼

| 項目 | 原生（native） | Rapier |
|---|---|---|
| 程式 | `engine/physics/collision.ts` `simulate()`（PH-1 通道、MV-1 分段等速、PH-2 相遇規則） | `@dimforge/rapier2d-deterministic-compat` **0.21.0**（本子專案 `package.json` 精確釘版，`package-lock.json` 只屬於本子專案） |
| 時間 | 事件驅動，事件時刻是解析解 | 固定步長 `dt`（預設 1/120 s；掃描 1/60、1/120、1/240） |
| 空間 | **一維**：每隻只有沿通道弧長 `s`，**沒有橫向自由度**；轉成共同格式時設 `u = 0`（中心線） | 二維 `(x, y)`，有橫向自由度；牆由通道寬度（帶狀區的補集）與障礙物（圓 → ball、凸多邊形 → convex hull）建成 |
| 身體 | 沿通道的區間＋寬度（判定用）；轉成膠囊給共同裁判 | 膠囊碰撞體（長 L、半徑 w/2，與 `body2d.ts` 相同）；旋轉鎖定沿通道方向（模型選擇） |
| 驅動 | 自由速度＋相遇規則 | 每步把速度設為「朝目標點、自由速度」，接觸由 Rapier 解算 |
| **生物決策** | 讓路、交叉等待、接觸停頓、單行跟隨（interaction-candidates，**非本種**候選規則） | **完全沒有**。沒有讓路、沒有等待、沒有感知、沒有招募。原生事件中的 `behavioural_response` 在 Rapier 沒有對應——這是量測到的差異，不是遺漏 |

共同輸入：`scenarios/*.json`（schema：`scenario.schema.json`，載入：`lib/spec.ts`）只**引用** `scenarios/physics/` 的幾何與候選檔，以路徑取值：
- 體長 2.5 mm（`castes.minor.body_length_mm.value`，文獻支持 R94）；
- 碰撞寬度 0.8 mm：檔案 `value` 是 **null**，情境明確取候選範圍上限（遊戲假設，只作敏感度；與 `tests/ph2-collision.test.ts` 相同）；
- 觸角可及 1.0 mm：`value` 是 null，取候選範圍中點（遊戲假設）；
- 速度 15.5／17.0／18.5 mm/s（R133，文獻支持）；8 隻場景沿用 §9b 測試產生器的 15–19 mm/s（遊戲假設）；
- `inside_turn_back_probability` 取候選值 0.5（遊戲假設，與既有測試相同）。

**取到 null 的值會讓情境拒絕執行**（`ScenarioRefused`），不補值；通道高度有變化（2.5D）也拒絕，**不會把多層投影到一個平面**。單位一律 mm、s、mm/s。沒有新增任何大頭家蟻數值。

## 2. 共同裁判（`lib/judge.ts`）
兩方的輸出都轉成共同軌跡格式（`lib/traj.ts`：每隻 `[t, x, y, heading, s, u]`；事件分為 `physical_contact`、`physical_constraint`、`behavioural_response`、`motion`、`solver_status`），再用**同一個**裁判：
- `body2d.capsuleOf`／`capsuleGap`：每個時間點的成對間距（重疊＝間距 < −1e-9 mm）；
- `body2d.checkOccupancy2D`：每個時間點的二維占用契約（小場景）；
- 兩個時間點之間：每隻是直線等速（原生是精確的 MV-1；Rapier 是積分器本身的直線一步），成對間距對時間是凸函數 → 三分搜尋最小值、`sweptCapsuleContact` 求第一次接觸時刻。**取樣之間發生的接觸或重疊一定會被找到，不會因為沒取樣到而報 0**（測試中有正對照：兩個快速身體在兩個取樣點之間交錯，瞬間檢查 0、裁判找到 1 次、時刻與解析值相差 < 1e-9 s）；
- 另做密集取樣（小場景 2 ms）交叉檢查；
- 通道帶狀區（`capsuleInLane`）、障礙物侵入（圓：精確深度；多邊形：下限）；
- 「寬段重疊」：重疊處的可用寬度 ≥ 兩隻寬度和——代表存在並排排列，只是軌跡沒有橫向座標（原生 1-D 的情況）；
- 第二個報告門檻 1e-3 mm（高於 Rapier f32 座標解析度約 3e-5 mm），區分捨入與真實侵入。

## 3. 實際量測結果（2026-11-07，本機 4 核，Node v22.23.4）

指令：`node prototypes/solver-compare/run.ts --scenario <id> --sweep-dt`（輸出在 `out/<id>-<solver>.json`）。Rapier 欄是 dt = 1/120 s，CCD 關閉。時間是第二次（暖機後）執行的牆鐘時間；同時有其他量測程序在跑，**時間只能看數量級**。

**單獨一隻時的抵達時間誤差**（相對解析值 距離／速度＋出發時間）：
- 原生：所有場景 0（< 1e-9 s）；
- Rapier：head-on −2e-5、−2.1e-4 s；crossing −9.5e-4、+2e-5 s；corridor-8 +8e-4～+8.2e-3 s（出發時刻被量化到步長邊界，dt = 1/120 ≈ 8.3e-3 s）；stone 的 S2 單獨 +0.398 s（繞過石頭的路比較長）。

## 4. 反例（兩邊都有）
**原生**
- 沒有橫向座標：寬段並排在二維裁判下全是重疊（corridor-8 286＋17 次、stone 2 次、100 隻 111,475 次），全部在「寬度夠並排」的地方——是缺少 `u`，不是互斥失敗；但也不是二維可行性的證明（P2-E）。
- 原生的 stone：可用寬度模型讓螞蟻在石頭前停下，沒有繞行；u = +8 mm 的 S2 也一樣（1-D 忽略 u）。
- 100 隻格狀起點：t = 6.23 s 時 99 隻 `unresolved`，原生停止；1000 隻同一格點起點：單次 `simulate()` 在 1,500 s 內沒有結束（原生每個事件步重新評估所有成對組合，collision.ts 註解已記錄約 N² 成長）。沒有 1000 隻的原生輸出檔。

**Rapier**
- 沒有生物決策：head-on 兩隻在 1.0 mm 窄段永遠互推，誰都沒抵達。
- 軟接觸＋每步重設速度：corridor-8 中 8 隻在 1.0 mm 寬的窄段**互相擠過去**（兩隻寬度和 1.6 mm），重疊深度 0.55 mm、牆侵入 0.107 mm——物理上不可能。
- 對步長不收斂（§3.2）；1000 隻時有 260 次接觸只發生在取樣之間、身體完全穿過（0.8 mm）。
- 結果依建立順序而變（四個小場景中三個、兩個效能場景都是）；同順序重跑逐位元相同。
- 位置是 f32（座標 250 mm 處解析度約 3e-5 mm）。

## 5. 取捨（只依上表量測）

| 面向 | Native | Rapier | Hybrid（候選，未實作） |
|---|---|---|---|
| 事件時刻 | 解析解；單獨抵達誤差 < 1e-9 s | 量化到步長；單獨抵達誤差至 8e-3 s | 事件時刻由原生決定 |
| 不重疊 | 在其 1-D 模型內成立；沒有橫向座標 | 有橫向座標，但量到 0.05–0.8 mm 重疊與 0.1–0.55 mm 牆侵入 | 用 Rapier 只做空間查詢／見證（PR #96 的做法），約束仍由原生判定 |
| 生物決策 | 有（非本種候選規則） | 無 | 決策留在原生行為模型 |
| 收斂與重播 | 重播相同 | 重播相同；依建立順序；對 dt 不收斂 | — |
| 成本（本機量測） | 100 隻 3.8 s；1000 隻 > 1,500 s 未結束（本格點起點） | 100 隻 0.4 s；1000 隻 13.2 s | 未量測 |

沒有量測就不下結論：混合方案、橫向位置的原生二維解算器、Rapier 的其他驅動方式（力、運動學身體、更多解算迭代）都**還沒做**。

## 6. 尚未做
- 原生解算器沒有 `u`：二維原生（PH-3）是下一步；本頁的原生二維判定都是 `u = 0`（另附 `judge_u_held_at_spec`：把 u 固定在起點值，只在 stone 有差別）。
- Rapier 端只處理單層、直線、軸向對齊的通道；斜向通道、轉折、2.5D 都拒絕。
- 觸角接觸只由裁判依間距 ≤ 1.0 mm 計算；Rapier 沒有觸角感測器。
- Rapier 的參數（摩擦 0、恢復 0、密度 1、預設積分參數 `lengthUnit` 1＝1 mm、允許誤差 0.005 mm、預測距離 0.02 mm、解算迭代 4）都是預設或數值選擇，**沒有調參**；結果在每個輸出檔的 `params` 中。
- 沒有網頁播放、沒有 Pixi。

## 6b. 模擬終點（Owner P2，2026-11-07 更正）
- 前一版 Rapier 跑 `Math.round(H / dt)` 步：dt 不整除 H 時，最後一步可能**超過**終點（H = 1 s、dt = 0.4 s 會跑到 1.2 s，終點之後的抵達仍被計入），也可能**不到**終點（dt = 0.3 s 停在 0.9 s）。
- 現在：整步 dt 之後，以一個較短的最後一步剛好停在 H；只有 t ≤ H 的抵達才算。裁判另外把 t > H 的抵達改為 `null`，列在 `arrivals_after_horizon_excluded`；輸出的 `cost.simulated_until_s` 等於 H。
- 已提交的輸出不受影響：所有情境的 H（10、20、40、120 s）都是所用 dt（1/60、1/120、1/240 s）的整數倍；重跑小情境的軌跡雜湊與抵達時間逐位元相同。
- 測試：`tests/solver-compare.test.ts` 用 dt ∈ {0.3, 0.4, 0.07, 1/120} 與抵達前後的 H 檢查；舊程式在這些檢查上失敗。

## 7. 執行
```
cd prototypes/solver-compare && npm ci            # 只裝本子專案（Rapier 0.21.0）
node prototypes/solver-compare/run.ts --scenario head-on-2 --sweep-dt
node prototypes/solver-compare/run.ts --scenario corridor-8 --solver rapier --ccd
node tests/solver-compare.test.ts                 # 離線可跑；沒裝 Rapier 時只跳過 Rapier 檢查
```

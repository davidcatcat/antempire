## 2. F88-01 — P2：期末屍體批次未重建，總量平衡可以掩蓋蛋白轉移與批次返老

位置：`cli/lib/source-flow-replay.ts:103–110`；引擎 `engine/ecology.ts:75–110`。

讀取器會依期初批次重算分解／到期事件，這一步正確；但期末只把全部批次的蛋白加總。引擎快照也只保留批次 ID 與食源總量。兩邊都沒有核對每個期末批次的剩餘量及不可變的 `original_day`。既有 ME-1 帳本在此同樣只檢查食源總量，不能補上缺口。

### 獨立重現

從 Day14 fixture 的世界建立生態步驟，F07 放入兩個各 1 份、來源欄位完整的測試批次：

- `REVIEW-OLD`：original_day = 6，當日年齡 9；
- `REVIEW-YOUNG`：original_day = 14，當日年齡 1。

保持當日天氣與全部事件不變。合法對照在生態步驟後兩批各剩 **0.714835** 份，引擎及獨立讀取器接受。

| 只改期末狀態的攻擊 | 引擎 checkSourceFlows | replaySourceFlows |
|---|---|---|
| 舊批次減 0.1、年輕批次加 0.1，食源總量與 protein 欄位不變 | 接受 | `ok: true, errors: []` |
| 只把老批次 original_day 由 6 改為 14 | 接受 | `ok: true, errors: []` |

兩項攻擊都沒有新增食物轉移或新屍體事件。讀取器回報 `unevented` 四項均為 0。

這不只是顯示欄位：讓三個版本在下一日相同無雨天氣下再跑 `growEcology`，原版本 F07 到期蛋白為 **0.714835**，轉移版本為 **0.614835**，返老版本為 **0**。轉移版本當日總剩餘蛋白比原版本多 **0.086**；返老版本則多 **0.614758**。沒有任何合法事件授權這些供應量差異。

### 需要修改

生態步驟檢查應按 `site + event_id` 重建期末批次，核對出生日期、年齡及剩餘量，而非只核對食源總量。完整日讀取器還須銜接新屍體、獵殺與採集對批次的合法影響；不能把合法採集誤判為分解。至少新增上述兩項反例及未變更的合法對照；每個聲稱覆蓋此契約的檢查器應各自拒絕。

這不是宣稱正常產生器已自動返老，而是新驗證契約會接受能改變未來食物供應的偽造輸出。

## 3. F88-02 — P2：期初超容量的既有花蜜被當成「從未分泌」，開關打開即中止

位置：`engine/ecology.ts:189–193`；相同公式也在 `cli/lib/source-flow-replay.ts:66–70`。`validateWorld`（`engine/day.ts:64`）沒有期初存量必須低於容量的限制。

### 使用預設參數重現

1. `loadBundle()`，Day0 A1，seed **2**，日期 **2027-03-21**。
2. F08 設定 `sugar = capacity + 1 = 3.4`、`capacity = 2.4`、`bloom_days_left = 0`。
3. `validateWorld(start)` 通過。沒有改任何生態參數；該日 `rain_mm = 0`。
4. 開關關閉：`simulateWorldDay` 成功。
5. 只打開 `source_flows.record_source_flows_v26`：拋出：

```text
Error: SOURCE_FLOW F08: 3.4 + flows 0 ≠ 2.4 after the ecology step
(a change without a flow, or a flow without a change)
```

公式此時計算 production = 0、excess = 1，分泌量變成 −1；`flow()` 因不大於 0 而不記錄它。另記的 `capacity_withheld = 1` 被排除於存量帳外，因此既有的 1 份減少沒有流出事件。

這個狀態沒有由一般 Day0 產生器自然產生的證據；但它是目前公共入口接受的非負、有限狀態，在降低容量或匯入既有世界時也必須有明確契約。新測試只覆蓋「恰好等於容量」，因此 1,870 次 on/off 比較沒有涵蓋此邊界。

### 需要修改

先把既有存量的超量與當日潛在分泌分開。`capacity_withheld` 不能大於當日潛在分泌量，也不能吸收既有食物的流失。若保留舊 clamp，既有量的減少應記為實際流出，並允許同一日同時有未分泌與流失；目前 mode 檢查也需配合。另一選項是在雙方共同的輸入契約中明確拒絕超容量狀態，但須說明相容性變更，不能繼續宣稱對全部現有合法輸入只增加事件。

以無雨、無開花與期初高於容量作回歸，並檢查蜜露的 withheld 選項是否有相同問題。

## 4. F88-03 — P3：分泌與再吸收的證據，不能直接支持「未曾存在」

位置：`docs/design-source-flows-v26.md` §3–4；`docs/references.md` R389；`engine/ecology.ts` FLOW_BASIS.capacity_withheld。

R389 為 Nepi & Stpiczyńska (2008), *The complexity of nectar: secretion and resorption dynamically regulate nectar features*, *Naturwissenschaften* 95:177–184，DOI **10.1007/s00114-007-0307-2**。

文件正確註明只讀摘要、非本花園、植物間差異大，也將事件標為 assumption。然而「存量受分泌與再吸收共同調節」並不等於「達固定上限後那部分從未分泌」：再吸收是已存在花蜜回到植物，應有來源、去向及先前生產；抑制分泌才是未生產。二者可以有相同末存量，事件歷史與因果不同。

建議把證據表拆開：

- 文獻支持：花蜜 standing crop 是分泌、移除／再吸收等過程的結果。
- 本版候選假設：以硬容量抑制分泌、超量 never_existed；尚無本花園物種實驗證據。
- 未實作替代：分泌後再吸收，須另有流量，不得以同一末存量推定其不存在。

Way (1963), *Mutualism between ants and honeydew-producing Homoptera*, *Annual Review of Entomology* 8:307–344，最多提供蜜露累積與相關生物利用的一般機制背景；它不能驗證本站固定容量或溢出速率。文件目前有註明數值是假設，應保留這個限制。

本輪沒有取得上述兩篇全文，因此不宣稱重新核對過全文。這項意見來自文獻所述機制與程式事件定義之間的推論界線，不是以缺少全文判定程式錯誤。

## 6. 科學判讀與未變更事項

v26 增加的是可食食物池的收支可見性。`loss:*` 是模型邊界外的去向，並未建模分解者、植物內部物質或外部消費者，所以閉合不等於整個生態系物質守恆，更不等於本種生物學驗證。遊戲份量也尚不能直接和乾重、糖量或能量觀測互換。

屍體依舊在超過壽命時刪除剩餘蛋白。文件已揭露其與「尚有可食量」的矛盾，未將它列為本輪新發現；事件補齊不代表該假設獲得科學支持。固定競爭者比例、雨沖量、每日分解率及花園容量仍需獨立資料與觀察算子評估。

## 附錄：最小重現核心

以下在本提交根目錄以 Node 22.23.4 執行。檔名使用 `.ts`，不需編譯；引擎檢查須觀察生態步驟狀態，不能將完整日的採集後狀態直接傳入。

```ts
import { loadBundle } from './cli/lib/load.ts';
import { buildDay0 } from './cli/lib/day0.ts';
import { resolveBundle, simulateWorldDay, legacyToWorldState, legacyColonyMeta } from './engine/index.ts';
import { fixture } from './tests/lib/harness.ts';
import { validateWorld } from './engine/day.ts';
import { growEcology, checkSourceFlows, sourceSum } from './engine/ecology.ts';
import { calcWeather } from './engine/weather.ts';
import { replaySourceFlows } from './cli/lib/source-flow-replay.ts';
const off: any = loadBundle(), on: any = structuredClone(off);
on.world.source_flows.record_source_flows_v26 = true;
const wp = resolveBundle(on).world;
const start: any = legacyToWorldState(fixture() as any, legacyColonyMeta(on.world.scenario_colonies as any));
const id = Object.keys(start.sources).find(k => start.sources[k].type === 'carcass')!;
start.sources[id].batches = [
  { event_id:'REVIEW-OLD', original_day:start.sim_day+1-wp.carcasses.carcass_max_lifetime_days, protein:1, age_days:8, origin:'review' },
  { event_id:'REVIEW-YOUNG', original_day:start.sim_day, protein:1, age_days:0, origin:'review' },
];
start.sources[id].protein = 2;
const snapshot = Object.fromEntries(Object.entries(start.sources).map(([k,s]: any) =>
  [k,{type:s.type,food:sourceSum(s),batches:s.type==='carcass'?s.batches.map((b:any)=>b.event_id):[]}]
));
const end: any = structuredClone(start), events: any[] = [];
const weather = calcWeather(end, wp, '2027-03-22');
growEcology(end, wp, weather, events);
const result = {weather,world_events:events,colonies:[]};
const mode = {honeydew_withheld:wp.source_flows.honeydew_capacity_limits_secretion,
              nectar_withheld:wp.source_flows.nectar_capacity_limits_secretion};
for (const attack of ['control','shift','younger']) {
  const fake: any = structuredClone(end);
  if (attack==='shift') { fake.sources[id].batches[0].protein-=.1; fake.sources[id].batches[1].protein+=.1; }
  if (attack==='younger') fake.sources[id].batches[0].original_day=start.sim_day;
  const after: any = structuredClone(fake.sources);
  for (const e of events) if (e.type==='new_food_source')
    after[e.site].batches=after[e.site].batches.filter((b:any)=>b.event_id!==e.id);
  checkSourceFlows(snapshot,after,events.filter(e=>e.type==='source_flow'),mode,start.sim_day+1);
  console.log(attack,'engine accepted',replaySourceFlows(start,fake,result,wp));
}
const s: any = buildDay0('A1',2,'2027-03-21',off).state;
const nectar = Object.keys(s.sources).find(k=>s.sources[k].type==='nectar')!;
s.sources[nectar].sugar=s.sources[nectar].capacity+1;
s.sources[nectar].bloom_days_left=0;
validateWorld(s);
console.log('off accepts',simulateWorldDay(structuredClone(s),off).result.weather.rain_mm);
try { simulateWorldDay(structuredClone(s),on); }
catch(e) { console.log('on rejects',String(e)); }
```

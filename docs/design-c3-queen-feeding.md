## 2. 設計
### 2.1 蟻后個體狀態（資料結構；為多后預留）
- `population.queens: Queen[]`，每隻蟻后：
  - `id`、`alive`；
  - `body_sugar`、`body_protein`：自己的身體區室，單位是遊戲份數，**不是 mg**；
  - `last_fed_day`、`days_unfed`：自己的經歷；
  - `eggs_laid_total`。
- 現在只有一隻蟻后；`queen_alive` 改為由 `queens` 推導，保留讀取相容。
- **初始儲備是未知量（D）**：Day0 創巢的蟻后儲備沒有本種資料。以情境參數宣告、標 `assumption: true`，並做敏感度範圍；Day14 遷移以 `null` 起算，不倒填。

### 2.2 最低限度、可驗證的局部接觸事件（巢內空間 P1-B 之前的過渡）
- **接觸位置**：巢內設一個「蟻后所在的巢室」標記 `queen_chamber`。這是**模型假設（D）**，不是量測到的巢室；P1-B 的巢室幾何完成後取代。
- **誰可能接觸蟻后**：只有當日任務是育幼（`nurse`）、且當日在巢內的工蟻。每隻保育工蟻用**以自己 ID 命名的亂數串流**，決定：
  - 當日是否到蟻后巢室（機率 D）；
  - 在巢內結算時段中的抵達順序值。
- **處理順序**：依每隻工蟻自己抽到的抵達值，同值時依 ID。**不依陣列位置**（#56）。
- **每次接觸是一筆事件**：`queen_contact`，記錄工蟻 ID、蟻后 ID、地點 `queen_chamber`、順序值、依據。
- **餵食**：
  - 接觸時，工蟻把自己**嗉囊裡實際有的**糖交哺給蟻后，量以蟻后需求與單次上限為上限（D）。
  - 蛋白：工蟻在接觸前從巢內蛋白倉取用、帶到蟻后處。這個「取用→交給蟻后」的路徑是 D 類假設；本種的蛋白交給蟻后的實際方式（固體、交哺分泌物）未查到資料。
  - 每一筆都是 `food_transfer`：
    - 糖：`crop:<工蟻> → queen_body:<蟻后>`，原因 `feed_queen`，歸因 `individual`，附接觸事件 ID；
    - 蛋白：`cache:<巢> → queen_body:<蟻后>`，原因 `feed_queen`，歸因 `individual`，附接觸事件 ID。
- **沒有工蟻接觸就沒有食物**：蟻后不從全巢帳自動取得任何東西。

### 2.3 蟻后自己的代謝、產卵與存活
- **代謝**：每日由 `queen_body` 支付（`food_transfer queen_body → metabolized`，歸因 `individual`），溫度係數沿用現行 Q10（一般生理學，C）。身體區室不足時，記為**該蟻后自己的缺口**。
- **產卵**：
  - 輸入只有：蟻后自己的儲備、自己的缺口紀錄、巢溫，以及**實際接觸到**的訊號（例如保育工蟻接觸時傳來的幼蟲求食訊號；這在 C4 才有）。
  - **移除全巢幼體數壓力**（`existing_brood_pressure × broodCount`）與全巢 `ratios`、`stores`。
  - 卵的成本由 `queen_body` 支付（`queen_body → egg:<卵 ID>`）。
  - 候選模型：
    - (a) 日機率，依儲備門檻（D）；
    - (b) 批次與暫停（Chang 1985、Yuan 2026 有質性證據 A；批次大小與間隔的數值是 D），依 #38 的設計。

    兩者並列，做敏感度與型態比較，不挑存活率最高的一組。
- **存活**：
  - 蟻后的營養危險依**自己的** `days_unfed` 與儲備，取代全巢 `stress_days`；
  - 「沒有工蟻」的危險改為「多日沒有被任何工蟻接觸」，這也是蟻后自己的經歷；
  - 自然年齡危險仍未建模，照實標示 `not_modelled`。
  - Chang 1985 的「無工蟻的蟻后 2～3 週內死亡」（A，條件型）作為驗證型態，不作為輸入。

## 4. 拆成小 PR
1. **C3a**：資料結構（`queens[]`、`queen_body`）、狀態遷移、`queen_contact` 事件與 `feed_queen` 轉移。產卵仍用舊規則；開關預設關閉；隔離。

3. **C3c**：蟻后存活改依自己的經歷。

## 0. 摘要
1. **蛋白「送到蟻后」在本種沒有被直接觀察到。**
   - Sanders, Chang, Ota & Nomura 1992（本種，全文）原文：「The feeding of protein to queens by workers was not observed.」
   - 同一研究中，標記的蛋黃「was fed to queens only after the larvae were fed」：幼蟲先得到，蟻后後得到，而且量很少（48 h 幼蟲 87.5%；蟻后約 1.9～2.2% 的全巢回收放射量）。
   - 工蟻在食物處把固體蛋白切成小塊，帶回巢放在幼蟲頭部附近的凹陷處；作者推論工蟻只攝取液體部分（水與胺基酸）。
2. **蟻后能自己取食**（Chang 1985，本種，全文）：「The queen could forage for food and water for herself」。Sanders 1992 也觀察到：沒有看到工蟻餵蛋白，但 6 h 時所有蟻后中腸都有綁在固體上的染料。
3. 因此，原設計的「工蟻從倉庫拿蛋白直接交給蟻后」（路線 A）在本種**證據最弱**。修訂後：
   - **主模型 B1**：工蟻嗉囊中的**液態**蛋白經交哺給蟻后（本種方向：Sanders 推論工蟻吸取液體部分；Tsuji & Win 2025 液態蛋白經交哺在巢間流動）。
   - **主模型 B2**：幼蟲加工路線：固體放到末齡幼蟲身上 → 幼蟲體外消化 → 工蟻收入嗉囊 → 交哺給蟻后。本種觀察（「先到幼蟲、後到蟻后」，A）與 B2 相容，但**不唯一識別 B2，也不排除 B1**（Sanders 的數字是回收放射量／染料，不是各區室蛋白 mg 或攝食流率）；機制只有他種（B）。B2 依賴幼蟲接觸（C4）。
   - **開關 C**：蟻后在同一巢室親身接觸食物、自行取食（A，條件型）。
   - **路線 A**（工蟻用大顎把固體帶到蟻后處）：只做敏感度比較。
   - 這四條都**不能寫成已證實的本種餵食機制**；它們是候選模型，要並列做型態比較。
4. 原設計 T2「沒有工蟻接觸就沒有食物」與 Chang 1985 衝突。改為：**「沒有局部、有來源、有時間與地點的事件，蟻后就不會增加營養」**。事件可以是工蟻接觸，也可以是蟻后親身接觸食物。這仍符合 D3：蟻后只依自己實際攝取的食物與自身生理運作。
5. **Day14 遷移的蟻后儲備記為 `null`，不得轉成 0，也不得倒填。** C3 先只在 Day0 實驗世界啟用（§6）。

## 2. 區室（食物在哪裡）
**原則**：持有不等於攝取；巢裡有不等於蟻后吃到；工蟻搬了蛋白不等於工蟻吃了蛋白。

| 區室 | 意義 | 可持有 | 增加的方式 | 減少的方式 |
|---|---|---|---|---|
| `cache:<nest>`（拆成 `cache:<nest>/<chamber>`，見 §3） | 巢內儲存的固體蛋白 | 蛋白（固體） | 卸貨 | 被工蟻取用、被蟻后自行取食、溢出或腐壞 |
| `carried:<worker>`（新） | 大顎持有的固體 | 蛋白（固體） | 從 `cache` 或食源取用 | 交付、放到幼蟲身上、放回、掉落、搬運者死亡 |
| `crop:<worker>`（**改為分類**） | 嗉囊（社會胃，仍是持有，不是已吸收） | `sugar`、`protein_liquid` 分開記，但**共用一個總容量**（§12.3） | 採集、交哺、從固體吸取液體 | 交哺、自身攝取（C5） |
| `worker_body:<worker>`（C5） | 工蟻自己已吸收的營養 | — | 自身攝取 | 代謝 |
| `queen_body:<queen>`（新） | 蟻后**已攝取**的營養（生理儲備），不是倉庫 | `sugar`、`protein`；分成 `unknown_initial_reserve`（可為 `null`，不可支出）與 `known_balance`（§12.4） | 只有 `feed_queen`（交哺）、`queen_ingest`（接受固體後攝取可攝取部分）、`queen_self_feed` | 只有蟻后自身代謝、產卵、死亡 |
| `queen_offer:<queen>`（新，只用於路線 A） | 放在蟻后身旁、尚未吃下的固體 | 蛋白（固體） | 工蟻交付 | 蟻后攝取、成為殘渣 |
| `larva_pocket:<larva>`（新，B2，C4 才用） | 放在末齡幼蟲旁、體外加工中的固體 | 蛋白 | 工蟻放置 | 幼蟲攝取、工蟻收走分泌物、成為殘渣 |
| `larva_body:<larva>`（C4） | 幼蟲已攝取 | — | — | — |
| `refuse:<nest>`（新） | 殘渣與丟棄物 | 任意 | 移除殘渣 | 分解（之後的生態工作） |
| `corpse:<worker>` 或 `dropped:<location>` | 搬運者死亡或掉落時貨物的去處 | 任意 | 死亡或掉落事件 | 之後的規則；二選一，要明文規定（D） |

- 每份食物在任何時刻只屬於一個區室。
- 全巢 `stores` 只是各區室加總的唯讀統計，不得作為任何個體決策或生理的輸入。這是目標狀態（C5 之後）。**C3a 過渡期間**舊的代謝、產卵與溢出程式仍會寫 `stores`；`stores` 的加總範圍（**不含 `queen_body`**）與舊路徑如何閉合，見 §12.1。

## 3. 地點與時間（最低限度、可驗證的局部接觸）
本種沒有巢室配置的資料（P1-B 未完成）。C3 使用**明示的模型假設（D）**：
- 巢內有三個具名位置：`store`（蛋白倉）、`queen`（蟻后所在）、`brood`（幼體）。位置之間的移動是事件。
- **巢內時間**：結算階段目前沒有分鐘。C3a 加一個巢內回合，用**序數時間**（不是分鐘）：每隻參與的工蟻以自己 ID 命名的亂數串流抽抵達值，同值時依 ID 排序。不依陣列位置（#56）。這是時間解析度假設，P0-A 的分鐘時鐘完成後取代。
- **抵達檢查**：每筆交付的時間必須晚於或等於持有者抵達該位置的時間；取用時間必須早於離開取用位置的時間。
- 蟻后的位置是 `queen`；只有蟻后的位置與食物相同時，才可能有 `queen_self_feed`（開關 C）。`store` 與 `queen` 是不是同一處，是一個假設參數（D，兩種都做敏感度）。

## 4. 事件鏈
**B1（主模型）：液態蛋白經交哺給蟻后**
1. `take_from_cache`：工蟻在 `store`，從固體蛋白吸取液體部分：`cache → crop(protein_liquid)`。量受固體實有量限制。
2. `move`：`store → queen`，帶序數時間。
3. `queen_contact`：工蟻與蟻后同在 `queen`，記錄雙方 ID、位置、序數時間。
4. `feed_queen`：`crop:<worker>(protein_liquid) → queen_body:<queen>`，附 `contact_event_id`。量不超過嗉囊實有量與單次上限（D）。
5. 蟻后可以拒絕（例如已飽足，門檻 D）：拒絕就沒有轉移，食物留在嗉囊。

糖用同一條鏈，只是嗉囊裡的糖來自採集（已有）。

第 1 步 `take_from_cache` **只屬於「固體蛋白在 `cache`」這個起點**。嗉囊裡的糖或液態蛋白也可以有其他合法來源（採集、同伴交哺、候選的液態蛋白採集、C4 的幼蟲分泌物、有 basis 的初始狀態），這時不需要 `take_from_cache`。`feed_queen` 要驗證的是**依路徑的來源鏈**，見 §12.2。

**B2（主模型，依賴 C4）**：`take_from_cache` → `carried` → `move(store→brood)` → `larva_contact` → `place_solid_on_larva`（`carried → larva_pocket`）→ 等加工時間（他種方向，數值 D）→ `collect_larval_secretion`（`larva_pocket → crop(protein_liquid)`）→ `move(brood→queen)` → `queen_contact` → `feed_queen`。

B2 會自然產生「幼蟲越多 → 經實際接觸流向蟻后的蛋白越多」，不需要讀全巢幼體數。但 Chang 1985 記錄到沒有幼蟲時蟻后仍會產卵，所以 B2 不能是唯一路線，必須和 B1 或 C 並存。

**C（開關）：蟻后自行取食**：`queen_encounter_food`（蟻后與 `cache` 或 `larva_pocket` 同位置）→ `queen_self_feed`：只有可攝取的部分進入 `queen_body`（比例 D），其餘不動。

**A（只做敏感度）**：`take_from_cache`（`cache → carried`）→ `move` → `queen_contact` → `offer_solid`（`carried → queen_offer`）→ `queen_ingest`（可攝取部分進入 `queen_body`）→ `remove_residue`（其餘進入 `refuse`）。

**未完成的情況**
| 情況 | 規則 |
|---|---|
| 沒有取用 | 起點是 `cache` 固體的路徑（B1 的蛋白、B2、A）：沒有 `take_from_cache` 就沒有持有，不可能有 `feed_queen`。其他起點依 §12.2 的來源鏈 |
| 取用不足 | 只能轉移實際持有的微份 |
| 重複餵食 | 每份持有物只能被清空一次；每次接觸、每種食物最多一筆 |
| 沒有接觸 | 食物留在原持有區室（嗉囊、`carried`），依規則放回或繼續持有；不得消失，也不得自動進入蟻后 |
| 搬運者死亡 | 貨物進入 `corpse:<worker>` 或 `dropped:<location>`；不得繼續被搬運或交付 |
| 受食者拒絕 | 留在原持有區室（B1），或成為殘渣（A） |
| 工蟻或蟻后不對、地點不同、抵達前就交付 | 拒絕（兩個檢查各自拒絕） |

**守恆**：所有新轉移都是 C2 的 `food_transfer`，通過依時間的名冊、路徑表與執行期格式驗證。新區室加入名冊，例如：`carried` 只能屬於當時存在的工蟻；`queen_body` 只能屬於當時存活的蟻后。

## 5. 蟻后個體狀態（為多后、多巢預留）
- `population.queens: Queen[]`，每隻蟻后有：
  - `id`、`alive`、`location`（巢 ID 加巢內位置）；
  - `body`：`{ unknown_initial_reserve: null | 'not_applicable', known_balance: { sugar: number, protein: number }, basis: 'day0_scenario' | 'unknown_at_migration' }`（§12.4；修訂 2 的 `sugar: number | null` 把未知與已知混在一個數字裡，已取代）；
  - `days_unfed`（沒有任何攝取事件的天數，含自行取食）、`days_without_worker_contact`（沒有任何 `queen_contact` 的天數），兩者分開（§12.5）；`last_fed_ordinal`、`intake_event_ids`。
- 現在只有一隻蟻后；`queen_alive` 改為由 `queens` 推導，保留讀取相容。
- 多后時不共用 `queen_body`（本種常見多后：Yuan 2026 每群 2～7 后；Sanders 1992 實驗群 20 后）。
- 多巢：巢 ID 進入地點，跨巢移動是事件（開放生態 OE 規格）。

## 6. 初始儲備與遷移
- **本種沒有蟻后儲備量或斷食耐受的資料**。只有蟻后體重 3.94 mg（Sanders 1992，作換算用）。Chang 的「2～3 週」不是儲備量。
- **Day14 正式存檔**：
  - 蟻后儲備記為 `null`，`basis: 'unknown_at_migration'`；不得填 0，也不得倒填。
  - **C3 在正式切換到新版 Day0 之前，只在 Day0 實驗世界啟用**，正式世界保留舊路徑。這樣不必在 Day14 歷史上追認未知的個體狀態。
  - 若日後必須在 Day14 投影中啟用，`null` 的語意是「未知儲備不可支出」：代謝與產卵只能用遷移後的已知收入，不足時記為蟻后自己的缺口，並在日誌與報告中明寫這個後果。不得把 `null` 當成 0 寫進存檔。**`null` 加上已知收入不等於整個儲備變成已知**：未知部分與已知部分分開記（`unknown_initial_reserve`／`known_balance`，§12.4），這條保守界線是 D 級假設。
- **新版 Day0**：初始儲備是候選假設（D），以「蟻后每日代謝（模型值）的 k 倍」表示，k ∈ {0, 3, 10, 30}。A1～A5 每個情境都跑完整掃描，不挑存活率最高的；結果記錄來源、範圍與敏感度。

## 7. 蟻后自己的代謝、產卵與存活（C3b、C3c）
- **代謝**：每日由 `queen_body` 支付（`queen_body → metabolized`，歸因 `individual`）；溫度係數沿用 Q10（一般生理學，C）。不足時記為該蟻后自己的缺口。
- **產卵**（C3b）：
  - 輸入只有蟻后自己的儲備、自己的缺口紀錄、巢溫，以及實際接觸到的訊號（C4 起才有幼蟲求食訊號）。
  - **移除全巢幼體數壓力**（`existing_brood_pressure × broodCount`）與全巢 `ratios`、`stores`。
  - 卵的成本由 `queen_body` 支付。
  - 候選模型兩種並列：日機率；批次與暫停（Chang 1985、Yuan 2026 有質性證據，批次大小與間隔是 D）。不挑存活率最高的一組。
- **存活**（C3c）：
  - 營養危險依蟻后自己的 `days_unfed` 與儲備；
  - 「沒有工蟻」的危險改為「多日沒有被任何工蟻接觸」，這是蟻后自己的經歷；
  - **「沒有接觸」不等於「沒有攝食」**：自行取食（開關 C）會讓 `days_unfed` 歸零，但不會讓 `days_without_worker_contact` 歸零。無社會接觸的危險只能是**候選的非營養危險**（C／D，本種沒有資料），不得被當成飢餓或併入營養危險（§12.5）；
  - 自然年齡危險仍未建模，照實標示 `not_modelled`。

## 12. C3a 過渡契約（Codex 2026-11-04／05 §6、§10 第 4 點）
C3a 只換掉「蟻后怎麼得到食物、蟻后自己的代謝從哪裡付」，其餘仍是舊規則。下面定義新區室和舊路徑同時存在時，帳如何閉合、哪些事件必要。本節是實作驗收契約，不是現存程式的故障；開關關閉時一切與前一版逐位元組相同（T5）。

### 12.1 `stores` 的加總範圍與舊路徑
- 現況（`engine/nutrition.ts` `consume`／`storageOverflow`、`engine/queen.ts` `oviposition`）：舊程式直接寫 `colony.stores`；卵的糖成本經 `settleCrops` 從工蟻嗉囊（陣列順序）扣，蛋白從 `stores.protein`（C2 的 `cache`）扣；全巢代謝包含蟻后那一份（`servedQueen`）。
- **C3a 開關打開時的「舊帳範圍」**：糖＝Σ `crop.sugar` ＋ `nest_unlocated`；蛋白＝`cache`。只有這些區室可被舊代謝、舊產卵與溢出扣帳，`colony.stores` 只對這個範圍加總。
- **不在舊帳範圍內**（舊規則不得扣，N15）：`queen_body`（已攝取，不是存量）、`carried`、`queen_offer`、`larva_pocket`、`crop.protein_liquid`。後四者另列統計 `held_outside_legacy_stores`，仍由 C2 逐區室閉合追蹤。
- **轉入蟻后**：`feed_queen`、`queen_ingest`、`queen_self_feed` 的量離開原區室時同步記負的 `nest_ledger_delta`（若原區室在舊帳範圍內），進入 `queen_body` 後不再出現在 `stores`。
- **巢內回合收尾**：回合結束時 `carried` 必須清空（交付、放回 `cache`、或依 §4 進入 `corpse`／`dropped`），不得帶著未結的持有進入舊結算。
- **蟻后代謝**：開關打開時 `consume` 的需求移除 `servedQueen` 那一份，蟻后代謝只由 `queen_body.known_balance` 支付，不足記為蟻后自己的缺口（不再走全巢帳），避免重複扣。全巢 `ratios` 因此不再含蟻后，舊產卵的 `enough` 條件輸入跟著改變；所以「產卵規則不變」指公式與參數不變（§9）。
- **舊產卵（C3a 不變，A08 未修）**：卵的糖成本仍經 `settleCrops`（只動 `crop.sugar`，再 `nest_unlocated`；C2 `recordSettlement`），蛋白成本仍從 `cache`，歸因 `unknown`。**不得從 `queen_body` 扣卵成本**；C3b 才改由 `queen_body` 支付。
- **舊蟻后存活（C3a 不變，F01／A08 未修）**：仍讀全巢缺口天數。`queen_body` 的缺口在 C3a 只記錄、不影響存活；C3c 才改。修正前不得在 C3a 結果上做蟻后營養的科學結論（CLAUDE.md §2.1b）。
- **順序（D）**：巢內回合放在舊結算（`consume`）之前；之後的順序做敏感度（§11 第 7 點）。

### 12.2 依路徑的來源鏈（取代 N1 的無條件要求）
- 嗉囊是可互換的池，不追蹤每一微份的身分（D）；來源鏈的驗證是**餘額層級**：在 `feed_queen` 的序數時間，給出者嗉囊該食物種類的餘額 ≥ 給出量，而且這份餘額的每一筆收入都是路徑表上的合法邊、序數時間更早（或是有 `basis` 的初始狀態）。
- 合法收入（路徑表）：

| 進入 | 合法來源 | 證據／狀態 |
|---|---|---|
| `crop.sugar` | 採集（`in_transit → crop`，C2 已有）、同伴交哺、初始狀態 | 現行 |
| `crop.protein_liquid` | `take_from_cache`（B1，起點是 `cache` 固體） | 候選；本種方向（Sanders 推論工蟻吸取液體部分） |
| `crop.protein_liquid` | 同伴交哺（`crop.protein_liquid → crop.protein_liquid`） | 候選；Tsuji & Win 2025 液態路線（A） |
| `crop.protein_liquid` | 在食源直接吸食液態蛋白（例如蛾卵內容物，Dejean 2007） | **候選**；目前引擎沒有液態蛋白食源，C3a 不產生，只在路徑表保留 |
| `crop.protein_liquid` | `collect_larval_secretion`（B2，C4） | **候選**；機制只有他種（B） |
| `carried` | `take_from_cache`、食源取用 | 路線 A／B2，候選 |

- `take_from_cache` 只在來源鏈起點是 `cache` 固體時必要。
- **時間**：C3a 事件用序數時間驗證，同值依 ID 決定；舊 `nest_settlement` 轉移（`minute: null`）仍標「時間未驗證」，不因與 C3a 事件並存而取得時間驗證結論。這採用 Codex F1 對 C2 的教訓（F1 本身屬於 #60／#63）。

### 12.3 分類嗉囊的共同總容量
- 每隻工蟻只有一個總容量：`crop.sugar + crop.protein_liquid ≤ trophallaxis.crop_capacity`（沿用現有參數，不另給兩個完整容量）。任何收入（採集、交哺、`take_from_cache`）的剩餘空間都用總量計算（N14）。
- 一份糖與一份液態蛋白占用相同容量，是 **D 級假設**（份數是遊戲單位，不是 mL 或 mg）；做敏感度，不宣稱是本種量測。
- 開關關閉時嗉囊只有糖，與現行逐位元組相同。

### 12.4 未知初始儲備與已知收支分開
- `queen_body` 分成 `unknown_initial_reserve` 與 `known_balance`（Codex 稱 `known_post_migration_balance`；對遷移的蟻后就是這個意思）。
- Day14 遷移的蟻后：`unknown_initial_reserve: null`、`known_balance: {sugar: 0, protein: 0}`、`basis: 'unknown_at_migration'`。收入只加到 `known_balance`；代謝（C3a）與產卵（C3b 起）只能從 `known_balance` 支出，不足記為蟻后自己的缺口；`null` 永不被支出、補值或轉成 0（N12、N16）。
- 新版 Day0 的蟻后：`unknown_initial_reserve: 'not_applicable'`，情境儲備（§6 的 k 倍）放進 `known_balance`，`basis: 'day0_scenario'`。
- **D 級假設**：只允許支出已知部分是保守界線，會**高估**遷移蟻后的缺口（真實儲備被當成不可用）。這個後果要寫進報告與日誌；在此界線下得到的蟻后缺口不得當成科學結論。

### 12.5 C3c：沒有接觸 ≠ 沒有攝食
- 兩個計數器分開：`days_unfed`（當日沒有 `feed_queen`、`queen_ingest`、`queen_self_feed` 任何一筆）與 `days_without_worker_contact`（當日沒有 `queen_contact`）。
- 自行取食只歸零 `days_unfed`。有自行取食、沒有工蟻接觸的蟻后不是「未攝食」。
- 營養危險只讀 `days_unfed` 與 `known_balance`。無社會接觸的危險是**候選的非營養危險**（C／D，本種沒有資料），開與關兩種都做敏感度。Chang 1985「只有蟻后的巢 2～3 週內死亡」是在有食物、蟻后自行取食的條件下，死因未辨識：只能作 T7 的型態比較，不能用來校準營養危險，也不能指定為某個非營養機制。

## 14. C3a 實作紀錄與物理接觸的介面契約（v2-review.25，2026-11-05）
**實作狀態**：C3a 已實作在開關 `queen_feeding.individual_queen_body_c3a` 之後（預設關閉；關閉時與 v2-review.24 逐位元組相同）。實作：`engine/queen-feeding.ts`；C2 擴充：`engine/transfers.ts`；獨立讀取器：`cli/lib/engine-transfers.ts`（`c3a` 參數）、`cli/lib/queen-round-replay.ts`；測試：`tests/c3a-queen-feeding.test.ts`。

**實作了什麼**（依 §9 第 1 點）：
- 區室：`queen_body:<queen>`（`unknown_initial_reserve` 與 `known_balance` 分開，§12.4）；嗉囊分類為 `crop_cargo_sugar` 與 `crop_cargo_protein_liquid`，共用 `trophallaxis.crop_capacity`（§12.3，採集、交哺與 `take_from_cache` 都用總量計算剩餘空間）。
- 巢內回合（序數時間）：在舊結算（`storageOverflow`、`consume`）之前。參與者是任務為 `nurse`、當時在巢節點的工蟻；每隻以自己 ID 命名的亂數串流抽抵達值（同值依 ID）。在 `store` 取用（路線 B1）→ `nest_move` → 在 `queen` 位置 `queen_contact` → 每次接觸、每種食物最多一筆 `feed_queen`；蟻后依自己的已知收支拒絕（飽足門檻 D）。
- 放回（§4「依規則放回」，D）：回合結束時，工蟻嗉囊中沒有餵出的液態蛋白走回 `store`，以 `return_to_cache`（`crop → cache`）放回。嗉囊中的液態蛋白只存在於回合內，不會帶到隔天，因此不會占用採糖的共同容量。
- 路線 C（`queen_self_feed`）：只有蛋白倉與蟻后同一位置（`store_is_queen_location`，預設 false）時才可能發生。
- 蟻后代謝：由 `known_balance` 支付（`queen_metabolism`，個體歸因），從全巢代謝移出；不足記為 `shortfall_today`，**只記錄**，產卵與存活仍用舊規則（C3b、C3c）。
- 舊帳範圍（§12.1）：`stores.sugar` = Σ 嗉囊糖 ＋ `nest_unlocated`；`stores.protein` = `cache`。舊代謝、舊產卵、溢出的路徑表都不包含 `queen_body`，嗉囊中的液態蛋白也不在舊帳內（N15）。

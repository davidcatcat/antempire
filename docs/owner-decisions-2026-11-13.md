## 1. #212 新版正式 Day0 的架構與範圍
| 題 | 裁示 | 要點 |
|---|---|---|
| Q1 | A | 正式世界採 P0-A2 連續時間、個體／事件驅動模型；Worker 與 Node 驗證器共用同一套決定性核心；生命史以事件子模型逐步接入。舊日步長引擎只作研究、資料與參數來源，不直接包成正式核心。不得把未實作機制假裝已模擬。 |
| Q2 | a | **D4-A 完整繁殖、D7-A 開放生態不再是最低可信 Day0 的「完整實作」硬性條件。** 未接入時，畫面、存檔中繼資料、文件與驗收報告必須清楚標示「尚未模擬」，不可用隱藏補給或代用演出冒充。**放寬完整度不等於放寬守恆、決定性、存檔恢復、生命狀態正確性與觀測誠實性**；已聲稱實作的機制仍須通過阻擋測試。 |
| Q3 | a | 初期只宣稱 x64 Linux／Node 22／Chromium 的已驗證一致性；ARM64、Safari、Firefox、實體手機可實驗性遊玩，須顯示「未經 Node 重算驗證」，不宣稱逐位元一致；另排實機相容性／回放驗證（連 #192）。 |
| Q4 | a | 不提供未簽章外部報告匯入作為可信驗證；未簽章 JSON 不能讓畫面顯示「Node 已驗證」。可信執行環境內直接重算的結果可用於 CI／正式驗收。 |

### 與 2026-11-03 D4-A／D7-A 的關係
[`owner-decisions-2026-11-03-d4a-d7a.md`](owner-decisions-2026-11-03-d4a-d7a.md) 把 D4-A、D7-A 列為新版正式 Day0 的必要條件。#201（2026-11-12）選「最低科學可信版」，#212 Q2（2026-11-13）明確裁示：**兩者仍是產品目標與後續工作，但不再是最低可信 Day0 的硬性完整實作條件**；未接入部分依上表標示「尚未模擬」。D4-A／D7-A 的科學要求（自主發生、不強制產生、不以「缺資料而關閉」宣稱完整、邊界進出要有生態因果）在接入時照常適用。`requirements-and-plan.md`、`product-vision.md`、`roadmap.md` 已同步加註；2026-11-03 決策紀錄本身不改寫。

| 題 | 裁示 | 要點 |
|---|---|---|
| Q1 | a | CHEM-0 暫維持 `isotropic_diffusion: false`；只代表目前模型範圍，不代表自然界不擴散；文件／畫面標明擴散尚未模擬。 |
| Q2 | b | CHEM-3 前建立簡單的地表／基質溫度模型（氣溫、日照、遮蔭；與蟻群無關；係數標來源或 `assumption:true`；保留氣溫代理對照；不冒充現地測量）。 |

| Q4 | 待核 | 「Draft 2018」暫按 R810 候選索引；完成書目核對前標「待核」；即使確認也只是跨物種候選機制。 |

## 3. #214 育幼生理
| 題 | 裁示 | 要點 |
|---|---|---|
| Q1 | a | 交哺／育幼候選都不升格預設；保持隔離、預設關閉、基準可重現。 |
| Q2 | a | 先建立幼蟲階段別能量與蛋白質／氮源需求及物質收支；缺值標 `assumption:true`；不得為製造差異放大需求。 |
| Q3 | a | 卵→三幼齡→蛹→成蟲發育時鐘、溫度依賴、營養不足的延遲／死亡風險；以 Yuan et al. 2026（28°C 卵到成蟲約 28.73 ± 2.83 天）為錨點並註明外推限制。 |
| Q4 | a | 另開獨立規則更新 PR 修正閒置接觸 `larvae` 清單覆寫；舊紀錄以版本識別，禁止靜默改寫。 |

## 4. #202 Day0 初始條件（暫定實驗規格，非 GO）
| 項 | 暫准開發的假設 | 正式啟用前必須滿足 |
|---|---|---|
| 小工蟻 | 50～500 對數均勻，`assumption:true` | 不宣稱為臺中野外分布；不依存活率改範圍 |
| 蟻后 | 預設 2～3；1～3 作敏感度對照 | 多后個體、產卵、死亡與存檔確實實作 |
| 大工蟻 | 隔離、標假設的比例候選 | 支援大工蟻個體／工作／能量／存檔，才能宣稱完整初始蟻群 |
| 幼體 | 零／低／中／高事前定義情境，全部 `assumption:true` | #214 完成後決定正式分布 |
| 入場日 | 固定 2026-11-13（Asia/Taipei），專案測試基準日，**不是**最佳建巢季節；全年另列敏感度 | 寫入 scenario metadata |
| 母巢 | 場景外、完全分離，明示為模型邊界 | 母巢連通另開規則更新 |
| 種子 | 20261113，可重現標識，**不是**挑選的種子 | 固定 PRNG／抽樣順序／scenario checksum，寫入存檔並驗證 Worker／Node 一致；正式上線前依 #201 再釘選 |
| 花園供給／需求 | 另開獨立稽核研究 | 不倒推資源保證存活 |

## 2. 架構
```
geometry.ts（PH-1）  ←  kinematics.ts（MV-1/2）  ←  collision.ts（PH-2/3）  ←  prototypes/physics（Work C）
        ↑                       ↑ rng.ts（命名亂數流）
 scenarios/physics/*.json（合成場景與候選值；不是 species/*.json）
```
- 全部是純函式，不使用平台 API，相同輸入得到相同輸出。
- 不讀也不改任何食物、嗉囊、幼體或族群。`physics-isolation` 測試同時禁止兩件事：
  - 正式管線（`engine/*.ts`、`cli/`、`web/src`）以任何形式參照 `physics/`；
  - physics 匯入食物或族群模組。
- 資料格式：`antempire.physics-geometry.v1` 是 P1-B `antempire.world-geometry.v1` 之上的**物理圖層**，不重新定義地點或路網。
  - 通路以 `route_edge_ref` 掛在路網的邊上。
  - 通路長度必須等於該邊的移動長度（G9），所以移動長度只有一個來源。

## 3. 單位與時間
- 長度 mm、時間 s、速度 mm/s。與路網層（cm、分鐘）之間只透過明確的換算函式。
- 沒有固定時間步：
  - 速度在兩次改變之間是常數；
  - 事件時間以解析求得：直線用一次式，跨通路兩個圓用二次式；
  - 窄段邊界改為解析求根（Codex 物理審查 F2）：圓形障礙、多邊形的頂點圓與邊帶、斜坡上的高度範圍，切點之間只判斷一次。舊的 0.01 mm 掃描會漏掉比取樣間距短的窄縮。
  - 仍是數值掃描＋二分法的，只有交叉讓路的「已讓開」時刻與退讓目標（已寫明）。
  - 跨通路的高度層（Codex 物理審查 F1）：
    - 兩隻在不同通路上，只有高度差 |dz| ≤ 體長＋1e-6 mm 時才互相作用（明示的簡化）。
    - 高度差在兩個事件之間是線性的，所以「同層」時段可以精確求出；接觸、碰觸只在這個時段內發生。
    - 走下坡進入同一層時，若平面足跡已經重疊，兩隻都停止並回報 `unresolved`（垂直方向的接近沒有模擬），不會穿過去。
  - 起點等於終點的工蟻在出發時刻直接抵達，不移動（Codex 物理審查 F3）。
- 事件標準排序：時間 → 種類 → 個體 ID → 參照，**從不依陣列順序**。
- 完全對稱的平手：用命名亂數流 `physics.yield` 決定，鍵是排序後的兩個 ID。

## 4. 數值與證據
| 值 | 來源 | 標記 |
|---|---|---|
| 小工蟻體長 2.5、大工蟻體長 3.5、大工蟻頭寬 1.3 mm | Yuan et al. 2026（R94），廣西實驗室族群 | 文獻支持（本種，約值） |
| 頭寬範圍：minor 0.50–0.61、major 1.10–1.54 mm | Sarnat et al. 2015（R99） | 文獻支持（本種，分類學範圍） |
| 碰撞寬度候選：minor 0.5–0.8、major 1.1–1.8 mm | 下限取 R99 頭寬最小值；上限是工程候選 | 遊戲假設，`value: null`，只做敏感度 |
| 沿跡速度：合併 17.0、離巢 18.5、回巢 15.5 mm/s | Vázquez et al. 2020（R133），實驗室人工路線，條件已列在候選檔 | 文獻支持（本種）。方向差異**不**解釋為負重 |
| 離跡倍數 0.5 | 沿用正式引擎 v17 的值 | 遊戲假設 |
| 個體速度變異 CV | 沒有資料 | `null` |
| 觸角可及距離候選 0.5–1.5 mm | 沒有資料 | 遊戲假設，`value: null` |
| 單行跟隨 | 不可重疊的物理結果 | 物理推論，**不是減速比例** |
| 迎面退讓、交叉讓路、寬段並排不花時間 | 本種沒有窄道相遇資料 | 遊戲假設（候選規則） |

規則的局部性：
- 「回頭路較短的那隻退讓」需要比較兩隻的狀態，是**成對的物理解法**，不是任何一隻螞蟻能知道的資訊。這點在 `interaction-candidates.json` 中寫明。
- 這條規則不讀全巢資訊，但**會讀對方剩餘的路線**（比較回頭距離、對方之後要走的路）。這是成對的工程求解器，不是單隻螞蟻能感知的局部資訊；Codex 物理審查指出前一版寫「不讀任何遠處資訊」與程式不符，已更正。進正式模擬前必須換成局部規則；即使日後找到本種相似的讓路行為，也不能因此讓個體讀取對方的計畫路線。

## 5. 與行為、營養的接點（C3–C5）
- 物理層只產生 `contact_start`／`contact_end` 事件，內容包括：
  - 時間、位置、雙方；
  - `certain`：寬通路上因為橫向位置未模擬，標為 `false`。
- **接觸 → 行為 → 營養**是一條因果鏈，物理層只負責第一段。
  - 交哺、招募、攻擊等是否發生，由 C3–C5 依個體的局部訊號決定。
  - 食物轉移必須走既有的 `food_transfer` 帳本與守恆檢查。
  - 物理層不建立任何食物交換。

## 6. 接進正式模擬的條件（未來的規則更新 PR）
1. 把 `engine/physics/` 加入 `cli/lib/load.ts` 的 `ruleFiles`，讓它進規則指紋；同時移除或調整 `physics-isolation` 中對正式管線的禁止規則。
2. 候選值移進 `species/*.json`、`world/*.json`，維持證據標記：未知值保持 `null`，未知值會讓物理層回報 `unknown`，不代入數字。
3. 正式花園的幾何（P1-B）目前大多未知。沒有幾何的路段要沿用既有路網的時間模型，不能捏造。
4. 依 CLAUDE.md §6，要有開關關閉時逐位元組相同的隔離證明，並做多日、多種子、極端情境的評估。結果在下一個遊戲日才生效。

  - 讓路規則使用非局部資訊（比較兩隻的狀態、對方剩餘路線），已揭露，進正式模擬前必須替換。

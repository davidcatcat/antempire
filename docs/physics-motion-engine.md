## 2. 架構
```
geometry.ts（PH-1）  ←  kinematics.ts（MV-1/2）  ←  collision.ts（PH-2/3）  ←  prototypes/physics（Work C）
        ↑                       ↑ rng.ts（命名亂數流）
 scenarios/physics/*.json（合成場景與候選值；不是 species/*.json）
```
- 全部是純函式，不使用平台 API，相同輸入得到相同輸出。
- 不讀也不改任何食物、嗉囊、幼體或族群。`physics-isolation` 測試同時禁止兩件事：
  - 正式管線（`engine/*.ts`、`cli/`、`web/src`）以任何形式參照 `physics/`；
  - physics 匯入食物或族群模組。
- 資料格式：`antempire.physics-geometry.v1` 是 P1-B `antempire.world-geometry.v1` 之上的**物理圖層**，不重新定義地點或路網。
  - 通路以 `route_edge_ref` 掛在路網的邊上。
  - 通路長度必須等於該邊的移動長度（G9），所以移動長度只有一個來源。

## 3. 單位與時間
- 長度 mm、時間 s、速度 mm/s。與路網層（cm、分鐘）之間只透過明確的換算函式。
- 沒有固定時間步：
  - 速度在兩次改變之間是常數；
  - 事件時間以解析求得：直線用一次式，跨通路兩個圓用二次式；
  - 窄段邊界改為解析求根（Codex 物理審查 F2）：圓形障礙、多邊形的頂點圓與邊帶、斜坡上的高度範圍，切點之間只判斷一次。舊的 0.01 mm 掃描會漏掉比取樣間距短的窄縮。
  - 交叉讓路的放行時刻改為解析求得（`releaseTime`，PH-P1-A）；仍是數值掃描＋二分法的，只有交叉讓路的退讓目標（已寫明）。
  - 位置與事件時間一律由**運動紀錄的起點、速度與經過時間**直接計算，不逐步累加（PH-P2-C）；成對事件在兩隻運動紀錄起點中較晚的那一刻求解，與哪一步、哪個時間窗來問無關。
  - 跨通路的接觸、碰觸與放行全部用同一個幾何 `discEncounter`：由 |r + v·t|² = R² 與「最近距離」b = |r × v| / |v| 判斷；b 與取樣時刻無關。剛好相切（b = R，容差 `LEN_TOL`）算擦過，不算接觸（PH-P1-B）。
  - 時間窗邊界是明確的：時間窗結束之後的事件，即使只晚 1e-12 s，也不在該時間窗處理（PH-P2-B）。PH-P2D 起更進一步：**時鐘只停在事件時刻**，時間窗結束不是計算時刻；時間窗只決定 broadphase 收集多遠的成對，沒有事件在時間窗內時只延長時間窗、不移動任何東西、不處理任何事件。所以以容差判斷的「現在就處理」（身體相距 1e-7 mm 內、前緣站在邊界上等）只會在事件時刻判斷，與 `window_s` 無關。
  - 跨通路的高度層（Codex 物理審查 F1）：
    - 兩隻在不同通路上，只有高度差 |dz| ≤ 體長＋1e-6 mm 時才互相作用（明示的簡化）。
    - 高度差在兩個事件之間是線性的，所以「同層」時段可以精確求出；接觸、碰觸只在這個時段內發生。
    - 走下坡進入同一層時，若平面足跡已經重疊，兩隻都停止並回報 `unresolved`（垂直方向的接近沒有模擬），不會穿過去。
  - 起點等於終點的工蟻在出發時刻直接抵達，不移動（Codex 物理審查 F3）。
- 事件標準排序：時間 → 種類 → 個體 ID → 參照，**從不依陣列順序**。同一時刻＝與最早事件相差不超過 `SAME_INSTANT`（時間值的 16 ulp，數值容差，不是模型參數）；同一時刻內依 KIND_ORDER（例如接觸紀錄先於碰觸處理）、個體 ID、對方 ID、資料值、時間排序。
- 完全對稱的平手：用命名亂數流 `physics.yield` 決定，鍵是排序後的兩個 ID。

規則的局部性：
- 讓路規則 v1 以每隻自己能感知的資訊為主：自己是否已在窄段內、自己與碰到的那隻是否帶負載、前方是否碰到身體、是否被推。v0 的「回頭路較短者讓」與「使用對方剩餘路線」已移除。
- **仍有的非局部步驟（已揭露）**：
  - 「已完全在窄段內」以兩隻寬度和決定的單行區段為準，是幾何代理；
  - 抽中的讓路者背後沒有寬處時改由另一隻讓，是成對步驟；
  - 入口排隊的放行是協調用解法；
  - 退讓目標點是預先算出的。
- **超出文獻之處**：L. niger 的讓路者原地等待；本模型的單行通道旁沒有空間，讓路者退到最近的寬處，可能退很遠。
- 除了上面列出、已揭露的非局部步驟，這條規則不讀遠處資訊或全巢資訊。v0 曾讀取對方剩餘的路線（比較回頭距離），Codex 物理審查指出 v0 文件寫「不讀任何遠處資訊」與程式不符；v1 已移除這一步。

## 5. 與行為、營養的接點（C3–C5）
- 物理層只產生 `contact_start`／`contact_end` 事件，內容包括：
  - 時間、位置、雙方；
  - `certain`：寬通路上因為橫向位置未模擬，標為 `false`。
- **接觸 → 行為 → 營養**是一條因果鏈，物理層只負責第一段。
  - 交哺、招募、攻擊等是否發生，由 C3–C5 依個體的局部訊號決定。
  - 食物轉移必須走既有的 `food_transfer` 帳本與守恆檢查。
  - 物理層不建立任何食物交換。

## 8. Owner 決策（2026-11-06）與仍待裁示

**決策 1：入口讓路**
- 物理實驗的預設候選模型是入口讓路：`encounter.priority = entry_yield`。依據是 R380，*Lasius niger*。

**決策 2：嗉囊液體**
- 嗉囊內的液體**不**算帶食優先的條件。

## 1. 摘要

- 【觀測】離線重播顯示：換掉「一工蟻一接觸、一日只取一次」的結構，送達／需求可以從 19.4 % 移到 74.0 %（T8R，測試值）；同一批世界、同一批種子，沒有挑選。
- 【推導】結構放寬後，下一個瓶頸依序是：①當天沒有保育工蟻（28.5 % 的幼蟲日，任務抽籤，不是巢內回合能解的）；②幼蟲自己的求食訊號低於門檻或已飽；③糖：發育輸入 x 取糖與蛋白的較小值，蛋白送到後，糖變成 x 的限制。
- 【觀測】在這些世界中，store 不是瓶頸：即使把額外取出的蛋白全部算成回饋，保守上界下 store 低於一口的群體日只有上界情境的 1.4 %。
- 【推導】C4b 四種形式在這些輸入下仍無法區分（x 幾乎只有 0 或 1）；C4c 若用「已知不足 5 日起算」的危險率，會與本種唯一的停食觀察（Phillips 1933，停食 2 週後仍化蛹）方向衝突。

## 3. 候選機制與數學（全部預設關閉；未實作進引擎）

### 3.1 P：餵食順序（Q1）
- 現行：store → 蟻后 → 幼蟲（`engine/queen-feeding.ts`）。候選 P1：store → 幼蟲 → 蟻后。
- 在真實時間軸上，「順序」不是一條規則，而是工蟻的路線與每段花的時間；本種沒有路線選擇的資料（`null`）。P1 只是 R346 結果順序的最簡單對應。

### 3.2 T：時間預算接觸（Q3）
- 保育工蟻 w 在巢內的時間 `H_w`（來自 P0-A 活動時間軸的巢內分鐘，`null` 時只用序數時間）。動作序列 a₁…aₙ，每個動作有持續時間：接觸 `d_c`、交哺 `d_f`、往返 store `d_s`、探視蟻后 `d_q`（**全部 `null`**；R210 的 11 ± 2 s 是非本種的交哺持續，只作量級參考）。
- 接觸次數不是參數，而是 `n_w = max{ n : Σ_{k≤n} d(a_k) ≤ H_w }`。離線比較中用測試格點 k ∈ {1, 2, 4, 8, ∞} 代替，**不是接觸頻率的候選值**。
- 每次接觸：在同一地點的幼蟲中均勻抽一隻（以工蟻 ID＋序號命名的亂數流）；若 `bᵢ ≥ θ` 且自己今日攝取 `Iᵢ,f < needᵢ,f`（自己的飽足，假設；方向：R210 非本種「飽的幼蟲被餵頻率低」），就給固定一口 `min(held_f, bolus_f)`。
- R：嗉囊沒有液態蛋白時回 store 再取一次，占用一個時段；每次取 `min(take_cap, 嗉囊剩餘容量, store)`。**嗉囊容量不變**，糖與蛋白仍共用（Owner 限制）。
- 上限：`D ≤ min( Σ_w n_w · bolus_P , Σ_w 取用次數 · take_cap , Σ_i needᵢ )`；現行結構 n_w = 1、取用 1 次，得到 41.8 % 的上限。
- 與 P0-A 排程相容：每次接觸／交哺／往返都是事件（工蟻、幼蟲、地點、序數或分鐘、來源）；沒有分鐘紀錄的事件不畫在精確分鐘上。

### 3.3 B：固體蛋白直接放到幼蟲旁（Q2）
- 帳的對應（全部是現有 food_transfer 格式）：

| 轉移 | 來源 → 接收 | 說明 |
|---|---|---|
| `pick_solid_piece` | `cache` → `mandible:<工蟻>` | 用大顎搬，不進嗉囊，所以不占嗉囊容量 |
| `larva_ingest_solid` | `mandible:<工蟻>` → `larva_body:<幼蟲>` | 只在接觸到的那隻幼蟲；它能吃固體（齡期門檻 `s*`，`null`）且自己未飽；吃 `min(塊, needᵢ − Iᵢ)`（假設） |
| `return_solid_to_cache` | `mandible` → `cache` | 回合結束沒吃完的放回 |
| （B2 候選）幼蟲體外溶解後工蟻吸回 | `larva_body` 或新區室 `brood_site_solid` → `crop` | R348 非本種；本研究未重播 |

- 引擎沒有齡期，只有進度 `progress`。離線比較用 `progress ≥ 2/3` 當「三齡中的末齡」的**測試代理**，不是候選值。

### 3.4 攝取 → 發育（Q4）
- 鏈：`feed_larva`／`larva_ingest_solid` → `fed_balance` → 自己支付的代謝 `paidᵢ = min(needᵢ, balanceᵢ)` → `xᵢ = min_f paid_f/need_f` → `N(xᵢ)` → `Δprogress = r_s(T)/larva_days · N(xᵢ)`（C4b，不改）。
- 結構候選只改變 x 的分布，不改 N 的形式。N-a／N-b／N-c 在比較中只用 design-c4b §10 的測試值；N-d 需要 Q（`null`），不能算。

### 3.5 個體飢餓與死亡（Q5）
- 保守設計（Owner 限制）：只**記錄** `known_unmet_daysᵢ`（自己已知蛋白支付 < 需求的連續日數），危險率 λ **不接上**（C4c h2）；未知儲備不當 0。
- 若日後接上，λ 的形式與參數全部 `null`；候選另有「工蟻食幼」路線（非本種 R208、R215），它是工蟻的局部決策與 `larva_body → crop` 的轉移，不是幼蟲自己的生理死亡。

讀法（數字都出自上表）：
- P1（幼蟲先於蟻后）：19.4% → 24.0%；代價是蟻后蛋白／需求 85.4% → 71.1%。
- 只增加接觸、不能回 store（T2～T8）：最多到 42.4%；T8 中 25.8% 的幼蟲日是「達門檻但工蟻手上沒蛋白」——一日只取一次＋與糖共用嗉囊成為新的瓶頸。
- 允許回 store（T8R）：74.0%；無限時間的上界 88.9%。剩下的是「無保育工蟻」28.5%（任務抽籤）與幼蟲線索／已飽。
- 固體路線（B，接觸仍一次）：28.4%（任何幼蟲都能吃）、20.7%（只有末齡代理）；它主要消除「工蟻嗉囊被糖佔滿」與「先給蟻后」（達門檻但無蛋白 12.0% → 0.1%）。
- 時間預算下順序的效果取決於「store 那一趟算不算時間」：P1_T8R 67.8% 低於 T8R 74.0%，因為重播中蟻后段之前的取用不占時段；這是時間成本未知（`null`）造成的模型差異，不是生物結論。
- 回饋：額外取出的蛋白只有 6.1%～17.0% 由當日溢出抵銷；但保守上界下 store 低於一口的群體日只有 1.4%（上界情境），其他候選 0.0%。
- 糖：T8R 的糖攝取／需求 52.2%；上界情境 x = 0 仍有 54.1%，蛋白送到後 x 被糖限制。
- C4b：三種形式的平均 N 差距很小（例如 T8R：0.44973／0.452273／0.469853），因為 0 < x < 1 的幼蟲日只有約一成；這些輸入不能用來選形式（與 design-c4b §10.3 一致）。
- C4c：引擎基準 284 隻幼蟲中 226 隻曾連續 ≥ 5 日已知蛋白不足、11 隻 ≥ 14 日。若用「5 日起算」的危險率，大多數幼蟲會死，與 Phillips 1933（本種，停食 2 週後仍化蛹）的方向衝突；已知不足又高估真實不足（儲備未知）。

## 5. 依賴順序

1. **送達結構（P／T／B）先於 C4b 形式選擇**：現行結構讓 x 幾乎只有 0 或 1，任何形式比較都只是在比較結構的人為現象。
2. **T 需要時間軸**：接觸次數由巢內時間與動作持續時間決定，依賴 P0-A 排程與活動時間軸（v17）；在持續時間是 `null` 時，只能以序數時間＋測試格點做敏感度，不能當正式值。
3. **C4c 只記錄，不接危險率**，直到有儲備模型（C4b 的 N-d 累積量，或 C5 個體代謝）。
4. **C5 個體代謝**（工蟻自己的身體帳 F01、蟻后依自己的身體產卵 A08／C3b）要在 P1 之前或同時處理：P1 降低蟻后得到的蛋白，但目前產卵不讀蟻后自己的帳，所以 P1 的代價在模型中看不見。
5. **任務分配（候選 D）** 是結構放寬後最大的單一瓶頸（28.5 % 的幼蟲日當天沒有保育工蟻），屬另一個工作包；本種沒有一手資料。

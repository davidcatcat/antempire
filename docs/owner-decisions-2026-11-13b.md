## 1. #219 花園供給與蟻群消耗（Q1～Q6）

| 題 | 裁示 | 要點 |
|---|---|---|
| Q1 | 採 mg／J | 新的個體與生態核心：糖、蛋白以 **mg** 計（內部可用整數 µg 或更細的定點），能量以 **J** 計；液體量與濃度另記（µL、mg/µL 或質量分率）。糖、蛋白、能量不得混成單一「份」。舊資料與遊戲份只留在有版本、標 `assumption:true` 的轉換／對照層，原始值與轉換值都可追溯；不得用假定係數冒充本種實測。耗能機制要列出轉換效率與物質流向；可用嚴格守恆的定點表示，並保持事件切分與重播的決定性。 |
| Q2 | 允許 | R950、R952（非本種）只作**候選量級與敏感度先驗**，須標物種、地區、氣候、測定條件與不可外推之處；同時保留低／中／高與「無蜜露來源」反例。 |
| Q3 | 允許明示假設區間 | 半翅目群拆成個體數、每隻分泌率、糖濃度、每日分泌時數等獨立、有單位的假設區間，依場景溫光與物候計算產量；**不得為符合消耗或提高存活率而倒推產量**；群體增減必須有事件與收支。 |
| Q4 | 允許明示假設區間 | 獵物生物量採隔離的低／中／高情境；昆蟲個體帶體重、可食比例與營養組成；同一隻獵物的總生物量不因死法而改變；未知值保留 `null`／「尚未模擬」。 |
| Q5 | 同意分階段 | **RU-1 → RU-2 → RU-6 → RU-3 → RU-4 → RU-5 → RU-7**（定義見 [`garden-supply-demand-audit.md`](garden-supply-demand-audit.md) §5）。依賴允許時可並行研究；每階段各自開 PR，驗收並版本化後才整合；不可先提高花園供應再補單位。 |
| Q6 | Day0 不直接放行 | 維持 #201 由 Owner 最終 GO、#206 目前 NO-GO。最低要求：已啟用的外生食物供應、可追溯的實際取食、糖／蛋白／能量帳、無秘密補給，並經多種子與極端環境驗證。仍未模擬的個別機制必須在 #206 逐項證明不是最低版的關鍵阻擋並清楚標示。 |

## 2. #222 P0-A2 育幼生理（Q1～Q8 全部採 A）

| 題 | 裁示（A） | 要點 |
|---|---|---|
| Q1 | 質量／能量需求候選 | 幼體糖、蛋白分開記 mg（內部整數 µg 或定點），能量記 J，與 #219 共用**同一套契約**。74.7 µg 蛋白、65.7 µg 糖及其不確定區間只是**隔離候選**，不是本種定值，也不得因原型需求太小就直接放大。 |
| Q2 | 液態蛋白優先 | 先做可逐隻對帳的液態蛋白餵食；固態蛋白「僅 L3 可接受」是隔離、預設關閉的研究候選（來源非本種），與其他齡期候選並列比較。 |
| Q3 | `linear_dd_A` | 隔離主候選；`flat`、`linear_dd_B`、`q10_refit` 為預先登錄的對照；`briere` 缺 Tmax 時不宣稱可用。28°C、28.73 d 是校準錨點，不是獨立驗證，也不外推全溫域。 |
| Q4 | `N-d` | 有量綱的化學計量限制作隔離主候選，分別記錄蛋白限制、成長能量不足與維持消耗不足；N-a～N-c 為對照。只有實際局部接觸並完成物質移轉事件的量才可入帳，不得讀全巢食物資訊。 |
| Q5 | `protein_catabolism: false` | 第一版不允許無來源的蛋白→能量轉換；要有證據與完整的碳／氮／能量及排出物收支，才可另建可選的研究模型。 |
| Q6 | H0 基線＋H1/H2/H3 隔離候選 | 目前為 `null` 的死亡閾值、比率與形狀參數不得偷設預設值。恢復餵食時先**保留已累積的 hazard**（保守實驗假設），與歸零候選並列敏感度。未接入可信死亡機制前，畫面、存檔與 #206 須列出「飢餓造成的生理死亡尚未模擬」，並判定是否仍為 Day0 阻擋；不得以 H0 冒充真實不會餓死。 |
| Q7 | S0 基線＋M1 主候選＋M2 對照 | CV 未知時以明示假設區間跑多種子，不拿文獻 SD 直接當個體 CV。每隻幼體有獨立、可重現的亂數流；其他個體增刪與事件分段不得改變其結果。 |
| Q8 | 依個體實際質量的維持代謝 | 階段平均質量固定版作簡化對照。質量→代謝關係未知時標來源物種與 `assumption:true`；階段邊界與存讀接續要守恆且逐位元一致。 |

## 3. 開發授權與界線（兩張 issue 共同）
- 解除 #219、#222 的決策等待：Claude 可自主拆 PR、開發、自審，CI 全綠後依現行規則合併。
- **單一質量／能量契約**：#222 育幼生理與 RU-6 需求帳共用同一套接口；任何「份↔mg」換算只能存在於有版本、標假設的橋接層，不得在兩個引擎各自寫死。
- 舊 golden 與舊歷史版本不得靜默改寫；新規則要有版本指紋、轉換資料、假設、守恆與不變性證據。
- **大工蟻與多后**可以同步開工：個體類型、蟻后各自的繁殖與死亡帳、各自代謝接口、幼體來源與階級分化欄位、存檔與可視化。營養數值與階級分化門檻在有證據前保持假設與隔離；不得用單后演算法假裝多后，不得憑空增加幼體。
- 育幼生理接入 P0-A2 時以可見的個體生長與照護事件呈現在觀察器中，並標「研究候選」。
- 未解的生物學校準問題記錄為證據缺口，不作為新的行政等待理由。

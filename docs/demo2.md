# Demo 2：地表＋地下同一世界的可操作 3D 觀察 Demo

> **非正式實驗世界**（P0-A2 候選／實驗世界，Owner #201）。本頁不建立也不宣稱任何正式歷史。
> Owner 2026-11-15 的需求：一個真的能操作、持續執行的 Demo，同時看到花園地表與地下蟻巢，而且兩者是**同一個世界**。

## 怎麼開

```
npm ci && npm run web:build && node cli/web-serve.ts
```

開 `http://localhost:8780/demo2.html`（桌機或 Android Chrome）。

| 網址 | 行為 |
|---|---|
| `demo2.html` | 接續這個瀏覽器上次玩的 Demo 世界（本機存檔）；沒有就建立新世界（種子 20261113，Owner #202 的可重現標識，不是挑選的種子），快轉到 09:00 開始 |
| `demo2.html?new=1` | 一律建立新世界 |
| `demo2.html?seed=1` | 不存檔的臨時世界（測試、快速看） |
| `demo2.html?world=p0a2` | 用原本的 P0-A2 世界（沒有蟻后／大工蟻／卵／蛹的引擎個體） |
| 其他參數 | `quality=high|medium|low`（固定畫質）、`speed=`、`mode=demo`、`view=full|surface|under`、`mag=`（螞蟻放大倍數）、`t=`（新世界快轉到的秒數）、`autostart=0`、`tour=0`（關閉自動導覽）／`tour=<秒>`（閒置幾秒後開始，預設 25） |

操作：滑鼠左鍵拖曳＝平移、右鍵拖曳＝旋轉、滾輪＝縮放；觸控單指＝平移、雙指＝縮放／旋轉；點一下螞蟻＝選取。

## 手機介面與「不操作也能看」（Owner 2026-11-15 第 4 項與最終目標）

**直式手機（寬度 < 760 px）**

- 頂部只有**一列控制**：「非正式實驗世界」標記、暫停／繼續、速度、視角（完整／地表／地下）、「⋯ 更多」；下面一行是模式標記（自然模式／展示情境）加一行短狀態（日期時間、光照、合成氣溫、速度），點一下展開成完整狀態（種子、巢外／巢內、狀態標籤），再點收合。兩個標記在任何狀態都看得到。
- 「⋯ 更多」選單：展示情境、跟隨螞蟻、自動導覽開關、統計／說明／存檔、畫面風格／渲染器／效能。
- 底部面板三種狀態：**收合**（只剩右下角一顆「▲ 巢外 n・巢內 n」小膠囊，3D 畫面用到底）、**半開**（約 46% 高）、**全開**（到頂部列下方）。點膠囊開啟；拖曳面板頂端的把手切換；畫面會重新取景到沒被蓋住的部分，場景標籤不會出現在面板或個體卡下面。
- 個體觀察：點螞蟻（或幼蟲、蟻后、卵、蛹）→ 底部出現兩行的精簡卡（編號、階級、引擎狀態、嗉囊量）加「跟隨」「詳情」；跟隨中多出「◀ 上一隻／▶ 下一隻」；「詳情」在面板的「個體」分頁顯示完整資料與資料分類；點空白處關閉。
- 所有按鈕、選單至少 44 CSS px；頂部與底部避開 safe-area；頁面不會左右捲動。
- 橫式手機與桌機維持原本配置（全部按鈕在頂部列、右側面板、左上角浮動個體卡）；桌機的個體卡在跟隨時也有「上一隻／下一隻」。

量測（Pixel 7 模擬 412×839；無頭 Chromium）：預設狀態 3D 畫面可用高度由 84.5%（頂部列 130 px）變成 **91.3%**（頂部列 73 px、面板收合）；選取個體時 84.6%；面板半開時由 40.5% 變成 45.3%。`tests/browser/demo2-ui.check.cjs` 斷言預設與精簡卡狀態都 ≥ 80%。Owner 的實機外面還有嵌入頁的標頭與瀏覽器列，實際可用高度比模擬小：比例**待實機確認**。

**不操作也能看**

- 開啟頁面後世界自動開始執行（不需要任何操作），並持續執行；自動存檔照舊（存檔語意沒有改）。
- **自動導覽**（預設開啟）：沒有任何操作 25 秒後，鏡頭開始慢慢巡覽——先看全景（完整剖面→地表→地下，沒有工蟻在巢外時不看地表），再跟隨一隻**正在做事**的工蟻約 16 秒，如此交替。跟誰由引擎資料決定：最新一幀的工蟻狀態（走向巢口、取食、回巢、前往食源、育幼、搜尋、回巢內）與頁面已收到的引擎事件（交哺、餵幼蟲；60 模擬秒內），同一類取最近發生的；每次從不同類別開始找，讓畫面有變化；同分以（世界種子、鏡頭序號、個體編號）的雜湊決定——**沒有 `Math.random`，同樣的輸入得到同樣的鏡頭**（`web/src/demo2/tour.ts`，純函式）。沒有工蟻在活動時只看全景，不會為了畫面安排任何事件。
- 畫面右上顯示「自動導覽中・點一下接手」；**任何操作**（點、拖、滾輪、按鍵）立即停止，鏡頭停在原地。再閒置 25 秒會重新開始；面板開著、你正在跟隨或選取個體、或世界暫停時不會啟動。可在「⋯ 更多」（桌機在頂部列）關閉，或用 `?tour=0`。
- **只動鏡頭**：自動導覽不對 Worker 送任何訊息（導覽的跟隨連「回報這隻工蟻的資料」的觀察指令都不送）。瀏覽器測試記錄送給 Worker 的每一則訊息：開導覽與關導覽的訊息紀錄**完全相同**（init、step_until、snapshot、set_speed、start），導覽後把兩個世界排程到同一模擬時刻，整幀 JSON 相同（#144：鏡頭不改變命運）。
- 自動化環境（`navigator.webdriver`）預設不啟動導覽，除非網址帶 `tour=<秒>`，讓其他瀏覽器測試保有自己的鏡頭。

## 引擎事件全量上畫面（D2E-1，2026-11-15）

稽核（[`demo2-engine-gap.md`](demo2-engine-gap.md) §2）指出：Worker 把世界的每一筆事件都送到頁面，但畫面只用了交哺與餵幼蟲。現在**頁面收到的每一類引擎事件都看得到**，而且沒有改動引擎、Worker、協定或存檔。

- **「事件」分頁**（面板／手機底部面板）：
  - 每一類引擎事件的**完整計數**（29 類：出巢、在巢口折返、搜尋結果、到食源有取食／是空的／過熱、取食結束、回巢、滿載、接觸有轉移／沒有轉移、喚醒、育幼碰到幼蟲／餵食、巢內走動碰到幼蟲、四種巢內選擇、蜜露產出、光照、天氣紀錄、新的一天、候選世界的名冊事件）。沒有發生過的類別仍列出 0（例如參考變體下「在巢口折返」一直是 0）。頁面不認得的事件種類會以原始種類名列在「其他」，不會被丟掉。
  - 可依分類篩選；「最近的事件」清單（最近 240 筆的視窗，顯示其中 60 筆），點一筆可選取該工蟻。
  - **空手而回如實顯示**：「到食源：是空的（空手折返）」是獨立一類，數字通常遠大於「有取食」。
- **場景提示標籤（◆）**：事件發生時，在該個體（或食源）旁出現短標籤，例如「◆ 食源是空的」「◆ 取食 0.05 份」「◆ 收到 0.26 份」「◆ 接觸 3 隻・沒有轉移」「◆ 被喚醒」「◆ 滿載回巢」「◆ 餵 l03 0.025 份」。
  - 事件的對象、時刻與量＝**引擎事件**；標籤飄在哪裡、停留多久＝**顯示**。畫面下方的說明列會寫「◆＝引擎事件（標籤位置與停留＝畫面）」。
  - 標籤停留約 2.2 秒**牆鐘時間**（1× 與 60× 一樣讀得到；暫停時不消失），一次最多 6 個（手機 3 個），每個個體一次一個，優先顯示較少見的事件（喚醒＞滿載＞取食＞餵幼蟲＞搜尋結果＞交哺＞空的食源＞無轉移接觸）。
  - **超過上限時只少畫標籤，計數不會少**；「事件」分頁列出「已顯示／因數量上限未顯示」。一次收到跨很長模擬時間的事件（快轉、載入後補跑）時，只有最後 20 秒模擬時間內的事件會出標籤；世界往前走遠之後，舊標籤也會消失——不會把很久以前的事標在已經走到別處的個體上。
  - 可在「事件」分頁關閉（或 `?cues=0`）。已經以走位演出的交哺／育幼沿用原本的標籤，不重複。
- 引擎的「接觸」是機率抽樣，不是身體接觸（M14），巢內位置是展示假設：被標示的雙方在畫面上不一定相鄰，文字只寫引擎記錄的內容。
- **對帳**：`web/src/demo2/events.ts`（純模組：只匯入協定型別，沒有時鐘、亂數、儲存或任何 Worker 指令）。`tests/web-demo2-events.test.ts`（BLOCKING）證明頁面的分類計數＝獨立的 Node 重播（`tests/lib/demo2-replay.ts` 直接數原型核心的事件紀錄，不共用分類程式）；`tests/browser/demo2-events.check.cjs` 在真實頁面上做同樣的比對（快轉後、再跑一段、5×、60×、候選世界與 `?world=p0a2`）。之後的工作包沿用這兩個對帳。

## 個體紀錄卡：「牠為什麼這樣做」（D2E-2，2026-11-15）

選取一隻工蟻（點牠、點「事件」清單中的一筆、或按「跟隨」）後，個體卡多了**牠自己的引擎紀錄**。桌面在浮動卡內（自己的捲動區）；手機維持兩行的精簡卡（場景仍占頁面高度 80% 以上），按「詳情」在底部面板的「個體」分頁看完整內容。

- **為什麼牠這樣做（只用牠自己的資訊）**：依牠目前的引擎狀態，寫出引擎的那個選擇讀了什麼——牠自己的嗉囊（空缺）、牠在接觸視窗內經歷的滿載回巢者接觸次數、牠自己的門檻與反應強度、牠親身走過的路線。顯示的是這些量的**目前值**，不重建選擇當下的機率（常數不在狀態框裡，頁面不猜）。空手而回會直接寫明：「牠走到食源時現場沒有食物，空手回巢。這是牠親身的經歷；出發時牠無從知道。」
- **工蟻不知道什麼**：每張卡都有一段固定文字——牠不知道全巢存糧、其他個體的狀態（除非實際接觸）、食源現在有沒有食物、全巢有幾隻幼蟲在餓；畫面上那些數字是玩家視角（CLAUDE.md §2.4）。
- **牠經歷的接觸**、**牠碰過的幼蟲與感知到的求食訊號**、**嗉囊與路線記憶**（上次取食、牠自己兩次取食的間隔、連續到場是空的次數）、**個體特質**：全部取自 Worker 回報的該工蟻紀錄（既有的 `follow` 觀察指令；唯讀投影）。
- **飢餓診斷**（空嗉囊的累計與最長時間、未滿足的代謝需求）：標「診斷」，並寫明引擎沒有死亡模型、沒有個體會因此死亡。
- **牠的嗉囊進出與行動**：本頁開啟後收到、與牠有關的引擎事件（出巢、取食／空的、交哺給誰、從誰收到、餵哪隻幼蟲、被誰喚醒）的完整次數與最近 14 筆。
- 幼蟲的卡：腸道量、此刻的求食訊號（＝1 − 腸道量）、被工蟻碰到與餵食的次數。蟻后、大工蟻、卵、蛹的卡不變（仍只列尚未模擬的項目）。
- **自動導覽選到的工蟻沒有個體紀錄**：導覽只動鏡頭、不向 Worker 送任何訊息；卡片會寫明，並只顯示本頁收到的事件。使用者自己點選或跟隨時才會送出 `follow`（只在對象改變時送一次）。
- 資料類別：列上的標籤「引擎」＝牠自己的引擎狀態、「診斷」＝統計診斷、「事件」＝引擎事件。
- 測試：`tests/web-demo2-record.test.ts`（BLOCKING）——每隻工蟻、每隻幼蟲的事件統計＝獨立 Node 重播；卡片內容逐值等於 Worker 的紀錄；卡片只依賴該工蟻參與的事件（把其他事件全部拿掉，內容不變）；讀取紀錄不改變世界。`tests/browser/demo2-record.check.cjs`（CI `demo2-optional`）在真實頁面上做同樣的比對與 #144。

## 可以觀察到什麼

- **同一個世界**：地表（土、石、草、落葉、雜草、磚塊邊、踏石、盆栽、寄主植物）與地下巢體剖面在同一個 3D 場景；巢口在地表是一個洞，在剖面上是同一條通道的頂端。
- **同一隻工蟻、同一個 ID**：巢室 → 通道 → 巢口 → 地表 → 蜜露來源 → 回巢。沒有「在巢口刪除、在地表重生」：畫面上是同一個 instance，跟隨鏡頭連續跟著穿過巢口。
- **只能走通道**：巢內位置只存在於巢體圖（通道與巢室地面）上，路線是圖上的最短路徑，不可能穿土；同一條通道裡各自有深度錯位（顯示用的避讓）。
- **階級外形**：小工蟻（頭、中軀、兩節腰、腹、六足、膝狀觸角）、大工蟻（心形大頭）、蟻后、卵、幼蟲、蛹。
- **動作**：步態相位只跟畫面實際走過的距離走（腳不滑）；沿路徑切線轉向並緩和；起步與停下有加減速；每隻、每趟的路徑偏移不同（固定種子）；休息的工蟻站定、伏低、觸角放下，只有原地微動作；取食時頭朝下；腹部脹大程度＝引擎的嗉囊量。
- **引擎事件上畫面**：回巢工蟻走到引擎記錄「有收到食物」的同伴旁頭對頭（交哺）；育幼工蟻走到引擎記錄「接觸／餵食」的幼蟲旁（被餵的幼蟲會亮一下）。
- **介面**：播放／暫停、速度（只改 Worker 排程）、視角「完整剖面／地表／地下」、點選個體資訊卡、跟隨螞蟻、統計（行為狀態、生命階段，引擎與示範資料分欄）、資料分類圖例、尚未模擬清單（取自此世界的存檔中繼資料）、存檔／載入／匯出／匯入、重新開始（顯示種子）、重設展示情境、FPS 與繪圖後端。
- **兩種模式**：
  - **自然模式**（預設）：只畫引擎個體——30 隻小工蟻、8 隻幼蟲，加上候選世界的蟻后 2～3、大工蟻、卵 8、蛹 3（引擎個體、數量為情境假設、生理與行為尚未模擬）。用 `?world=p0a2` 時蟻后室、蛹室是空的並標「尚未模擬」。
  - **展示情境・示範資料**：候選世界下只多出兩個不可取食的食物道具；`?world=p0a2` 下另外畫出蟻后 2（Owner #202 暫定 2～3）、大工蟻 4、卵 36、蛹 9，以及兩個不可取食的食物道具（花蜜、昆蟲屍體）。全部標「示範資料」、固定種子可重現、只有原地微動作；不存檔、不送進 Worker；30 隻小工蟻與 8 隻幼蟲在兩種模式下完全相同（都由引擎驅動）。

## 畫面上的資料分類

| 類別 | 內容 |
|---|---|

### 巢內位置怎麼決定（顯示規則，`web/src/demo2/stage.ts`）

引擎沒有巢內座標，只有狀態與時刻。畫面規則：

1. `to_entrance`（引擎固定 30 秒）：從目前畫面位置沿最短路徑走到巢口，**在引擎的結束時刻剛好抵達**；已在巢口的工蟻（回巢後立刻再出發）往通道內走一小段再回來。
2. `from_entrance`：在引擎的結束時刻抵達巢口前室的位置。
3. 沒有引擎時長的狀態改變（→ 休息／巢內走動／育幼，或剛回巢）：從目前畫面位置沿通道走過去，每段走動最長 45 秒（模擬時間）；途中先演出交哺時合計上限 96 秒。這段時間畫面位置可能落後引擎狀態，之後不會。
4. 休息：站在休息室或食物交換區的一個位置，到狀態改變前不平移（測試檢查）。
5. 巢內走動：在巢室之間閒逛、停頓（依工蟻、回合、段數固定種子）。
6. 交哺：只在路徑與時間允許時演出；有引擎期限的工蟻絕不為了演出而錯過期限。未演出的事件仍然發生（統計面板分列「引擎事件數」與「畫面演出數」）。
7. 頁面最多晚一個畫格才知道狀態改變：不超過 4 cm 的位置差會被吸收並在約 0.25 秒內消退；更大的跳位只有下列幾種。

**已列出的畫面跳位**：搜尋成功時從搜尋區（示意）直接到食源（引擎在同一時刻讓工蟻位於食源）；極短的失敗搜尋回程起點；開頁、載入存檔、重新開始的第一個畫面（沒有前一個位置）。

## 與引擎的邊界

- 模擬只在實驗 Worker 內；頁面經 `web/src/experimental/worker-client.ts` 只送排程（init／step_until／start／pause／resume／set_speed）與觀察（follow／snapshot）指令，載入存檔只經 SAVE-2 session 的 restore。繪圖、縮放、視角、跟隨、畫質、模式切換都不會送進 Worker。
- 存檔沿用實驗頁的 SAVE-2 流程（`ExperimentSession`＋`save-store.ts`，資料庫前綴 `antempire-experiment-`），沒有新增儲存路徑；只保存 Worker 在事件邊界產生的引擎快照。示範資料、鏡頭、模式不存。存檔狀態只會是「本機可玩／完整性檢查通過」，未經 Node 重算驗證。
- 資料層 `web/src/demo2/feed.ts`：一個介面 `ColonyFeed`，兩個提供者——`engineFeed(frame)`（引擎）與 `demoFeed(seed, castes)`（示範）。
- **候選世界 `p0a2-colony`（#263，已合併；`docs/colony-candidate-world.md`）是 Demo 2 新世界的預設種類**。它的 frame 仍是 P0-A2 frame，另外帶 `colony`：蟻后、大工蟻、卵、蛹是**引擎個體**（數量全部是情境假設），但在引擎中不進食、不產卵、不發育、不移動。本頁以 protocol 的 `isP0a2ColonyFrame` 讀取：這些個體靜態放在對應巢室（位置＝展示假設，只有原地微動作），可點選，資訊卡標「引擎個體」「候選世界・數量為情境假設」並逐項列出該個體 `not_simulated` 的項目；巢室標籤寫「蟻后 N（引擎個體；生理與行為尚未模擬）」，不寫成已模擬。展示情境此時只補引擎仍沒有的東西（食物道具），不會重複出現示範蟻后／大工蟻。存檔清單會列出並可重新開啟候選世界的存檔。`?world=p0a2` 改用原本的 P0-A2 世界：那些階級在自然模式標「尚未模擬」，在展示情境以示範資料顯示。

## 繪圖後端：預設 WebGL 2；可選用 WebGPU（實驗）

- **預設**：`THREE.WebGLRenderer`（WebGL 2，three r187）。WebGL 2 不可用時顯示清楚訊息與 2D 實驗頁連結。
- **選用**：`demo2.html?renderer=webgpu`，或在「效能」分頁按「WebGPU（實驗）」（會帶參數重新載入）。使用 three 的 `WebGPURenderer`，而且只在**真正的 WebGPU backend** 上（`renderer.backend.isWebGPUBackend`）：
  - 瀏覽器沒有 `navigator.gpu`、拿不到 adapter、或建立失敗 → 退回 WebGL 2，並在畫面與效能分頁寫明原因；頁面絕不把 three 自己退到 WebGL 2 backend 的情況報成 WebGPU。
  - WebGPU 裝置遺失（或無法把畫面呈現到 canvas）→ 停止繪圖、顯示訊息與「改用 WebGL 2 重新載入」的連結；模擬與存檔不受影響。
  - 效能分頁兩種渲染器都顯示：實際後端、GPU／adapter 字串、FPS、幀時間、draw calls、三角形，方便在同一台裝置上比較。
- **螞蟻關節 rig 有兩種著色語言、一份參數**：`WebGPURenderer` 不呼叫 `onBeforeCompile`，所以 WebGL 2 用 GLSL（`ant-rig.ts`），WebGPU 用 TSL node material（`ant-rig-tsl.ts`）；兩者的每一個振幅、頻率、相位、支點都來自 `rig-params.ts`（測試檢查 TSL 檔沒有自己的常數、GLSL 含有表中每個數字）。步態與姿勢的 CPU 計算（`gait.ts`）與顯示導演（`stage.ts`）完全共用，渲染器選擇不會進入它們。
  - 實作上的一個差異：three 的 node 管線在 `positionNode` **之前**就套用 instance 矩陣，所以 TSL rig 以原始幾何（`positionGeometry`）在模型空間計算，再把關節位移用每個 instance 的旋轉與縮放（`aXf`／`aScl`，與 instance 矩陣同值）帶到 instance 空間。四個 per-instance 屬性共用一個 interleaved buffer（WebGPU 每條管線最多 8 個 vertex buffer）。這兩點都是在驗證時發現並修正的（先前蟻后的頭與腹部位置錯誤、螞蟻在真正的 WebGPU 上不畫）。
- 其他材質（Lambert、Standard、Basic、虛線）是標準材質，`WebGPURenderer` 自動轉成 node material，沒有另外改寫。

### WebGPU 路徑驗證到哪裡（2026-11-15）

| 項目 | 狀態 |
|---|---|
| 沒有 WebGPU 時退回 WebGL 2 並說明 | 已驗證（無頭 Chromium，預設旗標） |
| node material／TSL rig 在 `WebGPURenderer` 的 **WebGL 2 backend** 上（`&backend=webgl2`，畫面標示「不是 WebGPU」）：畫面、點選、跟隨 | 已驗證（螢幕截圖；與 GLSL rig 的蟻后近景做像素比較，明顯不同的像素 0.01%） |

## 畫面風格：標準／HD-2D（選用，畫面效果）

Owner 2026-11-15 要求試「HD-2D」的畫面感（像素化的場景加上景深、泛光、暖色調、茂密草葉、薄霧光線）。這裡只借用**技法**；場景仍然是我們自己的花園與蟻巢，沒有使用任何既有遊戲的角色、建築、名稱或素材。

- 開關：「效能」分頁的「畫面風格：標準／HD-2D」，或 `demo2.html?style=hd2d`（另有 `px=1|2|3|4`、`dof=0`、`bloom=0`）。預設仍是標準畫面。三種視角與跟隨模式都可用；點選與跟隨在像素化下照常運作（選取用的是投影計算，不讀畫面像素）。
- 做法（`web/src/demo2/hd2d.ts`，全部在 WebGL 2 渲染器上）：
  1. **像素化**：場景先畫到縮小的內部畫面（關／2×／3×／4×，HD-2D 預設 3×），再以最近鄰放大；標籤、面板等 HTML 介面維持原生解析度。
  2. **景深**：焦點平面＝鏡頭目標，跟隨時＝被跟隨的螞蟻；離焦點越遠越模糊。
  3. **泛光**：亮部模糊後疊回。
  4. **色調與暗角**：色調依**引擎的光照狀態**選擇（日：暖；曙暮光：更暖；夜：不加暖色）。
  5. **場景加密**（第一次開啟時才建立，用自己的固定種子，不改動標準場景）：更多草葉、落葉與地被葉；空中的浮塵；沿太陽方向的光束。
- **這些都是畫面效果／裝飾**，在「資料分類」面板列為只屬於顯示：
  - 沒有加入任何生物或事件：沒有蝴蝶、螢火蟲、其他昆蟲，也沒有會被當成蜜源的花；地被只有葉片。浮塵是沒有形狀、沒有飛行路徑、緩慢飄移的小亮點。
  - 光線方向與顏色仍由引擎光照狀態決定（`setLight`）；光束只在日間與曙暮光顯示，夜間不畫；HD-2D 不會改變或暗示另一個時間。
  - 只改繪圖：引擎、Worker、顯示導演、資料層、科學參數都沒有動；同一模擬時刻下，開或關 HD-2D 的顯示導演輸出逐字相同（瀏覽器測試），畫出的個體完全相同。
- **自動畫質**：FPS 持續偏低時先關景深，再關泛光，最後才降畫質等級；「效能」分頁顯示目前作用中的效果。
- **WebGPU**：HD-2D 目前僅 WebGL 2。`?renderer=webgpu` 時維持標準畫面，按鈕停用，「效能」分頁顯示「HD-2D 目前僅 WebGL 2」。沒有出貨未驗證的 WebGPU 後處理路徑。
- 量測（**不是實機結果**：無頭 Chromium、SwiftShader、自動化；畫質「中」）：桌面 1440×900 HD-2D 約 3.5 FPS、64 draw calls、約 20.5 萬三角形；Pixel 7 模擬約 5 FPS、39 draw calls、約 20.6 萬三角形（多出的三角形是加密的草葉）。像素化後相鄰像素相同的比例：桌面 73%（標準 35%）、手機 67%（標準 44%）。實機數字待 Owner。

### 手機直向（窄螢幕）

- **取景**：巢體比直向螢幕寬很多。預設的「完整剖面」顯示巢口與中央的巢室，放大到看得清楚螞蟻（Pixel 7 模擬下體長約 21 px），鏡頭稍微俯視讓花園地表占上半部、土壤剖面占下半部；其他巢室左右拖曳即可看到（畫面下方的說明列會寫「左右拖曳可看其他巢室」）。「地下」是同樣寬度的正面平視。土壤剖面向下、向兩側延伸（裝飾），不會露出空的背景。桌面仍然整個巢都在畫面內。
- **標籤**：窄螢幕用短標籤（巢室名＋數量），以「※」代表「引擎個體，生理與行為尚未模擬」，畫面下方有一行說明；完整的說法保留在點選的資訊卡、統計面板與桌面的標籤。`?world=p0a2` 下短標籤寫「后：未模擬」。
- **不重疊**：標籤依優先順序放置（選取標記＞事件＞巢口＞巢室＞其他），會與已放置的標籤重疊時上下移開，放不下才隱藏（`web/src/demo2/labels.ts`，Node 與瀏覽器測試都檢查任兩個標籤不重疊）。
- **狀態列**：窄螢幕用較短的文字並允許換行，不再被右緣切掉（「非正式實驗世界」由上方的標籤顯示）。
- **面板開啟時**：面板不透明；場景標籤與說明列只畫在面板以上的區域，場景也上移到面板沒蓋住的部分。

## 還沒做到的（對照 Owner 需求）

- 蟻后、大工蟻、卵、蛹在候選世界是引擎個體，但引擎還沒有牠們的生理與行為：畫面上是靜態的（不走動、不產卵、不發育）。
- 交哺只演出一部分（受巢內路徑與引擎期限限制）；交哺雙方沒有口器對接的細部動畫，只有頭對頭與觸角前伸的姿勢。
- 固體食物搬運姿勢沒有做（引擎沒有固體食物）。
- 搜尋成功時畫面會從搜尋區跳到食源（引擎限制，已列出）。
- WebGPU 是選用的實驗路徑：只在軟體 WebGPU 上離屏驗證過，螢幕呈現與真實 GPU 待 Owner 實機確認（見上）。
- 三維地形沒有碰撞：地表工蟻會直接走過落葉、石頭旁的裝飾物之間（景物避開顯示路線，但不是障礙物）。
- `web/three.html`（3D 原型）保留不動；Demo 2 重用它的地形雜訊、螞蟻模型與效能統計模組。

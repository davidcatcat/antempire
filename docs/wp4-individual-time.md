## 1. 目標與範圍

長期目標是**個體事件時間**：每隻個體的決策時刻是自己的 `出發時刻 + k × dt`，而不是所有個體共用的網格。本 PR 只做到：

- 在 `engine/physics/local-steer.ts` 加入選項 `decision_clock: 'individual'`（輸入欄位；預設不給＝`'common_grid'`＝#142 基準，程式路徑與輸出逐位元不變）；
- 兩種時鐘並排比較（`prototypes/local-steer/time-mode.ts`），驗證決定性、事件順序與物理不變量；
- 保留所有失敗與發現（§6）。

## 2. dt 是模型假設，不是螞蟻的決策間隔

`decision_interval_s`（dt）是把連續行為離散化的**模型假設（遊戲假設，`assumption: true`）**，不是量測到的真實螞蟻決策間隔。大頭家蟻沒有任何關於「多久重新評估一次方向／讓路」的研究；兩種時鐘都沒有本種文獻支持，選哪一種是模型選擇。dt 改變結果（§5、`docs/wp4-local-avoidance.md` §6.2 收斂）本身就說明它是離散化參數，不能被解讀為生物學數值。最終方向是**事件驅動決策**（§7），dt 只留作退路或完全移除。

## 3. 個體時鐘的定義（`decision_clock: 'individual'`）

1. **自己的時刻**：個體的時刻 τ_k = `start_t_s` + k·dt（k = 0, 1, …），在十進位上精確計算、只捨入一次（`exact-time.ts`）。有入口規則時錨點仍是排定時刻；入口被占時在自己的時刻重試，入場時刻就是某個 τ_k。
2. **時間線**：所有個體需要的時刻（尚未抵達者的決策時刻、尚未入場者的入場／重試時刻、出口規則下已抵達者的出口嘗試時刻）的聯集，加上起點 0 與終點 H。兩個時刻之間每隻個體維持當時的決策，運動與精確接觸物理和基準是**同一段程式**。
3. **誰在何時決策**：只有 τ_k 恰等於當下時刻的個體決策，只讀那一刻的局部狀態。第一次決策恰在出發時刻（與 #142 Owner 決定 23 相同）。
4. **亂數鍵**：（種子、串流、個體 id、自己的時刻序號 k）。所以一隻個體的抽樣不依賴別隻的時鐘；當所有個體都在 0 出發，k 就等於網格序號，兩種時鐘給出**完全相同**的結果（測試）。
5. **規則 D（卡住視窗）**：以自己的決策期計數；在自己的下一個時刻或 H 檢查。
6. **終點**：與基準相同（§2b 第 3–5 點）：H 是一個時刻；H 出發記 `started_at_horizon`、不決策、不位移；H 之後沒有任何紀錄。
7. `stats.decision_instants` 在個體時鐘下是「至少一隻決策的時刻數」；另有 `stats.timeline_instants`（只在個體時鐘下出現）與結果欄位 `decision_clock: 'individual'`。基準輸出沒有這兩個欄位。

## 4. 驗證結果（四類分開）

### 4.1 程式測試

- **預設不變**：改動前（97bfcb5）與改動後，以預設時鐘跑 8 個情境 × A／B／C／N × 種子 1–5 × dt 0.1／0.05、`none`、K0–K3 × 4 規則 × 種子 1–2，共 360 次的 `runHash` **全部相同**（彙總 SHA-256 `5f654379…8696`）。`tests/wp4-individual-time.test.ts` 釘住其中 44 個雜湊；明確給 `'common_grid'` 與不給的整個結果相同。既有測試（`wp4-local-steer`、`physics-time-contract-wp4`、`physics-playback` 等）不改即通過。
- **化約**：所有個體在 0 出發（head-on-2、stone、crossing、offset-block、pass-clear）× 4 規則 × dt 0.1／0.05 × 種子 1–2：個體時鐘與基準逐位元相同。
- **時間契約**：共用的契約檢查（T1 精確出發／入場、T3 終點、T4 `final_mode`、T5 重跑與排列）在個體時鐘 × A／B／C／N × dt 0.1／0.05 × 有無入口規則下全部通過；每個決策事件都恰在自己的 `start + k·dt`（十進位精確）。單隻個體出發 0、0.25、0.3、0.30000000000000004、0.31、0.35、0.123、0.95、0.999：決策數＝H 之前自己的時刻數、第一次決策恰在出發時刻、時間線只有 0 與自己的時刻；H 出發與 H 之後出發同基準。
- **輸入順序**：五隻（三隻同在 0.25、一隻在 0.3、一隻在 0.3 後一個 ulp，彼此感知得到）五種輸入順序逐位元相同。
- **拒絕**：未知時鐘、`none`（不決策）配個體時鐘。

### 4.2 數學／物理不變量

個體時鐘下（`tests/wp4-individual-time.test.ts` 與 `prototypes/local-steer/out/time-mode.json`）：獨立取樣驗證器 0 穿透（成對與靜態）、裁判（≤ 24 隻）0 重疊、獨立 `contact_end` 檢查全部在區間內、決策時刻 0 違規、重跑／反序／打亂逐位元相同。詳細數字見 §5。

### 4.3 生物學與文獻比較

**沒有可比較的本種資料。** 大頭家蟻沒有決策間隔、相位或事件觸發的研究；兩種時鐘與 dt 都是模型假設。本 PR 不提出任何生物學結論。

### 4.4 使用者能看到什麼

**沒有**。個體時鐘沒有接入回放頁或觀察器；畫面上看到的仍是基準（共同網格）的輸出。

### 5.2 時間切片

- 個體時鐘的時間線是所有個體時刻的聯集：出發時刻各不相同時，時刻數約為「個體數 × H/dt」。例（§5.1）：crossing-traffic-100（出發在 0–5 s 隨機），dt 0.05：基準平均 500 個時刻，個體時鐘 28 453 個；CPU 平均約 4.2 s → 19.6 s。corridor-8（8 個不同出發時刻）：2 408 → 18 377。所有個體都在 0 出發的情境（head-on-2、crossing 等）兩者相同（個體時鐘在全部抵達後不再產生時刻，所以略少）。
- 時刻多、每個時刻只有一兩隻決策，同時決策的批次幾乎消失；這是 #142 文件預期的成本。
- 物理不變量不受影響：兩種時鐘各 208 列都是 0 穿透、裁判 0、獨立接觸檢查 0 違規、決策時刻 0 違規、重跑與排列逐位元相同、安全退路 0。

### 5.3 輸入順序

兩種時鐘都只依「時刻 → 個體 id」處理，亂數鍵不含陣列位置；反序與打亂輸入逐位元相同（§4.1、§5.1）。

### 5.4 終點效應

本表所有情境的 H 都在網格上，所以基準沒有被截斷的決策期；個體時鐘下，出發時刻不在網格上的個體，最後一期都被 H 截斷（crossing-traffic-100 全部 100 隻、K2／K3 在 dt 0.1 時 75 隻、0.05 時 50 隻、corridor-8 全部 8 隻）。被截斷的最後一期仍完整處理到 H（運動、接觸、規則 D 在 H 檢查），H 本身的語意相同（不決策、不位移）。截斷會讓卡住視窗在 H 前少一段，這是兩種時鐘在終點附近唯一的系統性差異。

## 6. 發現與失敗（保留，不修飾）

1. **時間切片的數值非局部性（已知缺陷，釘住）**：別隻的時刻會把一隻個體的運動區間切成多段，位置逐段累加，所以一隻永遠感知不到的遠方個體也會改變牠的座標末位。量測（N 規則、40 種出發 × 4 種遠方出發＝160 組）：個體時鐘 128/160 組座標不同、最大 5.0×10⁻¹⁴ mm；**基準也有**（非網格的出發時刻插入時間線）18/160 組、最大 7.1×10⁻¹⁵ mm（另一次 1000 組量測：個體 725、基準 57）。事件種類與時刻在這些例子中不變，但在門檻附近（例如探測是否「自由」）理論上可以翻轉決策。測試以量測值釘住，原因修正後必須更新。修正方向見 §7 第 1 步；本 PR 不改基準。
2. **一個 ulp 的相位不一定能保留**：0.30000000000000004 出發的個體第一個時刻是 0.30000000000000004，但 + 0.1 的十進位值 0.40000000000000004 最接近的雙精度數就是 0.4，相位併回網格；+ 0.05 則得 0.35000000000000003 ≠ 0.35，相位保留。小於時刻解析度的相位無法存在（只捨入一次、十進位精確的必然結果），不是錯誤，但要知道。
3. **結果差異不代表好壞**：出發時刻不在 0 的情境（crossing-flank 部分、corridor-8、crossing-traffic-100、K2、K3），兩種時鐘的決策時刻與亂數鍵都不同，抵達、卡住、接觸數會變，方向不一致（例：crossing-traffic-100 dt 0.05 抵達 93 → 112，dt 0.1 96 → 96；K2 dt 0.1 146 → 130；corridor-8 接觸 241 → 169），幅度和種子間差異同一量級（密集情境對決策時刻很敏感）。不能據此選擇時鐘。
4. **成本**：見 §5.2；1000 隻情境沒有跑（預期時刻數 ~10⁵–10⁶）。

## 7. 走向事件驅動決策的路徑（提案，未實作）

1. **以絕對時間表示運動**：每隻個體記錄目前運動段的起點位置與起始時刻，任一時刻的位置＝起點＋速度×（t − 起始時刻），不逐區間累加；接觸時刻也在絕對時間上求解。這樣別隻的時刻不會改變任何一隻的位元（修正 §6 第 1 點，兩種時鐘都適用；對基準而言是規則更新，需另開 PR）。
2. **事件觸發的重新決策**：以事件取代 dt——接觸開始、感知變化（另一個身體進入或離開感知半徑：與接觸同一套精確碰撞時刻計算，門檻改為感知半徑）、計時結束（B 的 `wait_s`、`reroute_max_s`）、抵達、入口／出口。決策只在這些事件發生時進行。
3. **dt 的角色**：只作為「長時間沒有事件時的重新評估」退路，或完全移除；若保留，必須標成遊戲假設並做敏感度分析。
4. **排程**：個體事件放進分層時間契約的排程器（`engine/scheduler/world-events.ts`，每隻個體一個時鐘、原生秒），同一精確時刻成批、以集合處理，與 P0-A0／P0-A2 一致。
5. **驗證**：事件驅動版與 dt → 0 的時鐘版比較收斂；同樣的 0 穿透、獨立接觸檢查、決定性、排列不變、跨環境（Node／Worker）比較。
6. **整合**：以上每一步各自一個 PR；預設關閉、基準黃金不變；Owner 核准後才替換。

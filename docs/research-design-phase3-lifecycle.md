## §0 範圍與規則

**範圍**：本草案處理四項生命週期機制。
1. 卵、幼蟲、蛹的溫度依賴發育。
2. 小工蟻、兵蟻（major）與蟻后依年齡與溫度的死亡率。
3. 蟻后的批次產卵與繁殖週期。
4. 食卵、營養卵、幼體被吃，以及幼體的營養調節（包括兵蟻由營養決定）。

**本草案遵守的規則**

- **歷史不可改寫**（CLAUDE.md §1）：Day1～14 不受影響。新規則只從合併後的下一個遊戲日起生效。
- **無上帝視角**（§2.1）：本文每一項機制的輸入，都限定為個體能感知的局部訊號：
  - 自己嗉囊或體內的營養；
  - 實際接觸到的同伴、幼蟲、卵；
  - 所在巢室的溫度。
  - 工蟻、幼蟲、蟻后都不得讀取全巢庫存、全巢缺口天數或全巢比例。
- **生態不依蟻群調整**（§2.2）、**GM 不干預**（§2.3）、**不為存活調參**（§7）：
  - 存活不是目標。
  - 下面的驗證案例只用來檢查模型能不能重現文獻，不用來讓蟻群活下來。
- **數值標註**（§3）：每個數值都標成下列四類之一，原則是「不知道就留 null」。
  - **文獻支持**：附來源 ID 與外推限制。
  - **一般生理學**：一般昆蟲生理學，不是本種的實測。
  - **遊戲假設**。
  - **非本種**：其他物種的數值，一律標「非本種」並寫出物種名。
- **不排除任何研究，除非寫明理由**：R94（Yuan）、R136（Chang）、R167（Phillips）、R166（Fluker）全部保留。唯一被排除的是 GISD 的「壽命 78／38 日」。理由是它與 Fluker、Chang 的發育時間上限完全相同，判定為把發育時間誤標成壽命（`literature-notes.md` B2）。

**其他條件**

- **繁殖蟻**（新后、雄蟻；只有 R94，28°C）：前蛹 4.16 日，蛹 12.31 日，卵→成蟲 37.60 ± 3.20 日。
- **兵蟻**：沒有本種的分開資料（Yuan 把小工蟻與兵蟻合併）。非本種的 *P. pallidula*：兵蟻幼蟲在第三齡超過 1.2 mm 後繼續長到 2.2～2.6 mm，沒有多蛻一次皮（Passera 1973，R212）。因此兵蟻的幼蟲期比小工蟻長，但長多少是 null。

### 1.3 互相矛盾的數據

1. **Phillips 與 Chang／Yuan 在相同溫度下差 1.5～1.8 倍。**
   - Phillips B（約 25.6°C）是 59.5 日，Chang（26.5°C）是 36 日，相差 0.9°C。
   - 兩者的兩兩 Q10 算出來超過 200，不可能單由溫度解釋。
   - 可能原因（都無法證實）：
     - Phillips 一週只餵一次，而他自己證明幼蟲期會因缺食延長（p.27～29）；
     - 一週檢查兩次，解析度約 ±3.5 日；
     - 「類別平均」是由各群的範圍取平均；
     - 溫度是室內月均溫，日變化不明；
     - 部分幼體死亡；
     - 階段定義可能不同（例如前蛹是否算入蛹）。
   - Chang 給的是「平均最短時間」，系統性偏短；Yuan 給的是平均值。
2. **蛹期**：Yuan 在 28°C 為 5.05 日，Chang 在 26～27°C 為 7～11 日；Fluker 在 21°C 為 19～23 日，Phillips 在所有溫度都是 17～23 日。
   - 若只用 Fluker 與 Yuan 兩點，蛹期 Q10 ≈ 7.7，遠高於一般昆蟲的 2～3（一般生理學）。
   - 兩份夏威夷舊研究的蛹期幾乎相同，而且 Phillips 的蛹期幾乎不隨溫度變化，可能是階段定義的差異。**無法解決，保留並列。**
3. **幼蟲齡數**：Chang 提到「第四齡」，Yuan 是三齡。對本設計影響不大，因為只用總幼蟲期。
4. **高溫**：Phillips 的 30°C 恆溫使 1～2 個小群在 16～21 日內死亡；Yuan 在 28 ± 1°C 長期飼養成功。兩者沒有直接矛盾，但 28～30°C 之間沒有任何本種數據。

**(f) 變動溫度**：線性度日在門檻附近有 Jensen 效應（一般生理學，R222）

- 例：日均 18°C、振幅 ±5°C（正弦），卵→成蟲約 137 日；恆溫 18°C 則要 201 日。

- 因此，若引擎只有每日一個巢溫，冬季的發育會被系統性低估；若有日最高、最低溫，應做逐時積分（作法同 R209）。

### 1.5 可實作機制（建議）

**狀態變數**

- 每個幼體：`stage` ∈ {卵、幼蟲、蛹}，`progress` ∈ [0, 1)（沿用現有欄位）。
- 新增 `caste_path` ∈ {未定、小工蟻、兵蟻、繁殖蟻}，預設「未定」。兵蟻與繁殖蟻路徑在 §4 與 §3 才啟用。

**每日更新**

```
對每個幼體：
  T_b = 幼體所在巢室溫度（本日的溫度剖面；只有日均溫時就用日均溫）
  r_s(T) = max(0, min(T, T_cap) − T0_s) / K_s        # s = 該幼體目前的階段
  Δprogress = ∫ 當日 r_s(T(t)) dt                     # 有日最高／最低溫時，用正弦或逐時積分
  幼蟲：Δprogress × 營養係數 n                         # 見 §4；沿用 larva_min_nutrition_growth_factor
  兵蟻路徑的幼蟲：K_larva × m_major
  繁殖蟻路徑：K_pupa × m_sex_pupa
  progress ≥ 1 → 進入下一階段
```

**低溫停滯**：T_b < T0_s 時 progress 不增加。若需要「低溫期間的幼體死亡」，另立參數 `cold_stall_hazard`（null），不與發育速率混在一起。

**模型開關**：新增 `development.model` ∈ {`q10_legacy`, `linear_degree_day`}。

- 開關設為 `q10_legacy` 時，必須通過 `tests/golden.test.ts` 的逐位元組比對，證明舊模型行為不變。
- 改用 `linear_degree_day` 才屬於規則更新。

### 2.2 適用條件

- Yuan 的條件：實驗室、28°C、70% RH、食物充足、新羽化個體。
  - 每 14 日普查一次（解析度粗）。
  - 小工蟻 n = 104，兵蟻只有 n = 14。
- 實驗室死亡**不包含覓食、天敵、打鬥等外在死亡**。野外的總死亡率 = 這裡的內在死亡 + 引擎其他路徑（飢餓、受傷等）。兩者不可重複計算。

### 2.3 互相矛盾的數據

1. **Yuan 正文說「最後一隻小工蟻死於第 84 日」，表 S3 卻是第 84 日仍有 1 隻存活、第 98 日歸零**（R94 內部不一致）。
2. **Yuan 的平均與中位相差很大**：小工蟻中位 28 日，平均 26.25 日；兵蟻 KM 中位 70 日，平均 56 日。
   - 我的 Gompertz 擬合：兵蟻中位約 59 日。
   - 原因是 14 日一次普查加上兵蟻樣本小。
3. **不同屬之間的差距**：*P. dentata* 在 25°C 的中位約 77 日（R172），本種在 28°C 是 28 日。只差 3°C，任何合理的 Q10（低於約 30）都解釋不了，應是物種或方法的差異。**不能用 *P. dentata* 的數值。**
4. **兵蟻／小工蟻的壽命比**：本種 2.1 倍（平均）、2.5 倍（中位）；*S. invicta* 的大工蟻只長 50%（約 1.5 倍；R204、R171）。不同屬，數值不可互換。
5. **高溫**：Phillips 的 30°C 恆溫在數週內殺死小群；Yuan 在 28°C 正常。急性致死要 34°C 以上（R146）。慢性高溫死亡的劑量—時間關係完全未知。

### 2.4 可實作機制（建議）

**狀態變數**：每隻工蟻有

- `caste` ∈ {小工蟻, 兵蟻}；
- `age_days`（日曆年齡，沿用）；
- 新增 `physio_age`（生理年齡）。

**每日更新**

```
θ(T) = Q10_life ^ ((T_個體所在處 − 28) / 10)     # 28°C 是 Yuan 的實驗溫度
physio_age += θ(T)
內在死亡率（Gompertz）：h_int(a) = A_c × exp(B_c × a)，a = physio_age，c = 階級
當日內在死亡機率：p_int = 1 − exp(−∫ h_int)
```

**與其他死亡合併**：沿用引擎的競爭風險寫法 1 − (1 − p_int)(1 − p_starv)…。飢餓、受傷倍率等既有路徑保留，但要重新檢查是否重複計算。

### 3.4 可實作機制（建議）：每隻蟻后一個狀態機

**蟻后的狀態**

- `mode` ∈ {產卵批次, 暫停}；
- `batch_remaining`；
- `reserve_q`：蟻后體內可用於產卵的營養，只來自工蟻實際餵給蟻后的量；
- `pause_days`。

**產卵批次**

```
進入批次時抽批次大小：batch_size ~ 分布(下限 2, 上限 82)    # 範圍：文獻支持 R136；分布形狀：遊戲假設
每日產卵 = min(batch_remaining, r_max(T) × g(reserve_q), 每顆卵的成本可負擔量)
reserve_q 不足 → 提前結束批次
```

**暫停**

```
恢復條件（任一成立）：
  ① 蟻后在其巢室「實際接觸到」前蛹或晚期 L3 幼蟲，或接觸到帶著前蛹訊號的工蟻
     # 機制：本種只有定性觀察（R94）；生理機制是非本種 S. invicta（R206）
  ② pause_days ≥ pause_max                                    # null；Chang 間隔 ≤ 8 日只能作上界參考
  而且 reserve_q ≥ 門檻                                        # null
```

**溫度**：產卵速率 `r_max(T)` 用與發育相同的度日形式，有下限溫度。下限溫度與斜率都是 null；方向有非本種支持（R225）。現有的 `laying_temperature_q10` 2.5 是遊戲假設。

**多后**：每隻蟻后各自一個狀態機。

- 同巢蟻后之間的抑制只能透過實際接觸：`r_max × f(本日接觸到的其他蟻后數)`。
- f 是 null；機制是非本種（R207、R208）。
- **本巢目前只有 Q001 一隻蟻后**：不能因為有了這個機制就生出新蟻后（species 文件 §2）。

**移除 E5**：一旦有了「實際接觸」的回饋，「幼體數 × 0.011」的全巢人口上限就應移除。

- 這是行為改變，屬規則更新。
- 移除後人口可能大幅成長，但**不得為此再調參**（§7）。

**繁殖蟻生產**：建議延到最後一個 PR。

- 雌性卵走向新后路徑的條件只能是局部的：蟻后自身狀態（季節、溫度的累積經歷，null）＋幼蟲得到的營養（§4），再加上「強壯大巢」的條件。
- 「巢有多大」不能讓個體讀取全巢人口。可行的局部代理：育幼室中保育工蟻與幼蟲的接觸比例。*S. invicta* 的參照（R211）顯示，工蟻:幼體比在 1 以上時，餵食不受群體大小影響。
- 雄蟻比例：null。
- **本巢目前約 14 隻工蟻；依 Phillips（R167）不應出現繁殖蟻**。這只是驗證檢查，不是硬性規則。

| `batch_size_min`、`batch_size_max` | 2、82 | 文獻支持（R136）；分布形狀為遊戲假設 |
| `monthly_eggs_reference` | 97～292／31 日（26～27°C） | 文獻支持（R136）；**只作驗證，不作輸入** |
| `pause_max_days` | null | Chang 的 8 日只是觀察上界 |
| `r_max(T)`、`reserve` 門檻、`f(N_q)` | null | — |
| `egg_cost` | 沿用現有 `egg_laying_*_cost` | 遊戲假設 |

### 4.2 適用條件

- 本種的資料只有三項：
  - Chang：卵→幼蟲 38%，卵被吃；
  - Yuan：無蟻后時孵化率 89%；
  - Phillips：缺食延長幼蟲期，小巢只產小工蟻。
- 兵蟻的營養決定、兵蟻抑制、營養卵，都只有同屬或其他屬的資料，必須標「非本種」。

### 4.3 互相矛盾的數據

1. **卵→幼蟲的轉換**：Chang 38%（有蟻后、有幼蟲）vs Yuan 89%（無蟻后、約 100 隻工蟻）。Yuan 自己的解釋是食卵；但兩者的條件也不同（溫度、濕度、族群、計數方法），不能只歸因於食卵。
2. **營養卵**：*P. pallidula* 只有未交配蟻后產營養卵（R164）；*S. invicta* 的創巢蟻后會產（R205 引 Voss）。本種沒有記錄，而且 Chang 寫的是「卵被吃」，不是「營養卵」。**不能假設本種有營養卵。**
3. **兵蟻與溫度**：*P. pallidula* 只有 24°C 以上才產兵蟻（R175）；本種在 Yuan 的野外觀察中，冬季與早春沒有兵蟻幼體。方向一致，但門檻數值不能搬用。
4. **兵蟻與群體大小**：本種小巢不產兵蟻（R167）；*S. invicta* 的大工蟻比例隨群體大小增加（R209）。兩者方向一致；但若要不讀取全巢人口，只能透過「保育工蟻能給每隻幼蟲多少蛋白」這個局部量來產生這個現象。
5. **成蟲兵蟻抑制兵蟻生產**：*Pheidole* 的方向一致（R174、R175、R213、R214）；*P. megacephala* 的野外兵蟻比例與競爭環境無關（R97，二手）。

### 4.4 可實作機制（建議）

#### 4.4.1 幼蟲的營養（取代全巢 `pFraction`／`sFraction`）

- 每隻幼蟲有 `gut_protein`、`gut_sugar` 與 `begging`（飢餓訊號）。
- 保育工蟻**實際接觸**到幼蟲時，依幼蟲的 `begging` 與工蟻自己嗉囊的內容，決定要不要餵一口。
  - 每口的量固定，屬遊戲假設。機制：非本種 R210。
  - 引擎已有 `nurse_larva_contact_probability` 與 `begging_signal`，可以沿用。
- 發育的營養係數 `n = clamp(本日實際吃到 / 本日需求, larva_min_nutrition_growth_factor, 1)`。
  - 缺食延長幼蟲期：文獻支持（本種，R167），數值是遊戲假設。

#### 4.4.2 兵蟻路徑（啟用 E3 開關前必須先有）

**敏感窗**：L3 的後段，也就是 progress 超過某門檻之後。門檻是 null；機制是非本種 R174、R212。

**每隻 L3 幼蟲累積兩個量**

- `protein_in_window`：實際被餵的蛋白；
- `major_contact_in_window`：實際被兵蟻成蟲接觸的次數。

**判定**

```
若 protein_in_window ≥ θ_P
且 major_contact_in_window ≤ θ_I
且 窗內的巢室溫度 ≥ T_major_min（null；P. pallidula 為 24°C，非本種）
→ caste_path = 兵蟻：幼蟲期 × m_major，羽化為兵蟻
```

- 「小巢不產兵蟻」與「冬季不產兵蟻」都應該由這些局部量自然產生，**不可另外硬寫**。
- θ_P、θ_I 都是 null。

#### 4.4.3 食卵與幼體被吃（新增 E7 路徑；必須守恆）

**觸發只能是局部的**：

- 剛孵化或 L1～L2 的幼蟲，與卵同室且 `begging` 高；或
- 嗉囊空的保育工蟻，碰到卵或幼蟲。

在這兩種情況下，以機率 `p_oophagy` 或 `p_cull` 吃掉一個卵或幼體。

- 本種的方向有文獻支持：卵被剛孵化的幼蟲或工蟻吃（R136）。
- 飢餓時增加：非本種 *S. invicta*，R215。
- 機率都是 null。

**守恆**：被吃個體所含的營養，以「回收率 ρ」轉入吃者的嗉囊或腸道；ρ ≤ 1，其餘記為損失。

- ρ 是 null（遊戲假設）。
- 被吃個體的營養含量，等於它當初的產卵成本加上累積吃進的量（引擎已記錄的量）。
- **不能憑空產生營養**。
- 事件必須記錄：吃者 ID、被吃者 ID、量、原因。
- **人口帳**：被吃的卵或幼蟲計入當日 `brood_deaths`（原因 `cannibalised`／`oophagy`），所以 `engine/day.ts` 的幼體守恆式「期末幼體＋死亡＋羽化＝期初＋產卵」不變；另在每日摘要分開列出被吃的數目，報告可以區分飢餓死亡與被吃。

**不實作營養卵類別**：本種沒有證據（§4.3 第 2 點）。若將來找到證據，再用蟻后產卵時的 `egg_type` 開關加入。

#### 4.4.4 幼蟲→工蟻的營養流（「消化階級」）

- *S. invicta* 的第四齡幼蟲把蛋白處理後交回工蟻（R205），屬非本種。
- 本種沒有資料。**不建議實作**；列為未知。

### 4.5 未知參數

- `p_oophagy`、`p_cull`（及其與飢餓的關係）、ρ。
- θ_P、θ_I、`T_major_min`、敏感窗位置、`m_major`。
- 每口餵食量。
- 本種是否有營養卵、是否有幼蟲消化階級。
- 雌性幼蟲走向新后路徑的條件。

## §5 建議的實作順序（每一步都是獨立的規則更新 PR）

每個 PR 都要做到下列各項：

- 舊行為開關通過黃金測試；
- 多日、多種子，加上極端情境（冷冬、長期缺蛋白、只有蟻后、高溫）；
- 保留失敗證據，不挑選種子；
- PR 說明列出所有新參數及其分類；
- 合併後的下一個遊戲日才生效。

1. **P3-1 發育模型**：線性度日、各階段的 T0、K，以及 `development.model` 開關。附候選 A、B、C 三組的比較。先做這一項，因為 §3 的暫停與 §4 的敏感窗都依賴發育進度。
2. **P3-2 工蟻壽命**：依階級的 Gompertz 曲線（28°C）與生理年齡。`Q10_life` 由玩家決定，未決定前用 null 並關閉溫度效應。兵蟻分支此時還不會被用到，但先備好參數。
3. **P3-3 幼蟲營養改為局部餵食，並加入食卵與幼體被吃（含守恆）**：同時處理 E7、E8。
4. **P3-4 蟻后批次產卵狀態機**：移除 E5 的全巢人口上限。`queen_natural_hazard` 維持 null 或不模擬，除非玩家選定代用值。
5. **P3-5 兵蟻生產**：敏感窗、蛋白門檻、兵蟻接觸抑制、溫度下限。完成後才把 `major_worker_production_enabled` 改為 true；還需要兵蟻的行為與代謝參數（另案）。
6. **P3-6 繁殖蟻與多后**：需要多蟻后的存檔結構。依 CLAUDE.md，不得因機制存在就讓本巢憑空出現新蟻后。**這一項可能超出目前範圍。**

需要玩家先裁示的事項：

- 發育參數用候選 A、B 還是 C；
- `Q10_life` 是否採用非本種的 1.93；
- E8（蟻后與幼蟲讀取全巢營養）是否屬於上帝視角；
- 已存在的幼體 `progress` 換到新模型時如何對應（建議沿用 progress 的比例，不重設）。

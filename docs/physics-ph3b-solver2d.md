> **地位**：隔離的物理實驗。`engine/physics/solver2d.ts`、`engine/physics/broadphase.ts` 不被每日生態循環、Day0、`cli/` 或 `web/` 引用（`tests/physics-isolation.test.ts` 自動涵蓋新檔）。沒有推進遊戲日，沒有改存檔或日誌，`engine/*.ts` 頂層沒有任何修改。

## 2. 設計

### 2.1 運動模型
- 每隻沿自己的通道前進，速度 `v ∈ [0, 自由速度]`；**橫向偏移 u 維持給定值**（橫向轉向模型是未知候選，null）。
- 兩個事件之間，每個身體都是直線等速平移 → 每對身體的間距對時間是**凸函數**。
- 轉折處：朝向在轉折點瞬間轉到下一段（與 `body2d.laneBodyPose` 相同的姿態約定；**幾何約定**，真實螞蟻走曲線）。轉動以保守推進（conservative advancement，對角度 Lipschitz）檢查通道邊、障礙物與其他身體；會穿透就不轉，停在轉折點等。
- u ≠ 0 而路線經過轉折：**拒絕**。偏移的身體怎麼繞過轉折是橫向轉向問題（未知），不補一個做法。

### 2.2 連續碰撞偵測（沒有時間步長）
- `pairFirstHit`：兩個平移膠囊第一次接觸的時刻。第一次接觸前兩軸不相交，所以軸距 = 四個「端點對另一線段」距離的最小值；每個都對時間是凸函數，先解析求最小值位置，再在遞減段上二分求 `距離 = r₁ + r₂` 的第一個根。最近距離只差 `HIT_TOL_MM = 1e-10 mm` 以內的擦身不算接觸。
- 結果只取決於兩個個體的運動紀錄（參考時刻、位置、速度），**不取決於任何時間窗、網格、取樣步長**。
- 與 `body2d.sweptCapsuleContact`（三分＋二分，另一套方法）比對 2,000 組隨機案例，時刻一致到 1e-9 s。
- 靜態幾何（通道邊、多邊形邊、圓形障礙物）同樣用 `pairFirstHit`（速度 0 的膠囊）；轉折處的圓弧邊用保守推進。每隻沿自己路線的「第一個碰到靜態幾何的位置」只算一次（幾何不動），到達就停（`stop`，原因寫明）。

### 2.3 接觸約束與速度解（物理約束而已）
- 事件時刻，間距 ≤ `ACTIVE_TOL_MM = 1e-7 mm` 的每一對是接觸；接觸要求 `dg/dt = n·(v_j e_j − v_i e_i) ≥ 0`（n 是兩軸最近點方向）。速度固定時間距是凸函數，所以起點不減就一直不減，到下一個事件都不會穿透。
- 每條約束都是「`v_x ≤ c·v_y`（c ≥ 0）」或「`v_x ≤ 0`」：迎面＝兩隻都停；追上＝跟著前面那隻的速度（c = 1）；從側面擦過＝允許滑過。
- 取**最大解**（每隻 ≤ 自由速度下盡量快）：上界單調，最大不動點唯一（Tarski），以乘積形式的 Bellman–Ford 鬆弛求得；乘積 < 1 的接觸環的最大解是 0。**唯一解 → 與處理順序、陣列順序無關。**
- 接觸間距長到超過 `ACTIVE_TOL_MM` 時解除約束（時刻用與判定相同的間距函數求，並推到第一個確實超過的浮點數，避免同一瞬間反覆觸發）。**約束的啟用／解除只是速度解的內部簿記**（`stats.contacts`／`releases`），不是接觸事件；接觸事件見 §2.6。

### 2.4 事件與同一瞬間
- 事件：start、goal（抵達）、geo（碰到靜態幾何）、vertex（轉折）、retry（等待轉折後重試）、contact、release、pass（同一通道錯身）。全序：時刻 → 種類 → 個體 id。
- **時刻完全相同**的事件一起處理：先套用全部，再更新接觸、再解一次速度。
- 每個事件帶兩個個體與該對的版本號；版本變了就是過期，丟棄不執行。另有不變式：同一個接觸事件（個體＋版本）執行兩次就中止並回報缺陷。
- 轉折受阻：只在「真正擋到轉動的」身體離開轉動圓盤（解析求離開時刻）或改變運動時重試，與時間窗無關。
- 安全上限：同一時刻超過 10,000 批、或總批數超過上限 → `aborted`，如實回報。

### 2.5 寬相（broad phase）
- 時間窗 `window_s`（預設 0.25 s，純數值）：每個窗的開頭，對每隻算**保守掃掠框**＝這個窗內以自由速度沿路線最多走到的中心路徑，再四周加 L/2（任何朝向的膠囊都在裡面）。窗內不論發生什麼事件，身體都不會離開這個框 → 窗內所有可能的接觸都在候選對中。
- 三種方法輸出完全相同（排序後的同層候選對）：`bruteForcePairs`（O(N²)，**只當參考**）、`gridPairs2D`（均勻網格／空間雜湊，預設 8 mm）、`sweepAndPrunePairs`（x 排序掃描、y 檢查）。主流程預設網格，不做全對比較。
- 時間窗、網格大小、方法都只改變成本：測試中 7 種設定（窗 0.01／0.25／1／25 s、網格 2／8／60 mm、SAP、暴力、反轉輸入順序）的軌跡與事件**逐位元相同**。

### 2.6 接觸事件：由連續幾何精確求出（2026-11-08 修正，契約見 [`physics-time-contract.md`](physics-time-contract.md)）
**舊行為的缺陷（6864974）**：`contact_start`／`contact_end` 直接記在約束啟用／解除的瞬間。滑動接觸以分段等速近似，每當間距打開 θ（1e-7 mm）就解除、全速前進、立刻再碰上——每次解除都被記成一個 `contact_end`，但兩身體間距最多只超過 θ 約 1e-16 mm，並沒有分離。WP4 獨立檢查器量到：區間寬達 0.033 s、100 隻交叉口 8 個結束之前找不到可括出的分離；`contact_start` 記在間距 0 的碰觸瞬間，而不是穿越 θ 的瞬間（晚約 θ／接近速度）；擦邊通過（間距恰為 0）完全沒有接觸事件。

**修正**（解算器本身的事件邏輯，不只改輸出文字；運動完全不變）：
- 物理接觸＝間距 g ≤ θ 的區段，與約束簿記分開。每一對（同層、寬相候選）追蹤 g 在門檻 θ−ρ、θ−ε、θ、θ+ε、θ+ρ 之間的區段（ρ = `SEP_RES_MM` = 1e-9 mm 分離解析度；ε = `GAP_EVAL_ERR_MM` = 1e-11 mm 宣告的間距計算誤差）。兩個運動紀錄之間 g 是凸函數，下一次跨越以「指數搜尋＋二分」（向上）或「膨脹膠囊的精確第一次接觸＋二分」（向下）求出，附根區間。搜尋區間不取決於時間終點。
- `contact_end` ＝ g 第一次超過 θ + ρ 之前最後一次向上穿過 θ；`contact_start` 對稱（θ − ρ）。超過 θ 但未到 θ + ρ 又回來的起伏合併到同一段接觸（`stats.sub_resolution_excursions`）。
- 每個事件附 `bracket_s`、`err_s`、`confirmed_t_s`、`exact`、`usable_as_cause`。事件在確認時才寫入、帶穿越時刻，最後依時間穩定排序。
- 時間終點時間距已超過 θ、未到 θ + ρ：記 `contact_end_unconfirmed`（`solver_status`，不能當原因）。仍接觸：不記結束。
- 一致性：每批之後檢查「有約束的對都在接觸中或待確認」（`stats.constraint_outside_contact`，所有情境 0）。
- 同時修正時間邊界（契約 §2）：經過轉折點不再重設時間錨點（事件時刻由速度改變時的錨點一次算出）；落在 (H, H + 8ε·max(1,H)] 的事件視為在 H；出發恰在 H 而未在目標上的個體記 `started_at_horizon`（舊為 `moving`）。

### 2.7 三種接觸（2026-11-08，Owner 決策第 6 題，#146；契約見 [`physics-time-contract.md`](physics-time-contract.md) §4）
- `geometric_contact`：§2.6 的接觸段（事件 `contact_start`／`contact_end`，`contact_kind: 'geometric_contact'`）。
- `constraint_active`：速度求解的作用集合（`active`）中有這一對的區間，`Solver2DResult.constraint_active`。在作用集合加入／移除該對的地方記錄（唯讀，不回饋運動），並在速度求解後標出這個約束是否**真的限制了速度**（`binding_t_s`、`binding_solves`；與事件 `stop`／`follow` 的原因判斷同一個條件）。起訖是解算器狀態改變的精確時刻，不是 g = θ 的根；釋放由釋放事件造成時附二分根區間 `end_bracket_s`。`stats.contacts`／`stats.releases` 就是區間的開始／結束數（測試斷言）。
- `antenna_contact`：PH-3b 沒有觸角幾何，**不支援、不產生**（`antenna_contact: null`；型別保留給之後 CHEM／CHC #135 的觸角幾何模型）。共同裁判的 `reach_contact_episodes`（`contact_reach_mm` 圓盤距離）只是距離診斷，**不是**觸角接觸，不得當作觸角接觸使用。
- 接觸不代表交哺、招募或攻擊；三種接觸不能互相推導（實例見契約 §4）。所有情境：幾何接觸段與約束區間經獨立檢查器確認 constraint_active ⊆ geometric_contact（解析度以下 0 段），運動紀錄與 83397c5 逐位元相同。

| 保證 | 依據 |

## 5. 不建模（不宣稱）
- 橫向位置怎麼選、側移、讓路、掉頭、交叉口誰先走：生物決策，未知候選，null。
- 偏移身體繞過轉折：拒絕（見 §2.1）。轉折處瞬間轉向是幾何約定。
- 身體外形是膠囊（遊戲假設），不含觸角與腳；**沒有觸角接觸**（`antenna_contact` 不支援，§2.7）。裁判的 reach 距離診斷不是觸角接觸。
- 推擠、摩擦、質量、加速度：沒有。速度只能在 [0, 自由速度]，不會被推著走、不會倒退。
- 節點（交會點、巢口）幾何：通道端點的平頭邊不當牆；身體伸出端點的部分屬於節點，契約回報「未檢查」。
- 同層內不同通道之間：每隻只受自己通道的邊界約束（與 PH-3a 契約相同）。
- 網頁播放：見 `docs/physics-playback.md`（隔離、非正式，只讀匯出的 JSON）。

## 7. 未解缺陷、未知與需要 Owner 決定的事
0. **接觸時刻修正後的未決事項（2026-11-08）**：

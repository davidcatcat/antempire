# Owner 指示紀錄（2026-11-13，之三）：遊戲畫面品質與真實世界呈現列為獨立 P0 工作線

> 來源：Owner 2026-11-13 對 Claude 的指示（觀看目前 demo 之後）。追蹤 issue：[#238](https://github.com/davidcatcat/antempire/issues/238)。本檔只摘錄指示與對開發的影響。
> **這是開發方向與驗收方式的指示，不是 [#201](https://github.com/davidcatcat/antempire/issues/201) 的 Day0 GO**；不改任何科學規則、參數或正式世界的地位。

## 1. 指示內容

| 項 | 指示 | 落實 |
|---|---|---|
| 0 | 目前畫面品質遠低於螞蟻生態遊戲應有的水準。把「遊戲畫面品質與真實世界呈現」列為**獨立 P0 工作線**，與科學引擎**並行**，不得阻擋其他工作 | Roadmap §3f（VIS-0～VIS-8） |
| 產品目標 | 在桌面與手機瀏覽器上，玩家像觀察真實螞蟻一樣，看一個持續運作的微型自然世界；不是儀表板，也不是抽象的實驗室畫面 | [`visual-p0-scene-spec.md`](visual-p0-scene-spec.md) 開頭 |
| 1 | 稽核 main 的網頁、繪圖、動畫、Worker 與物理整合，以及 Roadmap：已完成、缺少、依賴 | [`visual-p0-audit.md`](visual-p0-audit.md) |
| 2 | 完整的場景視覺規格：花園地面、植物、石頭、土壤、巢口、地下剖面、螞蟻形態、食源、其他生物、環境光影 | [`visual-p0-scene-spec.md`](visual-p0-scene-spec.md) §2～§8 |
| 3 | 優先讓螞蟻看得懂：六足步態、身體轉向、觸角動作、連續行走，不是「座標上移動的點」 | 規格 §5、§6；VIS-2（#240） |

| 驗收 | **實際觀看體驗是主要驗收**；CI 通過不證明畫面品質；每個階段交付可觀看的版本與「與上一版比較」的截圖 | 規格 §11；VIS-8（#246） |
| 地下 | 引擎沒有巢室幾何時，地下視圖只能顯示已知結構，或明確標示的概念視圖 | 規格 §7（概念視圖） |

## 2. 與既有規則的關係

- CLAUDE.md §0（科學優先）、§2.4（玩家視角不回饋）、§8（三類資料、「引擎沒有的機制，畫面就不顯示或標示尚未模擬」）、§9（Worker 邊界）全部照常適用；本指示沒有放寬任何一條。
- 每個 VIS 工作包是**純可視化 PR**（只讀 Worker 狀態框與事件）；只有 VIS-7 的運動學接入會改變 P0-A2 的事件時間，屬規則更新，依 CLAUDE.md §6、§9 另開 PR（預設關閉、版本邊界、Worker 白名單擴充附邊界測試），並依 #189 的授權範圍處理。
- 先前的畫面工作（V6 美術 PR A／B／C、#159、#164、V6-2）保留為基礎；本指示新增的是：以 P0-A2 實驗世界為主要對象、地下概念視圖、以觀看體驗與比較截圖為驗收。
- 2026-11-08 起的 Owner 決策（例如 20：只在紀錄的朝向改變時畫顯示轉身；47：預設 1×；49、50：WebGL 與效能以實機數據決定）繼續有效。

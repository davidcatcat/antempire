# C4b 幼蟲個體發育：候選模型、可辨識性與驗證（Issue #81，2026-11-07）

> **地位**：設計與工程基礎。引擎開關 `larval_development.individual_development_c4b` 預設關閉，而且在 Owner 選定營養反應形式之前**不能打開**（參數為 `null` 時讀參數就拒絕）。不推進遊戲日、不改 Day1～14 歷史與 Day14 權威存檔、不啟動新版正式 Day0。
> 依據分類沿用 CLAUDE.md §3：【觀測】【推導】【模型假設】【生物學推論】；他種一律標「非本種」。

## 1. 要修的缺陷（L2）

- `engine/brood.ts` `developBrood`：每隻幼蟲的發育速度乘上**全巢**的 `min(pFraction, sFraction)`。幼蟲自己被餵多少，對自己的發育沒有任何影響。
- C4a（v28）之後，個體攝取已經有紀錄，但發育仍讀全巢比例。C4a 敏感度（`reports/c4a-v28-sensitivity`）顯示：
  - 每口量 ×0.5 到 ×2，幼蟲自己的蛋白攝取／需求由 0.23 變到 0.72；
  - 化蛹數幾乎不變（1362、1350、1367）。
  - 這是 L2 的直接證據：發育與個體攝取無關。
- 而且 C4a 打開後全巢需求不再含幼蟲，全巢比例只反映工蟻，L2 的輸入意義也變了（`docs/design-c4-larval-nutrition.md` §7.2）。

## 2. 候選模型

```
dPᵢ/dt = r_s(Tᵢ) × Nᵢ(t) × Cᵢ(t) × ρᵢ
```

| 項 | 意義 | 本 PR 的處理 |
|---|---|---|
| `r_s(T)` | 階段 s 的溫度反應 | **不改**。沿用現行 Q10（上下限截斷）；溫度模型是 #38／P0-B 的待決事項 |
| `ρᵢ` | 持久個體發育率因子 | **不加**（P0-B：可辨識性不足，預設 `null`＝1） |
| `Nᵢ(t)` | 個體營養對發育的影響 | **候選形式並列，由 Owner 選**（§3） |
| `Cᵢ(t)` | 個體受照護的影響 | 沿用現行規則（§4），列為已知限制 |

### 2.1 Nᵢ 的輸入：用「自己實際支付的代謝」，不用「今天被餵的量」

C4a 的餵食是離散的一口：每口等於一日需求，平均每幼蟲日 0.79 次接觸。今日攝取／需求只會是 0 或 ≥ 1，直接拿來當 Nᵢ 會讓發育每天在最低與最高之間跳動。這是餵食離散化造成的人為現象，不是生理。

候選的輸入是**自己當日實際支付的代謝比例**：

```
xᵢ = min_f ( paid_f,i / need_f,i ),   f ∈ {糖, 蛋白}
```

- `paid` 由幼蟲自己的 `fed_balance` 支付（C4a，D3）。昨天多吃的存量今天可以用，所以 xᵢ 會被自己的收支緩衝。
- 輸入只有這隻幼蟲自己的紀錄，與全巢量無關（A5 靜態與執行期檢查）。
- 【模型假設】「發育受限於可支付的代謝」是一般昆蟲生理學的方向（生長需要同化的營養），**不是本種實測**；取兩種食物的較小值，沿用舊式（Liebig 式最小因子），也是假設。

## 3. Nᵢ 的候選形式（待 Owner 選擇）

| 候選 | 形式 | 新參數 | 可辨識性 | 說明 |
|---|---|---|---|---|
| **N-a 延續舊式** | `clamp(xᵢ, n_min, 1)` | 無（沿用 `larva_min_nutrition_growth_factor` = 0.1） | 沒有新參數；但「線性比例」本身沒有證據 | 只把舊公式的輸入從全巢換成個體。Owner 已指示：不得在沒有證據時直接設為線性比例，所以**不作為預設** |
| **N-b 門檻** | `xᵢ ≥ θ ? 1 : n_min` | θ（**null**，本種無資料） | θ 不可辨識 | 「吃夠就照溫度發育，不夠就幾乎停」 |
| **N-c 飽和** | `n_min + (1 − n_min) · xᵢ (1 + K) / (K + xᵢ)` | K（**null**） | K 不可辨識 | 少量營養就有大部分效果 |
| **N-d 累積量** | `dP = min(r_s(T), aᵢ / Q)`：發育量受「已同化營養累積」限制 | Q＝完成幼蟲期所需的營養總量（**null**） | Q 不可辨識；需要單位轉換（遊戲份量 → 質量），目前沒有 | 與「臨界體重」的一般昆蟲生理學方向一致（非本種）；最有生理意義，但參數最多 |

**可辨識性（為什麼本種資料選不出形式）**：
- 【觀測】Yuan 2026（R94）的條件是 28 ± 1 °C、70 ± 5 % RH、食物充足。在這個條件下所有候選的 xᵢ ≈ 1，Nᵢ ≈ 1，四種形式的預測相同。所以 Yuan 只能驗 `r_s(T)` 與整體分布，**不能區分 Nᵢ 的形式**。
- 【觀測】Phillips 1933（R167）：停食兩週後恢復餵食，幼蟲期延長（A9）。這只支持「沒被餵時發育變慢或停止，恢復後繼續」的方向，四種候選都符合；沒有劑量反應資料，無法決定形狀或參數。
- 因此任何選擇都是**模型假設**。不得用存活率或結果好看與否挑選（CLAUDE.md §7）。

**建議（給 Owner 參考，不是決定）**：
- 若要沒有新參數：N-a，但要明示「線性比例是假設，不是證據」。
- 若要較有生理意義：N-d，但需要先決定 Q 與單位，目前沒有本種依據，所以實際上不可用。
- N-b、N-c 都多一個不可辨識的參數，只適合做敏感度掃描。

## 4. Cᵢ（照護）

- 現行規則：當日開始時整個蟻群沒有任何工蟻，幼蟲就不發育；連續無照護達上限就死亡（`brood_care`，遊戲假設）。
- 這讀的是「全巢是否還有工蟻」，雖然不是營養統計量，仍是全巢量。
- 個體化的候選：「過去 k 日是否被實際接觸」。但 C4a 的接觸稀疏（平均每幼蟲日 0.79 次），k 與效果的形狀都沒有本種資料。
- **本 PR 不改照護規則**，列為已知限制，之後另開 PR 處理。

## 5. 守恆與單位

- 個體已知營養收支沿用 C4a：
  `期末 fed_balance = 期初 + 實際被餵 − 自己支付的代謝 − 其他有事件的支出（羽化、死亡）`，不可為負。
- C4b 只**讀** `paid / need`，不新增任何轉移，所以 C2 帳不變。
- 未滿足需求另行記錄（`larva_nutrition.shortfall_portions`，C4a 已有）。
- 糖與蛋白分開；**遊戲份量不是 mg、不是能量**。N-d 若要用「營養總量」，必須先建立單位轉換與證據，本 PR 不做。

## 9. 工程階段的診斷結果（2026-11-07，只報告，不調參）

### 9.1 打開 C4b 後幾乎沒有幼蟲化蛹
- 以三種**測試用**形式（clamp_linear；threshold θ = 0.5；saturating K = 0.5）跑 Day0 A1、A3、A5 春季各 150 日，三種形式都**沒有任何化蛹**，平均 N ≈ 0.106（接近最低值 0.1）。
- 1,504 個幼蟲日中，98.7 % 當日支付的代謝為 0，平均支付比例只有 2.4 %（糖與蛋白都是）。
- 原因不在 N 的形式，而在上游：
  - 這些小蟻群（10 隻工蟻左右）的任務分配常常讓保育工蟻為 0，當天沒有任何 `larva_contact`，幼蟲完全沒被餵；
  - 只開 C4a 時，幼蟲仍以全巢公式發育（L2），所以看不出來；
  - C4b 讓沒被餵的幼蟲停滯，沒有新工蟻羽化，蟻群逐漸萎縮。
- 這是現有任務分配（遊戲假設）與 C3a／C4a 餵食路線的結果。**不得用調高餵食量、改形式或改參數去讓蟻群存活**（CLAUDE.md §7）。
- 要讓 C4b 的結果有意義，需要先處理上游：保育工蟻的數量與接觸（任務分配是否應依局部的幼蟲訊號）、蛋白經路線 B1 的供給，屬 Owner 的模型選擇。

### 9.2 新發現的局部性缺陷：舊的保育工蟻求食線索不看位置
- `engine/workers.ts` 的保育工蟻接觸（W-NURSECONTACT，`nurse_contact:<id>`）從**所有**幼蟲中抽一隻讀取訊號，不管幼蟲在哪個位置。
- C4a 之後幼蟲有位置：另一位置的幼蟲沒被餵、訊號升高，保育工蟻「碰到」它們後改變覓食決策，嗉囊內容改變，第 3 日起原有幼蟲被餵的量就不同（B2 多日測試）。
- 另一條路徑：蟻后產卵讀全巢幼體數（C3b，暫停）。
- 修正（只從同位置的幼蟲中抽）會改變 C4a 打開時的行為，要另開規則更新 PR；本 PR 的 B2 只驗加入當日逐位元相同，多日的差異照實記錄。

### 9.3 Yuan 2026 觀察算子（B7）
- 條件：28 °C 固定、食物充足（x = 1）、每日檢查、一批 200 顆同日卵；發育是決定式的，沒有個體因子。
- 模擬：孵化第 9 日、化蛹第 20 日、羽化第 29 日，SD 都是 0。
- 觀測：孵化 7.69 ± 0.63 日（n 227）、蛹 23.68 日（n 80）、非繁殖型成蟲 28.73 ± 2.83 日（n 52）。
- 差異：卵期偏長、幼蟲期偏短、蛹期偏長，總長接近；SD 為 0 是預期中的不一致（沒有個體差異、同步的一批）。這些是 P0-B／#38 溫度與個體差異模型的範圍，本 PR 不調整。

### 9.4 Phillips 1933 方向（B8）
- 25 °C、前 14 日沒被餵、之後充足：三種測試形式的化蛹日都由第 13 日延後到第 25 日。
- 只驗方向（沒被餵時發育變慢，恢復後繼續），沒有可比較的本種數量。

- θ ∈ {0, 0.25, 0.5, 0.75, 1}（含引擎允許的兩個端點 0 與 1）與 K ∈ {0.1, 0.5, 2} 是**測試格點**，不是候選數值。
- 所有實驗在參考溫度下進行（溫度因子 1），n_min = 0.1（遊戲假設）、larva_days = 12（遊戲假設）。

### 10.1 數學性質
| 形式 | 定義域與值域 | 端點 | 單調 | 連續 | 形狀 |
|---|---|---|---|---|---|
| clamp_linear | x ∈ [0,1] → [n_min, 1] | N(0) = n_min，N(1) = 1 | 是 | 是 | 線性（x < n_min 時被截在 n_min） |
| threshold θ ∈ (0, 1] | 同上 | 同上 | 是 | **否**：在 θ 有一個大小 1 − n_min 的跳躍 | 階梯 |
| threshold θ = 0（合法端點） | x ∈ [0,1] → {1} | **N(0) = 1**，N(1) = 1 | 是（常數） | 是（常數） | N ≡ 1：不餵也全速發育 |
| saturating K | 同上 | 同上 | 是 | 是 | **凹**：飼料變動時，平均速率高於同平均 x 的線性形式（Jensen 不等式） |

- x 是無因次比例（自己支付的代謝 ÷ 自己的需求，取兩種食物中較小者）。
- N 也是無因次；發育速率的單位是 1/日。

### 10.3 可辨識性結論
> **更正（Owner P2，2026-11-07）**：前一版寫「所有形式的端點都相同：N(0) = n_min」，漏掉合法的 θ = 0（引擎接受 θ ∈ [0, 1]）。θ = 0 時 x ≥ 0 恆成立，N ≡ 1，不餵也全速發育，所以 N(0) = 1。已把 θ = 0 與 θ = 1 加入格點、改寫結論與測試。

- N(1) = 1 對所有形式、所有合法 θ 與 K 成立。N(0) = n_min 對 clamp_linear、所有 K > 0 與 θ ∈ (0, 1] 成立；**θ = 0 是例外**（N(0) = 1）。
- **除了 θ = 0**，只由「不餵」與「吃飽」組成的飼養歷史，在每種形式、每個 θ 與 K 下得到**完全相同**的化蛹時間，跨形式差距為 0。
  - Phillips 1933（R167）是不餵與吃飽：**能**把 θ = 0 與其他形式分開（θ = 0 時 E2 為 12 日，其他都是 24.6 日）。它支持的方向「不餵時發育變慢，恢復餵食後繼續」**排除 θ = 0**（以及任何 N(0) = 1 的形式）。
  - 其餘形式之間，Phillips 1933 與 Yuan 2026（R94，吃飽；含 θ = 0 也分不開）都**無法辨識**。
  - 排除 θ = 0 只依方向，不需要數量。除 θ = 0 外，不餵時的速率完全由 n_min 決定，而 n_min 本身是遊戲假設。
- 部分配給時，各形式差異極大：x = 0.3 時幼蟲期從 12 到 120 日（12 日來自 θ = 0 與 θ = 0.25，後者在 x ≥ 0.25 時全速）。所以形式的選擇對結果有決定性影響，**不能憑直覺選定**。
- **能辨識形式的資料**：多個中間配給水準下的個體發育時間（劑量反應）。docs/references.md 中沒有本種研究報告這種資料。
- **個體差異**（#84）：只由每日 x 的變動產生差異（E4 的 SD）；本模型沒有內在的個體差異。Yuan 2026 的 SD（例如羽化 28.73 ± 2.83 日）需要另外的個體變異模型（P0-B 候選），不在 C4b 中。

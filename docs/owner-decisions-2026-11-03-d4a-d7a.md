## 1. D4-A：完整繁殖系統是新版正式 Day0 的必要條件
新版正式 Day0 啟動前，必須具備科學上合理、**可執行、可驗證**的完整繁殖生命週期：
1. 蟻后產卵與繁殖週期；
2. 受精卵、未受精卵與性別決定；
3. 卵、幼蟲、蛹與成蟲的完整發育；
4. 小工蟻與大工蟻的發育分化；
5. 雄蟻的出生、成熟、生理、交配與死亡；
6. 新蟻后（gyne）的形成、成熟與繁殖；
7. 多蟻后的共存、繁殖、死亡與更替；
8. 符合物種與地區證據的交配方式；
9. 婚飛，以及其他有證據支持的繁殖擴散方式；
10. 分巢、建立新巢、巢間交流與族群擴張。

**怎麼解讀（本文件的執行規則）**：
- 這些機制要**依自然條件自主發生**，不必每天出現。
- **不得強制產生**：不得為了展示功能，讓蟻群產生雄蟻、新蟻后或分巢。驗收不設產量目標，改用「可達性測試」：在 Day0 實驗世界建構輸入條件，檢查路徑走得完、事件可追溯。正式世界裡沒有出現是合法的結果，但要能從個體的輸入解釋它為什麼沒有出現。
- **不得關閉**：不得因為缺資料，就把未完成的繁殖功能關掉，再宣稱正式 Day0 已完整。
  - CLAUDE.md §6 要求的「舊模型開關＋黃金測試」仍是開發流程，可以保留；但**正式 Day0 設定檔中，10 項都必須啟用**。
  - 新增「Day0 完整性閘門」測試：任一項關閉、或使用舊行為（例如「所有卵都受精」），就失敗。唯一例外是 Owner 確認過的阻擋項（§5）。
  - 「有證據顯示機制不存在」不算關閉，但要寫成證據判定。例：*Pheidole* 工蟻沒有卵巢，所以工蟻不產雄卵。
- **證據不足時**：建立可驗證的候選模型，標明假設與不確定性，並做敏感度分析；無法建立合理模型時，報告阻擋原因，不得捏造數據。
- **取代 PR #55 的建議**：
  - OD-2「繁殖不列入正式 Day0」**已被取代**；
  - OD-4「正式世界不開 D 類假設」與 D4-A 衝突，改為：正式世界可以使用標明 `assumption: true`、附範圍與敏感度結果的候選模型。

## 2. D7-A：開放式自然生態世界
- 臺中市西屯區的虛構住宅花園是主要觀察區域，但**不是封閉的生態容器**。
- 花園外有自主運作的生態環境，尺度要適當：
  - 植物、植被與棲地；
  - 蚜蟲、介殼蟲與其他半翅目；
  - 其他昆蟲與節肢動物；
  - 蜘蛛與其他有棲地依據的掠食者；
  - 其他螞蟻族群與巢穴；
  - 外部食物來源、屍體與分解作用；
  - 季節、天氣、溫濕度與棲地變化；
  - 繁殖、死亡、擴散與族群變動。
- **進出規則**：
  - 外界生物可以自然進入花園，花園內的生物也可以離開；所有進出都要有**生態因果來源**。
  - 不得因為主角蟻群缺食物、工蟻或新蟻后，就自動生成外界補給。
  - 外部環境即使沒有主角蟻群，也依自己的規則持續演化。
- **取代 PR #55 的 OD-3**（「只記錄離開模擬區域」）：離開花園的個體進入外部生態，之後由外部模組依自己的規律決定其命運。
- **禁止**：
  - 「離開視野＝死亡」；
  - 「進入視野＝自動出生」；
  - 邊界外有無限生物。

  使用抽象的外部族群時，出生、死亡、移入、移出分開記帳。

## 4. 開發順序（Owner 指示；各階段可以並行研究，有行為依賴的程式修改依先後順序）
1. **C2～C5**＋Issue #56：C2 引擎直接產生食物轉移事件（PR 另開）→ C3 蟻后依實際攝食產卵 → C4 幼蟲依實際被餵的量 → C5 工蟻個體營養、飢餓、死亡與屍體。
2. **時間與生命史**：P0-A 24 小時時鐘、P0-B 發育與溫度、分階級壽命、蟻后批次產卵、個體工作與休息。
3. **物理空間**：花園共用幾何、巢穴與通道、巢內移動、巢穴擴張／修補／遷移。
4. **開放式生態**：周圍棲地、外部族群、自主生命週期、邊界進出、世界共用事件時間軸、多群共享資源與競爭。
5. **完整繁殖系統**：依 PR #55 的 RR 規劃，再依本決策修訂（`docs/research-design-reproduction-d4a.md`）。

繁殖系統與開放生態**必須能交換個體與事件**：只有一本帳，不允許各子系統自行產生彼此不一致的生物數量。

## 0. 結論先講

1. **Chen & Neoh 2023（R145）本次重讀正文**（Frontiers 開放全文；圖 2 數值沿用 2026-11-03 的目測，本次沒有重新量圖）。都市（3 月）的本種「多在白天」，但夜間仍有捕獲；森林（5 月）整個 72 小時都有活動、日夜相近。**這是兩個描述性型態，原文沒有針對本種的日夜統計檢定**，也沒有本種活動對溫度、光、濕度的係數。
2. 這兩個型態放在一起是一個**有用的反例**：森林的晝夜地表溫差（26.6 vs 22.7°C）和都市（31.2 vs 27.7°C）差不多，森林卻日夜平坦。若模型只靠「溫度越高越活躍」的單調曲線，會預測森林也是白天高。作者自己提出的解釋是**都市白天的人類廚餘時段**（食物可得性），並明說「排除了生理優勢的解釋」（這是作者的推論，不是量測）。因此 P0-A2 必須讓活動時間由**溫度、食物出現時刻、局部招募、飽足**共同湧現，不可只放一條溫度曲線；而且**不能為了重現這兩個型態去調參**。
3. **CTmax 的量法會改變數值**：Chen & Neoh 用慢速升溫（35°C 前約 0.5°C/min、之後 0.2°C/min）。Leong et al. 2022（R760，香港，含本種，全文）發現慢速升溫得到的 CTmax 與野外最高覓食地表溫度（FTmax）差得最多；1°C/min 的 CTmax 最接近 FTmax（本種 |FTmax−CTmax| 約 3°C，表 2；**絕對值在圖 4，未讀數**）。所以 42／44°C 只能當「熱昏迷的參考」，**不是**覓食停止溫度，也不能直接比較不同方法量的值。
4. 其他本種資料（已在庫中）：Asfiya et al. 2016（R146，澳洲，上午 > 下午，餌站上本種比例的 50% 點為地表 41.9°C）、Su 1979（R229，夏威夷，傍晚到夜間約為白天 2 倍）、Castiñeiras 1982（R228，哈瓦那，24 小時都有、月份效應 > 時段效應，**只有摘要**）、Phillips 1933（R167，清晨／傍晚／夜間最活躍，冬季夜間停止）。**所有本種逐時資料都是誘餌或陷阱的活動密度**；沒有任何研究量過本種個別工蟻一天的活動、休息或任務時間。
5. 設計結論：P0-A2 的個體是**事件驅動的狀態機**，每次決策只讀自己的生理與所在位置的局部環境；活動時間分布是**輸出**；驗證用「虛擬落阱」觀測算子在同一單位下與 R145 等比較**形狀**，不比絕對量、不調參。
6. **環境輸入的限制照舊**：Parton–Logan 係數仍是 `null` → 逐時氣溫只能來自（a）逐時觀測，或（b）**明確標示 `synthetic: true` 的情境逐時剖面**；兩者皆無時溫度是 `null`，依賴溫度的機制**拒絕執行並記錄**，不補預設值。降雨只有逐時觀測或明示情境時段；**不發明雨的時刻**。

## 4. 模型設計（第二階段原型的規格）

### 4.1 時間分層（沿用 P0-A0／P0-A1 的 `layered` 契約）
| 層 | 時鐘 | 事件 |
|---|---|---|
| 世界環境 | `eco.light`、`eco.weather`、`eco.rain`（P0-A1 已有） | 曙光、日出、日落、暮光；逐時取樣；雨開始／結束 |
| 個體行為 | 每隻工蟻一個具名生態時鐘 `ant.<id>`（分鐘或秒原生時間） | `bout_end`、`arrive`、`contact`、`safety_check`（P0-A 設計 §3.1） |
| 物理（之後） | PH 的秒時鐘 | 第二階段**不用**；移動時間沿用路段長度 ÷ 速度（R133，`assumption: true`）；#157、#158 完成後替換 |

- 排序只依精確時刻＋round＋id（`layered`）；同一精確時刻的事件是**一個集合**，不依陣列順序決定先後。資源同時競爭沿用 P0-A1 §7 的 `contest_unresolved`（規則未決，不選贏家）。
- 延遲一律在原生時鐘上相加（`addNative`）。24:00 不重設任何個體狀態。

### 4.2 環境輸入槽（環境模組不讀任何蟻群狀態）
| 輸入 | 允許的來源（依序） | 缺值時 |
|---|---|---|
| 氣溫 `T_air(t)` | ① 逐時觀測（測站、時間戳記、`observation`）；② **情境逐時剖面**：24 個值的檔案，`synthetic: true`、`assumption: true`、寫明產生方式（例如「臺中 3 月平年值的日最高／最低溫，以手寫線性內插」）；③ Parton–Logan 重建（**係數 `null` 前不可用**） | `null` → 依賴溫度的機制拒絕執行，事件記 `temp_unavailable`；**不得**用常數或平均值補 |
| 相對濕度 `RH(t)` | 同上；或 P0-A1 的水氣壓內插（需要逐時氣溫） | `null` → 失水子模型關閉並記錄 |
| 微地點溫度 `T_site` | `T_air + surface_offset_c(site)`；參考情境 offset 0 | 同氣溫 |
| 光 `light_state` | P0-A1 太陽計算（一般方法） | 不會缺 |
| 雨 `raining(site,t)` | 逐時觀測；或明示的情境時段（遊戲假設） | `null`（未知）→ 雨效應不套用並記錄；**不當作 0 mm、不發明時刻** |
| 食物出現 | 只能來自世界生態事件（蜜露、花蜜、昆蟲死亡、人類活動情境），帶來源 ID | 沒有事件就沒有食物 |

「人類食物時刻」若要用來檢驗 R145 的都市假說，只能是**明示的世界情境事件**（標遊戲假設），作為對照情境比較；不得用來讓結果貼近圖 2。

### 4.3 個體狀態（每隻獨立；P0-A 設計 §2.3 的超集）
`location`、`activity_state`（`resting`、`awake_idle`、`nest_task:{brood_care|cleaning|repair}`、`outbound`、`at_source`、`returning`、`sheltering`）、`state_since`、`crop`（量與成分，只由自己的取食與交哺改變）、`theta[task]`、`response_gain`、`thermal_offset_c`、`water_deficit`、`desiccation_tolerance`、`rest_debt`（選用）、`recent_contacts`（環形緩衝）、`route_memory`、`food_memory`、`food_time_memory`（選用）、`internal_phase`（選用，只能在巢口或巢外照到光時校正）、`ctmax_i`（熱傷害用；分布 `null`）。

**不設**：全巢存糧、全巢飢餓、全巢幼體數、「現在幾點」。巢內工蟻不知道外面天亮或下雨，除非自己走到巢口／巢外，或接觸到剛回巢的同伴（身體濕、嗉囊滿）。

### 4.4 決策（每個事件，只用局部訊號）
沿用 P0-A 設計 §6.1：`P_start(k) = gain_i × hill(s_ik; θ_ik, n) × E_k(local env) × R_i(rest)`。

- **覓食刺激** `s_forage`：`(1 − crop_fill)`＋最近 W 內**實際**接觸到的回巢覓食者／招募次數。
- **照護刺激** `s_brood`：最近**實際**碰到的幼蟲求食訊號（C4 已有局部求食訊號；不讀全巢幼體數，CLAUDE.md §2.1b）。
- **清潔／修繕刺激**：所在巢室的局部狀態（P1-B 之前為 `null`，該工作停用並記錄）。
- **環境係數 `E_k` 只作用在出巢類工作**，且只在工蟻**位於巢口或巢外**時評估；巢內工作不乘任何光或溫度係數（R236、R237，非本種）。
- `E_forage = f_T(T_site + offset_i) × f_VPD × f_rain × f_light`；參考情境 `f_light ≡ 1`（允許夜間，Owner 2026-11-02）；「只在白天」與「光門檻」只作對照情境。
- 巢外每到路段端點才檢查：熱傷害（`T_site ≥ ctmax_i`）、回頭界限、雨、失水 → 回巢或就地遮蔽（P0-A 設計 §6.3）。

### 4.5 湧現的量（輸出，不是輸入）
每隻工蟻與全巢的：出巢分鐘、出巢次數、各工作時間、休息比例、夜間（日落到日出）活動比例、高峰時段；每個虛擬落阱的 3 小時計數。**沒有任何地方寫入「一天活動 N 分鐘」「白天 X%」之類的曲線或配額。**

### 4.6 觀測算子（玩家／研究視角，不回饋）
- **虛擬落阱**：放在指定地點，只計數經過或停留的工蟻；3 小時一格、從 00:00 開始、可合併多日（對應 R145）。另有 2 小時誘餌式（對應 R228、R229）。
- 不產生食物、不改任何工蟻狀態；不在任何決策函式的輸入中。測試：有無觀測算子，世界歷史逐位元組相同。
- 真實誘餌會引發招募，虛擬落阱不會；只比形狀。

## 8. 不變量與測試（第二階段必須阻擋性）

1. **決定性**：同輸入＋同種子＋同參數 → 事件紀錄逐位元組相同。
2. **排列不變**：`workers[]`、`colonies[]` 順序與 ID 改名不改結果（#56）。
3. **分段不變**：在任意精確時刻（含 23:59:59.5、00:00、雨中、交哺中）快照／還原或分成任意多次 `runUntil`，結果等於一次連續執行。這同時是第三階段「FPS 不改因果」的基礎。
4. **局部性（型別＋執行期）**：決策函式的參數型別不含任何蟻群聚合物件；環境函式不含蟻群；記錄的每個刺激都能追溯到一次接觸、一次親身抵達或自己的生理量。
5. **巢內不知天候**：巢內工蟻收到的事件中沒有光與雨；`local_env_change` 只送給當時在露天位置者。
6. **無曲線注入**：程式中沒有「時段 → 活動機率」的表；測試搜尋原始碼與參數檔的禁用欄位。
7. **缺值拒絕**：溫度 `null` 時依賴溫度的情境拒絕啟動；雨 `null` 時不產生雨事件；兩者都有紀錄。
8. **觀測不回饋**：有無虛擬落阱，世界歷史相同。
9. **守恆**：嗉囊與食物由 C2 事件帳記錄（#145 單一帳本）；個體數只由生死事件改變。
10. **隔離**：正式程式（`engine/*.ts`、`cli/`、`web/src`）不匯入原型；黃金測試逐位元組相同；不在規則指紋內。

## 9. 第三階段：V6-2 Web Worker 如何接上

| 要求 | 設計 |
|---|---|
| 模擬與 FPS 分離 | Worker 擁有排程器、世界與個體；主執行緒只收快照與事件流，用自己的 FPS 畫 |
| 播放／暫停／速度 | 主執行緒只送 `{play}`、`{pause}`、`{speed: 世界秒/真實秒}`、`{follow: id}`。Worker 每個預算週期呼叫 `runUntil(目標精確時刻)`；速度只決定**目標時刻推進多快**，不改事件內容或順序 |
| FPS 下降 | Worker 落後時只會晚一點到達同一個目標時刻，或略過畫面幀；**世界歷史不變**（不變量 3：任意分段＝連續）。不得用畫面 dt 當模擬步長 |
| 追蹤個體 | 純鏡頭；不改精度、不升降級（#144：畫面行為不得觸發精度升降）。測試：追蹤／不追蹤、任何縮放，生死、發育、繁殖逐個體相同 |
| 持續推進 | 世界時間無上限推進；不寫存檔（V6-2b）；可由同一種子＋輸入重播並與 Node 同一原型的輸出逐位元組比對 |
| 控制訊息白名單 | Worker 只接受上述四種訊息；其他一律拒絕並記錄。沒有任何訊息能改世界狀態、參數、種子或事件（§2.5 只觀察） |
| 三類資料 | 引擎事件原樣；兩事件間位置為顯示插值（標示）；沒有示範資料混入。實驗世界標「非正式」；沒有精確分鐘的事件不畫在精確分鐘 |
| 依賴 | `web/src` 不得匯入 `engine/`：Worker 的打包方式（獨立入口、由建置流程產生）需要另案設計，並更新 web 隔離測試——**需 Owner 確認**（§10） |

#145：個體 ID、群組與帳本以單一權威帳為準，Worker 不另建人口帳。#157／#158：之後以二維運動學與出口容量取代「路段長度 ÷ 速度」的移動時間；介面為「抵達事件的精確時刻」，所以替換不改決策層。

## 10. 需要 Owner 決定

1. **逐時氣溫來源**：第二階段要用（a）情境逐時剖面（`synthetic: true`，手寫或由月平年值內插，明示為遊戲假設），還是（b）先取得臺中測站逐時觀測？Parton–Logan 係數仍 `null`。
2. **人類食物時刻情境**：可否作為 V3 的對照世界事件（遊戲假設）？它只用來檢驗 R145 作者的假說，不作參考情境。
3. **CTmax 取值**：沿用 42／44°C（慢升溫）作熱傷害參考，或在個體間抽樣？R760 顯示量法造成數度差異。
4. **Worker 與 `web/src` 隔離規則**：V6-2 需要在瀏覽器執行引擎原型。是否允許一個獨立的 Worker 入口（例如 `web/worker/`，由建置產生、不屬於 `web/src`）匯入 `engine/` 的隔離模組？
5. **安全檢查間隔** `safety_check_interval_min`：是非生物參數，但可能影響湧現的活動時間；是否接受「以 30／60 分敏感度證明不影響型態」作為門檻？
6. 是否嘗試取得 Leong 2022 的補充資料（各種 CTmax 與 FTmax 絕對值）與 Castiñeiras 1982 全文。

## (a) 範圍與 D7-A 原則

### a.1 要解決的問題
目前的模型把臺中市西屯區的虛構花園當成一個幾乎封閉的盒子：
- 只有一個「相鄰庭園」昆蟲數字會單向流入；
- 只有一個固定比例的「背景蟻群」會分走 F04 的蜜露；
- 主蟻群的任何個體都不可能離開或進入花園。

D7-A 要求花園是**主要觀察區，但不是封閉容器**。花園外有一個尺度適當、自主運作的生態系，個體可以有原因地進出。

### a.2 D7-A 與 D4-A 的原則（本文件的驗收依據）
| # | 原則 | 來源 |
|---|---|---|

### a.3 不在本文件範圍
- 玩家干預（CLAUDE.md §2.5）：不設計、不預留。
- 疾病、寄生物：只列為阻擋項（§j）。
- 正式世界切換：另由新版正式 Day0 的遷移 PR 處理。

### a.4 一句話的設計結論
**邊界是一張帳，不是一道牆，也不是一個黑洞。** 每個生物在任何時刻只屬於一個區域；跨區是一筆事件，出發區的帳減一、到達區的帳加一；區域本身只能靠出生、死亡、遷入、遷出改變數量。

### c.2 第 1 層：花園個體模型
- **主蟻群一律是個體**：ID、階級（minor／major／蟻后／雄蟻／gyne／幼體各期）、年齡、生理（含 C2–C5 的區室）、位置、路線、個體記憶、營養、接觸、發育、繁殖、死亡。
- **規則（建議，需 Owner 確認）：「第 1 層跟著蟻群走，不跟著籬笆走。」**
  - 主蟻群的覓食工蟻走出花園時，仍是第 1 層個體，只是位置的空間解析度降為「斑塊＋到該斑塊的路段」。
  - 主蟻群若在花園外建立姊妹巢（多巢），那個巢也是第 1 層。
  - 理由：
    - C2–C5 要求每份食物都在某個個體或巢的區室裡（`docs/design-wpc-food-compartments.md`）；把外出工蟻降為族群計數，會讓嗉囊裡的食物失去歸屬。
    - Tsuji & Win 2025（R116）顯示本種巢間的營養交換靠**工蟻移動與工蟻間交哺**；這種交換只能在個體層級模擬。
  - 代價：計算量隨主蟻群擴張而增加。若日後需要粗化，只能用 §c.5 的「群組個體」並明示，不得悄悄降級。
- **其他生物在花園內的表示層級依類群宣告**（寫在世界參數檔，`assumption: true`）：
  | 類群 | 建議表示 | 理由 |
  |---|---|---|
  | 被模擬的其他蟻群（第二蟻群起） | 個體 | 多蟻群時間軸（`docs/multi-colony-timeline.md`）以工蟻為單位 |
  | 外部蟻群進花園的覓食者 | 暫時個體（越界時升級，離開時降級） | 要和主蟻群在同一時間軸上搶同一份資源 |
  | 大型、稀少的掠食者（蟾蜍、壁虎、大型蜘蛛） | 個體 | 數量少；捕食必須有同時同地的接觸事件 |
  | 小型蜘蛛、獵物昆蟲、分解者 | 齡期群組（cohort），每組有 ID | 數量多；現行 F07／F11 已是計數 |
  | 蚜蟲、介殼蟲 | 寄主上的群組（每個寄主一組，含齡期或至少成蟲／若蟲） | 族群以群落為單位（R179、R182） |
  | 植物 | 個體（寄主、開花植物）或斑塊植被狀態 | 寄主死亡已是個別事件 |

### c.3 第 2 層：周邊棲地斑塊
- **斑塊（patch）**是空間明確的棲地單位，有自己的狀態與規則；斑塊之間、斑塊與花園之間用「鄰接邊」相連，邊有距離與通行條件（距離未知就是 `null`，不推算）。
- **每個斑塊的狀態變數**（未知一律 `null`）：
  | 變數 | 說明 |
  |---|---|
  | `patch_id`、`habitat_type` | 例如 `neighbor_garden`、`wall_base`、`street_tree_strip`、`drain`、`lawn`、`paved` |
  | `area_m2`、`geometry` | 情境宣告；沒有就 `null` |
  | `microclimate_offsets` | 對世界天氣的遮陰、地表、濕度偏移；P0-A 的參考情境為 0°C（Owner 已決定） |
  | `vegetation` | 寄主植物群組、開花植物群組（物候情境）、落葉量 |
  | `populations[taxon]` | 每個類群依齡期（或年齡類別）的整數個數 |
  | `resources` | 蜜露、花蜜、屍體批次（每批帶來源事件 ID）、人類食物殘屑（只來自人類活動事件） |
  | `ant_colonies[]` | 外部蟻群：物種、巢位置、蟻后數、工蟻數、各期幼體數、繁殖蟻數、所屬超群（未知 `null`） |
  | `ledger[taxon][stage]` | 當日 B、D、I、E 四本帳，加上期初、期末 |
  | `carrying_capacity_basis` | 每類群的承載上限依據（資源或空間）；不得是常數「無限」 |
- **外緣邊界條件**（斑塊網的最外圈）只有兩個合法選項：
  1. **封閉**：外緣不進不出（對照組）；
  2. **區域池 R0**：一個粗尺度、**有限**的「都市背景」單元，有自己的 B／D／I／E 帳與承載上限，和最外圈斑塊交換個體。**R0 本身的外緣是封閉的**：R0 只因自己的出生、死亡，以及與最外圈斑塊成對的移入、移出而改變；沒有任何從 R0 以外來的流入。
  - **禁止**「固定密度、無限供應」的外緣（數學上的 Dirichlet 邊界）：它等於無限族群。
  - 封閉、反射、吸收、週期等邊界條件的分類是一般建模慣例。我**沒有讀到**一篇專門以原文支持此分類的 IBM 方法文獻（R339 Berec 2002 只核對了書目），所以這裡不引用數字或原文。

### c.5 越界時的升級與降級（保持身分與帳）
**基本規則**：個體的身分（ID）一旦建立就永不重用、永不消失；只能改變「所在區域」與「表示層級」。

1. **升級（promotion，第 2 層 → 第 1 層）**：
   1. 來源斑塊該類群、該齡期的計數必須 ≥ 要升級的數量，否則事件無效；
   2. 計數減少，記在來源斑塊的 **E** 帳；花園的 **I** 帳增加；
   3. 若來源斑塊的「已知身分名冊」（見第 3 點）中有該類群、該齡期仍存活的成員，優先取用其 ID（以具名亂數流抽選，不依陣列順序）；否則建立新 ID，前綴標明來源斑塊，例如 `X-H02-aphid-000123`；
   4. 新個體的初始狀態只能取自來源斑塊已記錄的狀態（齡期、年齡類別）；未記錄的生理量是 `null` 或物種預設值，並標 `assumption: true`；
   5. 若個體攜帶食物（例如外部蟻群覓食者回程、或主蟻群工蟻從外面回來），食物以 `food_transfer` 事件從來源區室轉入該個體的嗉囊或顎間區室，不得憑空出現。
2. **降級（demotion，第 1 層 → 第 2 層）**：只適用於「生命史已不再與花園相連」的生物，例如飛走的蛾、離開的外部蟻群覓食者、婚飛後飛出的 gyne。**主蟻群仍屬蟻群的個體不降級**（§c.2）。
   1. 個體離開花園，記花園 **E**、目的斑塊 **I**；
   2. 目的斑塊對應齡期的計數加一；
   3. 個體的 ID 與離開時的狀態快照寫入目的斑塊的**已知身分名冊**（`known_individuals`）；
   4. 之後斑塊層的死亡若落在該齡期，以具名亂數流決定是否落在名冊成員身上；被抽中的成員標記死亡，死因寫「斑塊層死亡（群組層級）」；
   5. 名冊成員再次進入花園時，沿用原 ID。
3. **不變量**：任一時刻，一個 ID 只在一個區域的一種表示中（花園個體、某斑塊名冊、或已死亡）；計數與名冊一致（名冊人數 ≤ 該齡期計數）。
4. **方法依據**：用「代表多個個體的群組個體」（super-individual）處理大族群是已有的建模做法（Scheffer et al. 1995，R340，**只核對書目**）；本文件的升級／降級規則是為本專案提出的候選設計（C），沒有文獻驗證。

| I11 | **順序無關**：同一時刻的事件處理順序不取決於陣列位置（§e） |
| I12 | **食物配對**：`resource_export`／`resource_import` 與 `food_transfer` 一對一，帳完全相等 |
| I13 | **身分永久**：ID 不重用；`retired`（死亡）後不得再出現 |

## (e) 共用的世界事件時間軸與多群共享資源

### e.1 一條時間軸
- 全世界只有一條事件佇列：天氣事件（下雨開始、停止）、斑塊過程、越界事件、所有蟻群的個體事件，都依 `(時間, 階段, 正規化鍵)` 排序。
- **正規化鍵**不得是陣列索引。建議用事件內容推得的穩定鍵（例如 `(region_id, taxon_id, 個體 ID)` 的字典序），並以排列測試證明結果與儲存順序無關（I11）。
- 這是 `docs/multi-colony-timeline.md` 方案 A 的延伸：該原型已證明「依蟻群陣列順序」會讓排前面的蟻群在 20 個種子中 15～19 次帶回較多食物（同一份文件 §1），並示範了以時間窗處理同時抵達。

### e.2 同時發生的爭用
- 同一地點、同一時間窗內，所有個體（不論屬於哪個蟻群或哪一層）對同一份資源的取用組成一個時間窗。
- 在有本種競爭行為的數值證據之前，沿用原型的**中性按比例分配**（最大餘數法）。這不是生物學主張，只是避免程式順序得利（multi-colony-timeline §3）。
- 驅離與攻擊的方向有本種證據（R135 只讀摘要；R173；R132），但沒有可用數值。實作時物種參數標 `assumption: true`，數值是遊戲假設。

### e.3 第 2 層的更新也必須與順序無關
- 斑塊之間的擴散量一律用**同一步開始時的狀態**計算（同步更新、雙緩衝），再一起套用；不得一個斑塊更新完再用它的新狀態算下一個斑塊。
- 若多個流向同時要求同一來源的個體，而來源不足，按比例縮減，餘數以具名亂數流處理。
- 測試：打亂斑塊順序與類群順序，輸出逐位元組相同。

### e.4 與 Issue #56 的關係
- Issue #56（open，P2）指出：只改 `population.workers` 的儲存順序，就會改變誰接觸誰、交哺給誰，最後人口軌跡不同（審查者探針：A1 春 seed 3 第 90 日 8 隻 vs 5 隻工蟻）。
- 開放生態會把同樣的問題放大到「誰先越界、誰先取得外部資源」。因此：
  - **任何外部蟻群的個體進入花園之前**，A09（多群陣列順序）與 #56（工蟻陣列順序）的修正必須先完成；
  - 驗收沿用 `tests/issue50-brood-order.test.ts` 的形式：依 ID 正規化後的排列不變量。

### e.5 取代固定比例的背景蟻群
- `background_colonies.F04_rival` 的 22% 固定比例要移除，改成第 2 層的外部蟻群：
  - 它有自己的巢、工蟻數、資源；
  - 它的覓食者經過越界門進入花園，升級為暫時個體，在同一條時間軸上取用 F04；
  - 出發率只依該外部蟻群自己的狀態、所在斑塊的資源與天氣，**不讀主蟻群**；數值沒有證據，是 D。
- **兩者不得並存**，否則同一份蜜露會被扣兩次（multi-colony-timeline §4 已提醒）。

  2. 其他物種要等各自的參數檔。

## (f) 外部族群動態：各類群的候選模型與證據等級

> 共同規則：
> - 所有過程只讀天氣、棲地、該類群自己的狀態與所在斑塊的資源；
> - 與螞蟻的交互作用只能經由實際發生的局部接觸（例如在場照護、捕食事件）；
> - 所有速率在沒有本地資料時是 D，並以多組情境比較，不為結果調參（CLAUDE.md §7）。
> - 模型骨架（B／D／I／E 分帳、源—匯、斑塊網）是建模方法（Pulliam 1988 R333；Thomas & Kunin 1999 R334；Hanski 1998 R335；Levins 1969 R336），不是螞蟻量測。
>   - Pulliam 1988（摘要）：源棲地的繁殖剩餘可以維持匯棲地的族群，因此某地看到的物種組合可能受鄰近棲地的種類與距離影響，程度不亞於當地條件。這正是「花園不是封閉容器」的理由：花園裡某類群存在，不代表花園自己養得活牠。
>   - Thomas & Kunin 1999（摘要）：把每個區域放在兩條軸上：「補償軸」（源：B>D、E>I；匯：B<D、E<I）與「移動軸」（區域族群受 I＋E 主導，或受 B＋D 主導）。四本帳分開記，才能事後判斷花園是源還是匯；這是本文件 O6 的方法依據。
> - **擴散核**：Kot et al. 1996（R337，摘要）指出，擴張速度對擴散核的形狀，尤其是尾部，極為敏感；肥尾的核可以產生加速擴張。因此：
>   - 沒有本種距離資料時，不得只選一種核就報告擴散速度；至少並列薄尾與肥尾兩組；
>   - 擴散核的分類與寫法另見 Nathan et al. 2012（R338，**只核對書目**）。

- Liu et al. 2022（R141）的「島嶼尺度跳躍擴散」是**數十年、全島**的歷史推論，**不得**換算成每日起飛機率或每日長距離落點機率。它在本模型中的用途只有兩個：
  1. 支持「人為搬運」作為一種存在的越界方式（情境事件，頻率 `null`）；
  2. 作為驗證時的負面檢查：模型若在數年內產生大量自然長距離擴散，要調查原因，不是當作符合。
- R153、R154 的擴散速率是**族群前緣**的長期量，不得換算成單一巢每日分巢機率。

## 附：ODD 的寫法建議
- Grimm et al. 2020（R330，全文）建議：子模型本身超過約 10 頁時寫成「巢狀 ODD」，只重寫目的與型態、過程與排程、子模型三節；混合模型要在「子模型」一節加一小節，說明各子模型在什麼框架下耦合、何時互動、透過哪些變數與過程交換資料與同步（作者稱為子模型之間的 "hooks"）。
- 因此建議把本層寫成 `docs/odd-protocol.md` 的一個巢狀 ODD，並在其中新增「第 1 層／第 2 層／第 3 層耦合」小節，列出：升級與降級規則、帳的對應、時間同步方式（同一事件佇列）、以及每一個交換變數。

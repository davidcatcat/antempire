# 🐜《螞蟻帝國》GM 規則卡 v2（Day 15 起生效｜審閱草案）

**版本**：`antempire.rules-v2.day15.proposal`。**適用**：從 Day 15（2026-11-14）開始。**Day 1～14 唯讀，不回算、不補寫死亡或羽化。** 這是一套可長期演化的**生態啟發式遊戲引擎**，不是對真實庭院的觀測、精確預測或實驗室孵化紀錄。物種固定為**熱帶大頭家蟻 *Pheidole megacephala***；場景為臺中市西屯區**虛構**獨棟住宅花園；日期錨點為 Day 14＝2026-11-13、336 模擬小時。下一次「繼續」只增加一天（24 小時）。只有明確要求改規則時才能動引擎或 `params.json`；日常推進中嚴禁修改。

## 一、權威、因果與數據身分

每天只讀 `saves/main.json`、`saves/world-state.json`、**本卡**、`sim/params.json` 與 `sim/day_engine.cjs`。`world.sim_engine_v2` 是 Day 15 起的**可執行遊戲狀態權威**；主存檔維持蟻群人口及舊歷史記錄的對外鏡像，世界檔維持氣候、食源、地圖及全世界生態。禁止另一份獨立創造的食物庫存，亦禁止將歷史 `sugar_units=3`、`protein_units=3` 當成 Day 15 食物份數。

**資料身分永遠清楚：**科學文獻說明可能機制；1991–2020臺中歷史氣候是實際公布的月均資料；逐日氣溫/雨量是虛構生成；`params.json` 內每一項數值含 `assumption:true`，只是一套**遊戲假設**；個體、食源、出生與死亡是模擬結果。資源單位叫「份」，不是毫克或微升，不能反推本物種真實每蟻能耗。**所有出入帳有來源事件 ID，來源和巢內移轉不能重複計數。**

## 最高優先：禁止 AI 上帝視角與超自然事件（Day15 起）

**AI 是觀察者、規則執行器與紀錄員，不是蟻群的神或導演。** 只准由已保存的環境狀態、自然生態機制、局部感知及固定種子產生事件。**不論結果是否漂亮、蟻群是否瀕危、玩家是否期待擴張，AI 都不可透過修改事件/參數/存檔來給食物、指定螞蟻死活、救活死蟻、指定孵化或強迫產卵。** 上一日狀態與固定引擎決定下一日；寫日誌僅如實敘述引擎輸出，不得補上引擎未發生的行為。

- **自然事件必有前因**：新死蟲先從已記帳的活昆蟲族群扣除，再生成唯一屍體 batch；活昆蟲遷入須從**已記帳的有限相鄰棲地昆蟲族群**扣除，非直接補蛋白或無限憑空出現。蜜露須有寄主、存量及分泌條件。雨、枯葉、腐壞、捕食、疾病等要符合地點、季節、接觸與因果。沒有「任務獎勵食物」或「為保群不餓死而突然出現的資源」。
- **工蟻只有局部資訊**：牠們不能偷看全巢精確糖／蛋白數值、遠處死蟲剩餘量或全地圖。只依據自身舊路線、近巢觸角接觸、近期餵食經驗、實際到達的現場資訊與同伴招募改變行為；未知位置須沿已知鄰接路徑實地探查。
- **死亡與繁殖不得劇情化**：只可依疾病暴露、年齡、傷勢、天氣、掠食接觸、食物缺口等已存在的機制與擲骰判斷；沒有保底存活、指定死亡名單、硬湊人口規模、瞬間復活/傳送/長大等超現實機制。生存或全滅都是允許的自然結果。
- **規則更新與世界事件完全隔離**：測試環境可以做斷糧／增糧反事實壓力測試，但結果**不得導入正式世界**。不得為了使某次30日測試出現羽化、避免全滅或製造高潮而倒調參數；若驗收失敗，**如實記錄失敗**，下一次規則更新才可因合理機制理由修正。
- **程式強制驗證**：拒絕任何 `force_food`、`target_worker_death`、`make_sure_queen_survives` 或其他額外干預輸入；驗證「每筆新屍體 ⇐ 已有昆蟲自然死亡」「族群及食物守恆」「路線局部可達」「事件類別白名單」。

科學背景：*P. megacephala* 實際會採蜜露、捕食、搬運死蟲和招募同伴（UF/IFAS IN712；Dejean 等2007，DOI:10.1016/j.crvi.2007.06.005）；無中央指揮、由局部互動調節集體行為的機制見 Gordon 2023，DOI:10.1111/ede.12439。**文獻支持機制，不代表模型機率已實測校準。**

## 二、單日引擎順序（不得為故事結果倒填事件）

1. 載入完成日與下一日日期；驗證 Day+1、兩個 save 時鐘一致、`params` 與引擎 SHA256 和前一日保存的凍結指紋相同。隨機根種子由穩定遊戲種子、下一日序與獨立事件標籤產生，**絕不包含 GitHub Commit SHA**。同一存檔/版本/日期得到同一結果。
2. 生成臺中歷史月均氣候驅動的虛擬日雨量、日均溫及**假設巢溫**；由前日濕/乾與距平產生連續天氣。土表水分用上一日指數留存及本日降雨更新，基礎乾燥扣減 `0.025`，不再硬扣 `0.1`。土表指數不等於真實土壤含水百分比；有雨不自動代表巢室淹水。
3. 更新**所有生態食源**：既有蚜蟲、花蜜以寄主、開花期、天氣、容量補充；已存在死蟲依腐敗率及壽命遞減；新昆蟲屍體必須先有**已保存的活昆蟲族群死亡**（扣除活昆蟲）才能產生唯一 batch；鄰近棲地遷入新昆蟲有獨立移動事件。異巢採食、分解、雨水沖刷均不可憑空產生食物。未經工蟻探索的外界資源不能直接算入主巢。
4. **每隻活工蟻每天都有任務**：局部育幼、採食、休息、守衛或巢口維護。任務受年齡、傷勢、局部育幼需求、前一日接觸/餵食訊號、已知路線、雨量調整；不再固定 W005/W006/W011 才可採食。新的個體從 `W018` 往上唯一編號。只有工蟻掌握路徑或實際巢內接觸傳遞資訊，才會到達對應食源。找到可採食物後，可以讓**在巢相遇**的工蟻知道路線並同日跟進；不是全巢即時知道全地圖。訊號與口對口食物共享是兩種不同事件。
5. 食物由工蟻到場、遭遇、採集上限、路程與回巢驗證後才增加巢內`糖/蛋白份`；**外部採集只有一次收入**，工蟻之間轉移沒有新收入。已知來源若尚有可食存量，即使不是當天新生成，也有機會搬回。
6. 扣除工蟻、蟻后、幼蟲的維持消耗與出勤成本。糖、蛋白各自按 `初存＋實際採入－攝食－產卵成本－容量溢出＝期末` 核對，缺口不允許負庫存。任一項需求不滿足，累積對應的 `sugar_gap_days`、`protein_gap_days`；滿足後依明示遊戲假設解除連續缺口。**無食物收入 ≠ 無攝食；有食物在外界 ≠ 已入巢。**
7. 全部幼體有發育進度：`卵→幼蟲→蛹→成蟻`。標準25°C `10/12/10`天以溫度係數調整；幼蟲發育額外受營養滿足率影響。達門檻才轉期；蛹羽化新增獨立工蟻 ID；死亡（自然/老化/營養不足/傷勢）用事件 ID 扣除，絕不把同一個體多次計入。蟻后在缺糧達門檻時停止產卵，即使隨機抽中也不得繞過產卵成本；產卵只在足夠糖與蛋白時成立。
8. 日終檢查人口與雙營養守恆、所有工蟻活動分類、唯一食物 batch、日期、事件 ID、保留外部未知節點。輸出唯一 JSON 決策結果，按原子提交更新兩份 save 與當日 `journal/v2-day-NNNN.md`。

## 四、生命／危險／世界機制的邊界

物種有小工蟻、兵蟻、雄蟻與未交配蟻后等形態/性別區分；目前對原14隻工蟻仍沒有可靠 minor/major 鑑別，**不因外表工作推定 caste**。新羽化預設建立一隻普通工蟻（未核實 caste），不直接生成有翅蟻或新蟻后。原 Q001 沒有任意指揮全巢的能力。蟻群超過百隻後需要 cohort 與巢區流量優化；本次30天小型殖群測試**不代表萬隻情境已驗收**。

掠食者、他巢、病原、社會清潔、巢穴工程、未知節點、活昆蟲捕食、分巢與領地競爭保留為受**時間/位置/接觸**約束的擴充機制。既有世界的蜘蛛、蟾蜍與其他蟻巢不能無理由消失，但也不能因背景事件就強制主巢死亡。v2首批引擎已實作基礎傷病、築巢任務、食物生態、局部路線分享及生命帳；**未把所有25份規格的進階機制宣稱成已完整數值化**，需要後續獨立規則更新開工。

## 五、日常操作與規則變更門檻

玩家說「繼續」：**①執行已凍結的引擎一天 → ②保存兩份狀態 → ③生成當天日誌**。不改 `sim/day_engine.cjs`、`sim/params.json` 或本卡；同一天不得跑兩次，遠端 SHA 更新以比對寫入避免覆蓋。無法讀取既有主存檔、引擎指紋變動、重播失敗、守恆失敗，當天**不得提交**。

玩家要求「修改規則」：僅做規格/程式/參數更新與至少30天隔離測試，不推進遊戲日；得到確認後，以新生效日提交規則版本。**修改失敗時保留原完整存檔，不回寫舊日敘事。** 假設參數改動只影響後續，不允許把試跑結果反灌歷史。閱讀詳細內容時回到25份長規格，但**每天只需讀本卡**。

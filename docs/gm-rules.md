# 《螞蟻帝國》GM 規則卡 v2.1 — 自然生態校準審閱草案

**狀態：PR 待審，未合併、未正式推進。** 本規則預定自 Day15 起適用；Day1～14 的故事、存檔與日誌保持原樣。唯一正式起點仍是 Day14、336 小時，台中市西屯區的虛構庭院，物種 *Pheidole megacephala*。所有「份／日」數值、行為機率、危險率、寄主植物與半翅目族群初始數目均為遊戲假設（`assumption:true`），**不是文獻實測值**。氣候根據臺中1991～2020歷史月均生成虛擬日天氣，絕非2026年11月特定日的觀測。日常只讀本規則卡、引擎、參數及兩份權威存檔。

## 1. 不得干預生態、不用總帳指揮個體

AI 只是規則執行器及觀察者，**不准**為達成「要活」「要死」「要通過測試」「要有劇情」目標，修改食物、出生、死亡、雨量、隨機種子或個體狀態。不能突然刷新死蟲、死而復生、賜予全地圖知識、指定誰生誰死。任何事件都必須由既有環境、局部接觸和固定種子決定；若驗收失敗，如實保留結果。試跑環境可進行對照，但絕不能反灌正式存檔。

**工蟻不能讀取** `colony.sugar`、`colony.protein`、總庫存可支撐天數、全域蛋白缺口、遠處尚未發現的食物量。任務選擇只依據：自身嗉囊飽足（個別餵食經歷）、真正碰到的巢友嗉囊與求食反應、搬食返回後實際卸貨快慢、育幼工蟻真正接觸到幼蟲的求食訊號、已親身走過的食源路線，以及有局部接觸來源的招募訊號。工蟻可在實際抵達食源時感知現場食物，不能在巢內遠端查庫存。沒有任何全巢倒數廣播。肉／蛋白的口糧分配與糖類嗉囊是不同生理路徑，模型以區別的局部代理訊號表示。

## 2. 環境先決定蜜露，蟻群才選擇是否採到

**花園食源產出絕不依蟻群需求反推。** Day15 一次性假設既有寄主及半翅目小群：F01 兩株寄主植物／四群蚜蟲；尚未由本巢確認的 F04 兩株／三群介殼蟲，F05 一株／兩群蚜蟲；F10 原始藏身點沒有活寄主。這些是「既存花園」的遊戲假設，**不是觀察者憑空為螞蟻增建食物點**；未經工蟻親身發現，資源不能被主巢採集。F04 的異巢競爭者會消耗部分蜜露。模擬日產量由寄主存活數、半翅目群數、每群分泌率、雨水抑制及沖刷、異巢採食獨立計算。寄主有自然死亡風險，半翅目群數有繁殖和崩潰風險；演化只依自然生態及固定種子。

花朵花蜜受開花期與雨影響；死昆蟲只會從**已保存的活昆蟲自然死亡**形成一次性帶來源 ID 的屍體，持續衰減、被採或被雨水沖刷，不能每天重生。已記帳的鄰近昆蟲遷入須同時在來源族群扣除；物質及人口不會無因生成。不同食源分屬不同地點，工蟻不能跨越未知路線瞬移或共享全知地圖。

本輪**沒有**改動 `worker_sugar_daily=0.1`、初始糖庫存 7.6／蛋白 2.3、自然死亡率、產卵基本機率。幼蟲蛋白需求由 0.2 改為 **0.08 份／幼蟲／日**，是為讓遊戲攝食尺度一致的明示假設，並非實測。蟻后在沒有照護工蟻、長期營養不足的情況下會承受額外死亡風險，不是強制殺死。

## 3. 引擎每日固定順序及守恆

1. 驗證 Day+1、單一權威狀態、引擎與參數 SHA256，並以固定遊戲種子／模擬日生成多條命名 RNG 串流（不依 GitHub commit）；生成雨量、溫度、土表保水與巢溫情境。
2. **先更新獨立花園生態**：寄主植物、半翅目族群、開花、蜜露產出／流失、昆蟲背景死亡／遷入及屍體腐敗，僅記錄自然來源，不察看巢內糖／蛋白。資源只加入其原本存在的自然地點。
3. 每隻存活工蟻依個體局部經驗選擇覓食、育幼、休息、巢口修護或守衛；接觸後可分享一條路線或交換食物，育幼工蟻可實際接觸幼蟲求食；成功覓食可就地招募。覓食可因雨水、傷勢、自己的飢餓、同伴卸貨回饋減少或增加，不能因 GM 發現全巢存糧不足而直接指派。
4. 只有到場且成功搬回的食物才算巢內**外部收入**，被工蟻轉手分食不可重複入帳。逐日計算 `期初+成功收入−實際攝食−產卵成本−儲存容量溢出=期末`，糖與蛋白分開核對，不得負庫存。所得／消耗／存量同時寫入每日日誌；「沒有新收入」不等於「完全沒有吃」。
5. 卵→幼蟲→蛹→工蟻依25°C參考期 `10／12／10天`，再依巢溫與幼蟲實際獲食速度發育；羽化必須有真的蛹，唯一工蟻 ID，絕不可提前湊成果。個體自然死亡/傷勢/飢餓危險率透過引擎抽樣；沒有工蟻照護且長期斷糧的蟻后危險率上升；不能強制存活或強制死亡。
6. 驗證所有工蟻有一項任務、人口與營養守恆、食源 batch 的死亡前因、雨天事件、唯一編號、日序和 RNG 重播。任一檢查失敗：**不得提交日誌或存檔**。

## 4. Day15 一次性遷移、日常三步、規則更新

Day14 權威已知卵：E001／E002／E003／E004／E005 分別經過 **12／6／6／5／1 天**；用25°C等效發育進度作過渡假設，不回寫舊日誌。L001、L002 未知幼齡假設各完成幼蟲期50%；舊工蟻未知成年日齡假設7天，六舊傷保留。巢內初始7.6份糖、2.3份蛋白不由舊「抽象糖3點」換算。F07 Day11新死蟲、F07 Day10舊死蟲、F11 Day9死蟲各保存原始來源ID及明示假設的剩餘量。新寄主/蚜蟲初始數量列在遷移日誌，主巢並不預先知道 F04/F05。

日常玩家說「繼續」：**①執行凍結的單日程式→②更新兩份權威存檔→③寫入當天日誌**；禁止當日途中修改引擎或調參，禁止 Day 重複執行。玩家說「規則更新」：在獨立分支／審閱資料夾修改引擎、參數和規則卡，跑60日及極端情境，保留失敗證據，待確認才提交；不動 Day14 或過去歷史。

驗收中「60日工蟻至少70%、L001/L002羽化、Day30前產卵、新卵完成生命週期」**只是診斷指標，不是規則目標**。不能為了通過而反向調參；保留不同 RNG 種子的反例、未達成的生理事件及營養瓶頸。所有數字都是遊戲假設。

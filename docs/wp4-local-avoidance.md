# WP4：局部避障與讓路——候選行為模型隔離比較

> **地位**：隔離物理實驗・候選行為規則（非本種/假設）。`engine/physics/local-steer.ts` 不被每日生態循環、Day0、`cli/`、`web/` 引用（`tests/physics-isolation.test.ts`、`tests/wp4-local-steer.test.ts`）；`engine/physics/solver2d.ts`（PH-3b）沒有任何修改；沒有推進遊戲日、沒有改存檔或日誌。所有情境都是合成世界（`synthetic: true`）。
> **不宣稱**：大頭家蟻屬沒有任何窄道交通、迎面相遇、讓路或側移研究（見 `scenarios/physics/pheidole-megacephala.interaction-candidates.json`）。下列候選都**不是本種行為**，比較結果只說明「若螞蟻這樣決策，物理上會發生什麼」。抵達率**不是**選擇標準；由 Owner 決定。

## 1. 候選

| id | 名稱 | 規則（只用局部訊號） |
|---|---|---|
| `none` | 基準 | 直接呼叫 PH-3b `solve2D`，輸出原樣（u 固定、沒有決策）。測試確認與 PH-3b 逐項相同 |
| `A_free_direction` | A：選擇可通行方向 | 每個決策時刻，在候選方向（0、±15…±90°）中挑「感知半徑內走得通」且最朝前的方向；左右都通時以命名亂數決定；都不通就等。無記憶，不後退 |
| `B_contact_decision` | B：接觸後等／退／繞 | 前方沒有阻擋就前進；同向同伴在前就跟隨；碰到（感知到）擋路的同伴時，抽一次：等待 `wait_s`、後退 `back_distance_mm`、或繞行（最多 `reroute_max_s`）；靜態障礙物一律繞行 |
| `C_sidestep` | C：有空間就側移錯身 | 前方被擋且旁邊有空間時，選一側（命名亂數，整個相遇維持同一側，該側封閉才換邊）斜向／側向平移，直到前方通了；沒有空間就等；同向同伴在前就跟隨 |
| `N_no_yield` | N：不讓路**對照**（不是候選） | 永遠直走，從不等待、讓路、後退或側移；前方有身體就非彈性停下到下一個決策時刻。大頭家蟻沒有任何讓路文獻，這是「什麼行為都不加」的對照，與 A–C 共用決策網格、物理、規則 D 與對照情境的入口／出口規則（PH-3b `none` 不支援入口／出口，所以另設 N）。沒有亂數抽取：各種子結果相同（測試確認） |
| 規則 D（A–C、N 共用） | 幾何不可通過：停下或回報 | 在 `stall_window_s` 內前進 < `stall_progress_mm` 就發出 `blocked_report`，附局部診斷：`too_narrow_for_two`（兩側牆都在感知範圍內、局部寬度 < 兩隻寬度和）、`blocked_by_nestmates`、`static_ahead`、`way_ahead_free`（停是自己的等待／後退）、`static_closed`（靜態幾何封閉所有方向 → 永久停下）。B 在 `too_narrow_for_two` 時不繞行 |

**不預設**靠左／靠右，也不預設一定有一方讓路：左右由每隻自己的命名亂數決定；B 兩隻各自獨立抽，可能都等、都退或都繞。

## 2. 共同設定

- **感知（局部）**：只看自己身體間距 ≤ 感知半徑的身體（膠囊與身體軸方向；**不含**對方速度、目標或意圖）與靜態幾何（牆、障礙物），以及身體接觸。「方向 d 走得通」＝把自己的膠囊沿 d 平移一個感知半徑，對**原地不動**的已感知身體與牆做精確連續碰撞，沒有碰到。沒有全圖、沒有群體量。
- **決策時刻**：共同網格 k·`decision_interval_s`（以十進位精確計算，見 §2b；加上各自的出發時刻，以及入口規則下各自的入場時刻）。決策只讀該時刻的狀態與命名亂數（種子、規則、個體 id、決策序號），與陣列順序無關。
- **物理**：沿用 PH-3b 的膠囊（體長 2.5 mm：R94 文獻支持；碰撞寬 0.8 mm：候選上限，遊戲假設）與精確連續碰撞（`pairFirstHit`）。兩個決策時刻之間每隻直線等速平移；遇到靜態幾何、目標或另一身體（**朝對方移動**的那隻，法向判斷）就在接觸時刻停下，Jacobi 反覆到停止時刻不再改變（與順序無關）；不收斂就該區間全員不動（安全退路，計數 `fallback_intervals`）。已接觸、相對速度極小的滑動以 `boundedHit` 判斷「本區間內是否真的穿透超過 1e-10 mm」，避免把無限遠的穿透當成立即碰撞。
- **抵達與時間終點（與 PH-3b 一致）**：PH-3b 處理所有 t ≤ `horizon_s` 的事件，所以抵達的定義是「前進座標到達目標的第一個時刻 t ≤ 終點」，只記一次：區間內、恰在決策區間終點（含恰在時間終點）、或出發時就在目標上（剩餘距離 0，於出發時刻抵達）都算；超過終點才到達則不算。時間終點本身也是一個處理時刻（長度 0，不做決策、不移動）：先套用對照情境的出口與入口規則，再讓出發時刻恰等於 `horizon_s` 的個體出發（與 PH-3b 相同記 `start`），若出發時已在目標上就在終點時刻抵達一次（`final_mode` = `arrived`）；未在目標上的個體最終狀態記 `started_at_horizon`（PH-3b 記 `moving`，但候選在終點沒有決策，所以沒有速度）。出發時刻 > 終點則不出發。（R15 修正 Codex：原本出發即在目的地、出發時刻恰等於終點時漏記出發與抵達。）入口規則的重試（預定時刻入口被占時）包含終點；出口規則在終點也會執行。區間終點的判斷容許 `GOAL_TOL_MM` = 1e-12 mm 的浮點捨入（區間內運動仍是一般浮點）。（R13-05 修正：原本恰在區間終點到達時永遠漏記。）
- **接觸的開始與結束**：接觸在某隻被另一身體擋停、且停下時刻兩者間距 ≤ `CONTACT_TOL_MM`（= PH-3b `ACTIVE_TOL_MM` = 1e-7 mm）時開始。接觸結束＝間距**第一次超過** `CONTACT_TOL_MM` 的時刻，由兩隻在**實際運動**（分段等速；決策區間不是時間解析度）上精確求解：每一段上間距對時間是凸函數，找到第一個終點間距 > 容差的段後二分到浮點解析度；事件附 `bracket_s` [lo, hi]（lo 時間距 ≤ 容差、hi 時 > 容差，記錄時刻＝hi）。結束時刻不會早於拉開間距的那段運動開始，也不是決策區間的起點（R13-06）。另有獨立程式重算並給誤差界（§6.1）。
- **`contact_end_estimated`**：只有對照情境的出口會產生——某隻因出口規則**離開道路**（被移出物理平面），它的接觸在離開的決策時刻結束。這不是物理分離，事件標 `usable_as_cause: false`，**不能**當作任何生物原因（例如「被碰後離開」）；沒有出口的情境中一律 0 個（測試確認）。
- **保守停止（R13 留下的 C 項，已修）**：Jacobi 停止時刻是依對方「原本計畫」的路徑算出的；若對方自己更早停下，兩者在停下時刻其實沒碰到（間距 > 容差）。這種停止現在記為 `conservative stop: the planned path of X would be hit, but X stopped earlier (gap … mm; no contact)`，計入 `stats.stops_conservative`，**不再**寫成「contact with X would penetrate」，也不計入 `stops_contact`、不開接觸。測試逐一確認：寫「contact with」的停止確實接觸、寫 conservative 的確實沒接觸。100 隻交叉口種子 1：A 14、B 15、C 16、N 148 次保守停止。
- **對照情境的邊界規則（`input.control`，預設關閉；情境假設，不是螞蟻行為）**：`spawn`＝個體在進場前不在路上（不被感知、不是障礙物），若入口姿態空著（與所有在路上的身體間距 > 容差）就**恰在排定時刻**進場（不對齊決策網格），被占則在之後第一個空著的網格時刻（或終點）進場，同時刻以排定時刻、再以 id 決定順序；`exit`＝抵達的個體在其目標端（通道×方向）出口未滿時，於下一個網格時刻（或終點）離開道路，每隻占用出口 `dwell_s`；出口滿了就留在目標處當障礙物。同一決策時刻先處理出口、再處理入口。
- **幾何約定（遊戲假設）**：身體軸維持與通道平行；選的方向是平移（前、斜、側、後），速度＝自由速度。**身體只平移、不轉向**（不建模轉身）。只處理直線通道（有轉折的通道拒絕）。通道兩端也當牆（候選可以後退）。抵達的個體留在原地成為障礙物（與 PH-3b 相同），除非對照情境開了出口。

## 2b. 時間契約（Owner 統一的物理事件時間邊界）

依 Owner 的統一契約，並以已核准的分層時間契約（`docs/p0a0-time-contract.md`、`engine/scheduler/time-contract.ts`、`world-events.ts`）為整合方向。排程器只把**完全相同**的精確時刻視為同時，「同一時刻」由生產者決定；本節就是 local-steer 這個生產者的規則。不為畫面 FPS 改變任何事件時刻。

1. **控制時刻精確**：輸入中的控制時刻（排定出發／入場、決策間隔、出口占用 `dwell_s`、B 的 `wait_s`／`reroute_max_s`、卡住視窗、終點）以其**最短十進位表示**（即 JSON 輸入檔寫的數）為準。網格時刻 g_k = k·`decision_interval_s` 以整數 k 乘十進位值、只捨入一次（`engine/physics/exact-time.ts`）：k = 3、間隔 0.1 時 g₃ = 0.3，不是浮點乘積 3 × 0.1 = 0.30000000000000004，也不累加。占用期滿（0.1 + 0.2 = 0.3）等加總與比較都在十進位上精確進行，沒有容許值。浮點捨入不會把排定事件延後到下一個時刻。區間內的運動時刻（接觸、停止、抵達）仍是一般浮點。
2. **入場不對齊網格**：排定時刻 t 的個體若入口空著，就**恰在 t** 入場並記 `start`（時間線上插入 t）；它在入場時刻做**第一次決策**（只讀該時刻的局部狀態），之後跟隨共同網格。其他個體在入場時刻**不做決策**，維持原決策（被擋停者維持停止到下一個網格時刻）。曾考慮的另兩種作法：「延到下一個網格才入場」會延後排定事件（違反第 1 點）；「入場後先直走或原地等到下一個網格」是沒有根據的行為。入場時刻即決策時刻是本模型的**遊戲假設**（`assumption: true`；本種沒有入場行為資料）。決策的命名亂數鍵在網格時刻是 k，在入場時刻是「前一個網格序號|entry」，與處理順序無關。入口被占時，只在之後的網格時刻與終點重試（不在別隻的入場時刻重試，保持局部性）。出口只在網格時刻與終點處理。
3. **終點是一個時刻**：終點 H 可以處理事件，但沒有正長度的時間可移動。H 上的合法事件依共同排程的批次與因果順序：先出口、再入口，再讓出發時刻＝H 的個體記 `start`（只記一次），在目標上者於 H 抵達一次；恰在 H 到達目標者於 H 抵達一次。H 之後沒有任何事件或紀錄。
4. **H 出發不位移**：出發時刻＝H 的個體可以記 `start`，但經過時間為 0，**不得位移**，也不做決策。
5. **`final_mode` 的跨模組定義**：`final_mode` 描述**處理完 H 上所有事件之後**的狀態。
   - `started_at_horizon`＝恰在 H 出發、不在目標上、經過時間 0（`final_speed_mm_s` = 0，沒有發生任何運動）；
   - `moving`＝在一段結束於 H、長度為正的區間內移動過，且在 H 的速度 > 0；
   - 其餘（`arrived`、`exited`、`not_started`、`not_entered`、停止類）不變。
   local-steer 已實作。**PH-3b（`solver2d.ts`）目前對 H 出發的個體仍記 `moving`、速度＝自由速度**——這是待修項目，由另一個以 main 為基礎的 PR 修正（本分支不改 `solver2d.ts`）。PH-3b 需要的改變：出發時刻＝H 且未抵達的個體，`final_mode` 改為 `started_at_horizon`、`final_speed_mm_s` 改為 0（樣本與事件不變）。`tests/physics-time-contract-wp4.test.ts` 把這個差異**明確釘住**為已知待修：PH-3b 修好時該檢查會失敗，屆時移除 `pending` 項目即可（`none` 就是 PH-3b，同樣釘住）。

**測試**：`tests/lib/physics-time-contract-wp4.ts` 是不依賴解算器的契約檢查（以 adapter 傳入解算器）；`tests/physics-time-contract-wp4.test.ts`（BLOCKING）套用到 PH-3b 與 local-steer 全部策略（不含／含入口規則、決策間隔 0.1 與 0.05 s）：排定 0.3 恰在 0.3 出發／入場、0.25 恰在 0.25、0.1 + 0.2 與 0.3 是兩個不同時刻、同時排定者同一時刻；決策事件都在精確網格或自己的出發時刻；終點語意（H 出發不位移、在目標上於 H 抵達一次、恰在 H 到達、H 之後無紀錄）；重跑、反序、打亂輸入逐位元相同。另有 local-steer 專屬檢查：出口占用 0.1 + 0.2 恰在 0.3 釋出、入口被占時恰在網格 0.3 入場、網格之間入場時在入場時刻做第一次決策、網格 k = 0…5000 與十進位乘積逐位元相同。修正前的引擎在入口規則下有 34 項失敗（例：排定 0.3、0.25 都在 0.30000000000000004 入場）。這個 helper 與另一分支的 `tests/lib/physics-time-contract.ts`（PH-3b）合併後應統一為一個。

## 6. 驗證

### 6.1 接觸結束時刻的獨立重算（R14-A）

`prototypes/local-steer/contact-check.ts` 是**另寫的程式**：不匯入 `engine/` 或執行器，自己算膠囊距離、自己查姿態、自己二分；只讀匯出的分段運動（每段兩端的精確姿態，與播放檔相同）和事件表。

- **方法**：在兩隻的共同分段上兩者都是等速平移，間距（兩個平移凸集的距離）對時間是凸函數：兩端 ≤ θ 的段整段 ≤ θ；第一個終點 > θ 的段上交叉唯一，二分到浮點解析度。間距的計算誤差上限取 δ = `DELTA_G_MM` = 1e-9 mm（容差的 1%；數值選擇）。對 θ− = 容差 − δ 求下界 lo（之前精確間距 ≤ 容差）、對 θ+ = 容差 + δ 求上界 hi（hi 時精確間距 > 容差），實際分離時刻必在 [lo, hi] 內；**誤差界** `err_s` = hi − lo（秒）。
- **判定**：每個 `contact_end` 必須落在 [lo, hi]；解算器自己的 `bracket_s` 必須與之相容；未結束的接觸到時間終點（或任一方離開道路）都不能有可括出的分離；`contact_end_estimated` 必須恰在某一方離開道路的時刻、之前沒有可括出的分離，並標為不能當生物原因。
- **結果**：A、B、C、N 在 8 個播放情境、100 隻交叉口、對照 K0–K3、決策間隔 0.025／0.05／0.1 s 的所有執行：**0 個結束時刻落在區間外**，0 個漏記或錯標。最大誤差界 2.4e-7 s（發生在兩隻以極小相對速度分開的接觸：δ／分離速率）；測試中 608 個精確結束全部在區間內。誤差界記在每個播放檔 `contact_end` 事件的 `check_s`、`err_s`，以及 `contact_end_check` 摘要；`compare.json`、`controls-*.json`、`convergence.json` 每列也有。
- **δ 的敏感度（如實記錄）**：δ = 1e-12 mm 時同樣 0 違規（誤差界約小 1000 倍）；δ = 1e-14 mm 或 0 時出現區間外（100 隻 A 201 個）——解算器內部逐區間累加的位置與匯出紀錄線性內插之間有約 1e-13 mm 的捨入差，所以 δ 必須涵蓋它。
- **估計結束**：沒有出口的情境 0 個；有出口的對照中出現的每一個都通過上述判定（§5b 第 4 點）。
- **PH-3b（`none`）的接觸結束不是同一個定義**：用同一檢查器檢查 PH-3b，結束時刻多數落在區間內但區間很寬（滑動接觸的分段近似，誤差界達 0.033 s），且 100 隻交叉口有 8 個 `contact_end` 之前找不到可括出的分離。這是 PH-3b 的接觸釋放規則（每次間距打開 1e-7 mm 就重解的滑動近似），`solver2d.ts` 依規定不改；記為開放問題（§7）。

## 7. 需要本種證據或 Owner 決定

1. **本種證據（全部缺）**：大頭家蟻工蟻是否側移、讓路、後退，相遇時的反應機率與等待時間，觸角感知距離，決策頻率，轉身與倒退行走——全部 null。要能選候選，至少需要本種在窄道（< 2 體寬）與寬道迎面相遇的錄影計數（反應類別與比例），以及同向跟隨是否超車。
2. **Owner 決定**：(a) 是否接受「身體軸平行通道、側移是平移」這個幾何約定，或先做轉身／曲線行走模型；(b) 後退時撞到背後同伴的鏈狀後退要不要做（interaction-candidates 的 `chain_back_out` 是遊戲假設）；(c) 抵達的個體是否該離開通道：§5b 的出口是候選邊界規則（容量 2、停留 1 s 都是遊戲假設），要不要採用、數值依據為何；(d) 密集格狀基準只當效能／非穿透壓力測試（§4.1），交通結論改用依時間流入＋出口的情境？流入率 2 隻/s/方向沒有本種依據；(e) 候選之間比較時看哪些指標（抵達、互卡、事件數、CPU、可解釋性），本文件不做選擇。
3. **未解缺陷**：A、C 在對稱相遇（crossing）結構性互卡；1000 隻 CPU 90–170 s；同一決策網格讓所有個體同時決策（同步是數值選擇，不是觀測）；共同裁判 1000 隻未跑（只跑獨立驗證器）。
4. **R14 新增的開放問題**：(a) PH-3b（`none`）的 `contact_end` 用的是滑動近似的釋放規則，獨立檢查器量到寬區間（到 0.033 s）且 100 隻交叉口有 8 個結束之前找不到可括出的分離——PH-3b 依規定不改，是否另開 PH-3b 的接觸結束修正由 Owner 決定；(b) 接觸數與接觸時長對決策間隔敏感（§6.2），決策間隔需要本種證據或被明確定為遊戲假設；(c) 不讓路對照 N 在所有情境 0 抵達，表示此幾何下「完全不加局部反應」必然互卡——是否需要本種在交叉口的相遇錄影來決定加哪一種反應；(d) 1000 隻 N 一次約 390 s CPU。

# 競爭蟻群與蜜露：從固定比例到真實蟻群（Issue #85，Owner D7）

> **地位**：設計，不是規則更新。沒有修改引擎、參數、存檔或正式世界。
> **Owner 決定（2026-11-07，D7）**：
> - 朝真正的競爭蟻群生態模型開發。
> - 完整模型完成前，保留現行固定比例，作為**明示的比較基準**。
> - 不擅自修改正式世界。
> - 不為了提高主蟻群存活率而減少競爭者取得的資源。
> - 不預設不同蟻群相遇必然攻擊。

## 1. 現況（比較基準 B0）
- `world/xitun-garden.json` 的 `background_colonies.F04_rival.honeydew_harvest_fraction = 0.22`，屬遊戲假設。
- `engine/ecology.ts` 的 `rivalShare()` 每日先從 F04 的蜜露生產扣掉 22%。
- 問題（#85）：
  - 沒有個體、族群、時間與事件；
  - 取用量不隨季節、對手大小或本群占用改變；
  - 被拿走的量只記在 `ecological_record.rival_share_portions`。
- **B0 保留**：作為之後每個候選模型的對照組，並在報告中標明「固定比例，非蟻群活動」。

## 2. 目標模型的要求（對應 D7 第 1–7 點）
| D7 | 要求 | 引擎中的實現方式 |
|---|---|---|
| 1 | 競爭蟻群有自己的個體與族群狀態 | 世界中的第二個 `ColonyState`（多蟻群架構已存在：`tests/multi-colony.test.ts`），有自己的工蟻、幼體、蟻后與存糧 |
| 2 | 覓食由自己的個體決策與局部訊號產生 | 沿用同一套個體活動時間軸（v17）；**不讀**主蟻群或任何全域量 |
| 3 | 蜜露消耗有實際事件與來源 | `food_collected`（帶 `site`、`colony`、`worker`、來源 ID）＋ C2 食物轉移；取代 `rivalShare()` 的扣除 |
| 4 | 食物競爭考慮時間與空間 | 兩群在同一地點、同一時段的取用依實際抵達順序；剩餘量是共享的世界狀態（世界生態不依任一蟻群的需求供應） |
| 5 | 一致的世界事件時間軸 | #9 的多蟻群統一時間軸（原型 `prototypes/multi-colony-timeline`）：同一個事件佇列、固定的同時刻排序規則、與陣列順序無關（#56） |
| 6 | 族群數量、季節與資源影響競爭結果 | 競爭結果由兩群各自的人口、活動時窗、季節與蜜露生產湧現，**不設定勝負比例** |
| 7 | 不預設相遇必然攻擊 | 相遇行為是候選模型（§4），依局部化學辨識（#27）；預設**只記錄相遇事件** |

## 3. 未知與待 Owner 決定
- **競爭者是什麼物種**：世界設定沒有指定。依 CLAUDE.md §4，新蟻種需要自己的文獻與物種參數檔，不能拿本種參數直接套用。候選：
  - (a) 另一個熱帶大頭家蟻蟻群。可用本種參數，但本種在入侵地常為**單群體性**，同種不同巢之間可能不互相攻擊。這是事實問題，要查文獻。
  - (b) 臺灣常見的其他蟻種，例如 *Tapinoma melanocephalum*、*Anoplolepis gracilipes*、*Paratrechina longicornis*。都需要各自的文獻與參數檔，數值未知時保持 `null`。
- **競爭者巢的位置與距離**：現有地圖只記錄 F04 附近有對手。精確位置未知，標示為示意，**不得**為畫面捏造。
- **初始族群大小**：未知（`null`），要以情境假設明示，並做多情境敏感度分析。

## 5. 分階段計畫（每一步都是獨立 PR、預設 OFF、固定種子重播）
1. **E0 事件化的比較基準**（規則更新）：
   - `rivalShare()` 的扣除改為每日一筆有來源的 `rival_take` 事件，進入 C2 食物帳（`sink:rival_colony_F04`）；
   - 數量**完全不變**（仍是 22%），只讓它可追溯、可在觀察器顯示；
   - 開關預設 OFF，OFF 時逐位元組不變。
2. **E1 多蟻群時間軸**：把 #9 原型接入引擎（只用於實驗世界），驗證兩群的事件排序與陣列順序無關。
3. **E2 競爭者物種參數**：依 §3 的 Owner 決定建立物種檔，附文獻；查不到的保持 `null`。
4. **E3 第二蟻群的個體覓食**：先只開 E-a（只記錄相遇），比較 B0 與 E3 的蜜露取用量分布（多種子、多季節）。
5. **E4 相遇候選比較**：E-a 到 E-d 使用同一組條件，只報告差異，**不以主蟻群存活率選擇模型**。

## 6. 驗證
- **數學**：
  - 蜜露守恆（任一時段 [t₀, t₁]）：期初現存(t₀) + 生產 = 兩群取用 + 自然損失 + 期末現存(t₁)；期初現存是 t₀ 時世界狀態中已存在的蜜露，不可省略（世界第一天之前的存量也要入帳）；
  - 事件因果順序；
  - 陣列順序不變性（#56）；
  - 固定種子重播。
- **生物**：
  - 取用量隨季節與兩群人口改變，不是固定比例；
  - 沒有任何個體讀取另一群的存糧或人口；
  - 世界生態不讀任一蟻群的需求。
- **觀察**：觀察器可以顯示兩群工蟻在 F04 的取用事件與相遇事件。資料是實驗世界，要標示「非正式」。

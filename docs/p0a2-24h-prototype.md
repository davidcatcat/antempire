# P0-A2 第二階段：24 小時個體行為隔離原型（Issue #156）

> **地位**：**非正式**實驗原型。只在 Day0 實驗世界的隔離測試中執行；**不**改 `engine/*.ts`、`cli/`、`web/`、`saves/`、`journal/`，**不**在規則指紋內，**不**推進遊戲日，**不**建立正式 Day0。正式引擎的 360 分鐘活動時窗不變。
> **依據**：[`docs/p0a2-24h-behaviour-design.md`](p0a2-24h-behaviour-design.md)（第一階段設計，PR #161；下稱「設計」）。本文件只寫第二階段實作了什麼、哪裡與設計不同、哪些仍是假設。
> **程式**：`prototypes/p0a2-24h/`（純 TypeScript，無 DOM／Node API）；參數 `prototypes/p0a2-24h/params.json`；測試 `tests/p0a2-24h-proto.test.ts`。
> **最重要的限制**：所有輸出都是模型在**合成天氣**（`synthetic: true`）與大量**遊戲假設**下的結果，不是野外觀測，不能拿來宣稱本種的日夜活動型態。

---

## 1. 做了什麼（摘要）

1. 一個小實驗群（30 隻小工蟻、8 隻幼蟲）與一個情境食源（半翅目蜜露 `hemiptera-A`），在**連續事件時間**上運行任意天數。
2. 每隻工蟻有自己的生理（嗉囊量、代謝、未滿足的代謝需求）、個體特質（覓食／育幼門檻、反應增益、CTmax）、路線記憶與**自己實際經歷的接觸紀錄**；在巢內休息、巢內走動、育幼、到巢口、出巢（沿路線或搜尋）、取食、回巢之間轉換。
3. 每個決策只讀「這隻個體＋它所在位置」的資訊；活動時間分布是**輸出**。程式中沒有「時段 → 活動」的表，沒有把本種設成日行或夜行。
4. 環境（日出日落、逐時氣溫、相對濕度）是時間與情境的純函式，不讀任何蟻群狀態。
5. 決定性：同種子＋同參數 → 事件紀錄的 sha256 相同；任意切分推進時間、或快照／還原，事件紀錄與狀態**逐位元組相同**（這是第三階段「FPS／速度／鏡頭不改命運」的證明基礎）。

## 2. ODD 摘要（ODD Protocol 精簡版，R330、R332）

### 2.1 目的
檢驗：在只用個體生理與局部訊號的規則下，加上隨時間變化的環境，**活動的日夜分布能否、以及如何湧現**；並建立一個可在 Web Worker 中持續運算、可重播的核心（第三階段）。**不是**為了重現某個觀測型態而設計，也沒有為此調參。

### 2.2 實體、狀態變數與尺度
| 實體 | 狀態變數 |
|---|---|
| 工蟻 | `state`（resting、idle、brood_care、to_entrance、outbound、searching、feeding、returning）、`loc`（nest、nest_transit、outside）、`crop`（µP）、`consumed`、`debt`（未滿足的代謝需求，診斷用）、`theta_forage`、`theta_brood`、`gain`、`thermal_offset_c`（0）、`ctmax_c`、`route`（路線記憶）、`trip_loaded`、`contacts[]`（自己經歷的接觸）、`begging[]`（自己碰到的幼蟲與當時感知的求食訊號）、唯一的待執行事件 |
| 幼蟲 | `gut`（µP）、`consumed`、`deficit`；不發育、不死亡（尚未模擬） |
| 食源 | `stock`、`produced`、`taken`（帶來源 ID） |
| 環境 | 不是狀態：光（NOAA 太陽計算）、氣溫（情境逐時剖面）、相對濕度，都是時間的純函式 |
| 統計（玩家視角） | 各狀態逐時累計時間、逐時出巢／放棄／回巢次數、食物帳。**只供統計與守恆檢查，任何決策都讀不到** |

- 時間：整數毫秒，自實驗 Day0 00:00（當地時間）起算；沒有影格、沒有固定步長。
- 食物：整數微份（µP，遊戲份的 10⁻⁶），守恆檢查是整數相等。
- 空間：只有「巢內／巢口與巢內移動／巢外」三種位置；巢口到食源 2 m（情境），移動時間＝距離÷沿跡速度。二維空間、出口容量尚未模擬（#157、#158）。

### 2.3 過程與排程
- 事件依 `layered` 時間契約（`docs/p0a0-time-contract.md`）排序：（精確時刻、round、正規 ID）。同一時刻由某事件引發的事件放在下一個 round。ID 由實體 ID 與該實體自己的事件序號組成，不依陣列位置。
- 每個事件從自己的亂數流抽樣：`rng(hash32(種子|事件 ID))`（與 `engine/scheduler/world-events.ts` 的 `rngStreamName` 原則相同：由內容導出，不共用循序亂數流），所以沒有需要保存的亂數狀態。
- `advanceTo(T)` 執行所有 `t ≤ T` 的事件。狀態只在事件發生時改變（代謝、時間預算都在事件時刻以整數運算結帳），推進的切法因此不影響結果。
- 世界事件：每日 `env_day` 排定該日的光照轉換（民用曙光、日出、日落、民用暮光）與 24 個逐時氣象取樣（只寫入紀錄，供觀察）；蜜露 `produce` 每 900 秒一次，固定、不依蟻群狀態。
- 工蟻事件：`bout_end`、`wake`、`at_entrance`、`arrive_source`、`feed_end`、`search_end`、`arrive_nest`。

### 2.4 設計概念
- **湧現**：出巢時間分布、休息比例、巢內工作量都是輸出。
- **感知（局部）**：
  - 自己：嗉囊飽足度、門檻、增益、CTmax、是否有路線記憶、最近 600 秒內**自己被滿載回巢者接觸**的次數、**自己碰到**的求食幼蟲數。
  - 巢口或巢外：**所在地**的溫度（氣溫＋地點偏移）與光照狀態。巢內工蟻收不到光與溫度。
  - 食源：只有**親身抵達**時才看到現場食物量。
  - 交哺：只看到實際接觸到的那隻同伴的嗉囊空間；育幼：只看到實際碰到的那隻幼蟲的求食訊號。
  - **沒有**全巢存糧、全巢飢餓、全巢幼體數、「現在幾點」。
- **互動**：回巢者在巢內與同伴相遇（每隻同伴各自的相遇機率）、交哺、傳遞招募訊號（路線），並可打斷被接觸者的休息（R233 的機制方向，非本種）。育幼者碰到幼蟲並餵食。
- **隨機性**：個體特質、段長（指數分布）、相遇、出巢判定、搜尋成功都是事件自己的亂數流。
- **觀察**：虛擬巢口落阱（3 小時一格，對應 R145 的取樣格）與逐時活動比例，由事件紀錄與統計副本計算，不回饋（測試：有無擷取紀錄，世界相同）。

### 2.5 初始化
Day0 00:00：所有工蟻在巢內休息；起始嗉囊與幼蟲腸內量在 [0, 容量] 均勻抽樣；第一次休息結束時刻由各自的亂數流抽樣（不同步）；食源存量 0；沒有工蟻有路線記憶。

### 2.6 輸入資料
兩個**合成**情境（`synthetic: true`、`assumption: true`），由臺中站 1991–2020 月平年值（`data/taichung-climatology-1991-2020.json`）手寫線性剖面產生：06:00＝月平均日最低溫、14:00＝月平均日最高溫，其間直線，每日相同。
| 情境 | 日期（情境） | 氣溫範圍 | 相對濕度 | 雨 |
|---|---|---|---|---|
| `taichung-march-ref` | 2026-03-26（月日對應 R145 都市取樣） | 16.4～25.2°C | 74.6%（日均） | `null`（未知，不產生雨事件、不當作無雨） |
| `taichung-may-ref` | 2026-05-11（月日對應 R145 森林取樣；但氣溫仍是臺中站，不是森林） | 23.1～30.7°C | 75.7% | `null` |

Parton–Logan 係數仍是 `null`，所以沒有用 `WeatherSeries` 的日內重建；`WeatherSeries` 只接受**觀測**的逐時資料（合成資料不得冒充觀測，這個檢查保留不動）。逐時剖面有缺值時，原型**拒絕執行**，不補值。

### 2.7 子模型
| 子模型 | 規則 |
|---|---|
| 代謝 | 嗉囊以常數速率消耗（0.1 份／日）；嗉囊空了，缺額記為 `debt`（不是食物）。巢溫未模擬，不套用 Q10 |
| 巢內選擇 | 覓食刺激 `s_f = (1 − 嗉囊飽足度) + 0.5 × 最近被招募接觸次數`；育幼刺激 `s_b = 最近碰到的求食幼蟲數`；`P_f = gain × hill(s_f; θ_f, 2)`，`P_b = gain × hill(s_b; θ_b, 2)`（嗉囊空時 `P_b = 0`）。以一個均勻數決定是否開始工作、再依 `P_f : P_b` 選工作；都不做時，0.3 機率巢內走動、否則休息 |
| 出巢（M1） | 巢口所在地溫度 T：`T ≥ CTmax` → 不出（`heat`）；否則以機率 `f_T(T)` 出巢（10°C 為 0、24°C 為 1、46°C 為 0，直線）；`f_light ≡ 1`（M2 關）。溫度 `null` → `temp_unavailable` |
| 路線與搜尋 | 有路線記憶 → 沿跡到食源；沒有 → 搜尋一段（平均 600 秒），0.2 機率找到並記住路線 |
| 食源 | 抵達時看到現場存量，取 `min(嗉囊空間, 存量)`；取食時間依載量比例；`T ≥ CTmax` 時立即返巢 |
| 回巢 | 與巢內每隻同伴各以 0.1 機率相遇，隨機順序取前 3 隻；每次交哺 `min(0.28 份, 自己嗉囊, 對方空間)`。這趟載量 ≥ 50% 容量者是招募者：被接觸者得到接觸紀錄與路線，休息或走動中者被喚醒並立即重新決策 |
| 育幼 | 每隻幼蟲各以 0.5 機率被碰到；感知求食訊號 `1 − 腸內量／腸容量`；≥ 0.3 才餵，每口 `min(0.025 份, 自己嗉囊, 幼蟲空間)` |

## 4. 診斷輸出（**不是目標**，CLAUDE.md §7）

種子 1、3 天、合成天氣（`node tests/p0a2-24h-proto.test.ts` 會印出完整 JSON）：

| 情境 | 虛擬巢口落阱 3 小時格（00–03 … 21–24，出巢＋回巢次數） | 日出到日落之間出巢／其他時段出巢 |
|---|---|---|
| 3 月 | 771、631、685、1094、1320、1356、1054、747 | 2275／1555 |
| 5 月 | 1318、1341、1383、1039、854、825、964、995 | 2281／2079 |

5 個種子（1～5）、各 3 天，09–17 時與 20–05 時的出巢數：3 月每個種子都是白天多（例如 1677 vs 1141）；5 月每個種子都是夜間多（例如 1207 vs 1797）。

**如何讀**：
- 3 月：白天高、夜間仍 >0。這個形狀主要來自 `f_T`：3 月氣溫 16.4～25.2°C 都在 24°C 峰值以下，愈熱出巢機率愈高。
- 5 月：夜間到清晨高、下午低。這是因為 5 月白天超過 24°C 後 `f_T` 下降——**完全取決於從 *P. pallidula* 外推的峰值溫度**，不是本種證據。
- 與 R145 的關係：R145 都市（3 月）「多在白天、夜間不為 0」與 3 月的形狀方向一致；R145 森林（5 月）「日夜相近」與 5 月的「夜高」**不一致**，而且 5 月情境用的是臺中站氣溫，不是森林。這些**只是形狀比較**，沒有多種子統計、沒有敏感度分析，也沒有調任何參數去接近或遠離 R145。設計 §7 的 V1～V10 驗證（≥20 種子、四季、極端、每個假設參數至少兩值）**尚未做**。
- 其他觀察（如實記錄，未修正）：約 92% 的抵達食源是空手（蜜露每 15 分鐘一份，先到者取走）；少數覓食者把嗉囊全部交出後反覆出巢，自身代謝缺額（`debt`）累積。原因：交哺上限 0.28 × 3 隻 ＞ 嗉囊容量 0.8，回巢者可能交光；沒有「放棄」或食物時刻記憶（M6 關）；路線記憶不衰退。這是模型假設的後果，不是本種行為的結論（見 §7 Owner 問題）。

## 6. 尚未模擬

雨與遮蔽、失水（M8）、休息債（M5）、食物時刻記憶（M6）、營養改變熱耐受（M7）、光線索（M2，`f_light ≡ 1`）、內在時鐘；熱死亡、飢餓死亡、任何出生或死亡；幼蟲發育；蛋白質（只有糖）；巢溫與巢內空間；二維移動與出口容量（#157、#158）；費洛蒙路徑與其衰退；路線記憶的遺忘；個體間熱耐受差異；溫度對步行速度的影響（R143，非本種）；多個食源；人類食物時刻情境（設計 §10 問題 2，待 Owner 決定）；多群；巢內工蟻之間的交哺。

## 7. 已知限制

- 同一精確時刻、同一 round 的不同個體事件（例如同時被喚醒的多隻工蟻）依**正規 ID 順序**處理；同時競爭的規則仍未決（設計 §4.1、P0-A1 §7），統計 `same_instant_events`（種子 1、3 天約 80～90 次）。ID 改名會改變結果（個體特質由 ID 導出的亂數流抽樣）；陣列順序不影響（全部依排序後的 ID 走訪）。
- 相遇用「每隻同伴各自的機率」代替空間；巢內位置、擁擠度沒有模擬。
- 代謝是常數；嗉囊與代謝共用同一個池（沒有脂肪體）。
- 所有工蟻都是小工蟻、都能覓食（沒有年齡分工）。
- 診斷只做了種子 1～5、兩個合成情境、3 天；沒有敏感度分析，不能下結論。

## 8. 第三階段：接到實驗 Web Worker（#169）而不改結果

- 匯入白名單：原型核心只匯入自己的目錄、`engine/clock/`、`engine/scheduler/`、`engine/rng.ts`、`engine/sha256.ts`（PR #165 的實驗 Worker 白名單）；測試會擋。另有 `prototypes/p0a2-24h/tsconfig.json`（無 DOM、無 Node 型別）可單獨檢查：`npx tsc -p prototypes/p0a2-24h/tsconfig.json`。

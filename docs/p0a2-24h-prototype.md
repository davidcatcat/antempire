# P0-A2 第二階段：24 小時個體行為隔離原型（Issue #156）

> **地位**：**非正式**實驗原型。只在 Day0 實驗世界的隔離測試中執行；**不**改 `engine/*.ts`、`cli/`、`web/`、`saves/`、`journal/`，**不**在規則指紋內，**不**推進遊戲日，**不**建立正式 Day0。正式引擎的 360 分鐘活動時窗不變。
> **依據**：[`docs/p0a2-24h-behaviour-design.md`](p0a2-24h-behaviour-design.md)（第一階段設計，PR #161；下稱「設計」）。本文件只寫第二階段實作了什麼、哪裡與設計不同、哪些仍是假設。
> **程式**：`prototypes/p0a2-24h/`（純 TypeScript，無 DOM／Node API）；參數 `prototypes/p0a2-24h/params.json`；測試 `tests/p0a2-24h-proto.test.ts`；Node 分析工具 `prototypes/p0a2-24h/tools/`（不在阻擋測試內）。
> **Owner 裁示（#188，#193 於 2026-11-12 裁示）**：參考情境改為 `ft-flat`（f_T 錨點 null，只保留本種 CTmax 42°C）；覓食者保留自身所需只作預設關的隔離候選機制；放棄機制維持預設關；同時刻平手順序維持為過渡性工程仲裁並加驗證。完整紀錄見 §10，Q2 敏感度結果見 §11。
> **最重要的限制**：所有輸出都是模型在**合成天氣**（`synthetic: true`）與大量**遊戲假設**下的結果，不是野外觀測，不能拿來宣稱本種的日夜活動型態。參考情境 `ft-flat` 是**暫定、未校準**的參考：f_T≡1 **不代表**實測的日夜活動相同，模型輸出的日夜分布**未經科學驗證**。

## 1. 做了什麼（摘要）

1. 一個小實驗群（30 隻小工蟻、8 隻幼蟲）與一個情境食源（半翅目蜜露 `hemiptera-A`），在**連續事件時間**上運行任意天數。
2. 每隻工蟻有自己的生理（嗉囊量、代謝、未滿足的代謝需求）、個體特質（覓食／育幼門檻、反應增益、CTmax）、路線記憶與**自己實際經歷的接觸紀錄**；在巢內休息、巢內走動、育幼、到巢口、出巢（沿路線或搜尋）、取食、回巢之間轉換。
3. 每個決策只讀「這隻個體＋它所在位置」的資訊；活動時間分布是**輸出**。程式中沒有「時段 → 活動」的表，沒有把本種設成日行或夜行。
4. 環境（日出日落、逐時氣溫、相對濕度）是時間與情境的純函式，不讀任何蟻群狀態。
5. 決定性：同種子＋同參數 → 事件紀錄的 sha256 相同；任意切分推進時間、或快照／還原，事件紀錄與狀態**逐位元組相同**（這是第三階段「FPS／速度／鏡頭不改命運」的證明基礎）。

## 2. ODD 摘要（ODD Protocol 精簡版，R330、R332）

### 2.1 目的
檢驗：在只用個體生理與局部訊號的規則下，加上隨時間變化的環境，**活動的日夜分布能否、以及如何湧現**；並建立一個可在 Web Worker 中持續運算、可重播的核心（第三階段）。**不是**為了重現某個觀測型態而設計，也沒有為此調參。

### 2.2 實體、狀態變數與尺度
| 實體 | 狀態變數 |
|---|---|
| 工蟻 | `state`（resting、idle、brood_care、to_entrance、from_entrance、outbound、searching、feeding、returning）、`loc`（nest、nest_transit、outside）、`crop`（µP）、`consumed`、`debt`（未滿足的代謝需求，診斷用）、`theta_forage`、`theta_brood`、`gain`、`thermal_offset_c`（0）、`ctmax_c`、`route`（路線記憶）、`trip_loaded`、`empty_streak`（連續空手抵達次數，只供放棄開關）、`contacts[]`（自己經歷的接觸）、`begging[]`（自己碰到的幼蟲與當時感知的求食訊號）、唯一的待執行事件 |
| 幼蟲 | `gut`（µP）、`consumed`、`deficit`；不發育、不死亡（尚未模擬） |
| 食源 | `stock`、`produced`、`taken`（帶來源 ID） |
| 環境 | 不是狀態：光（NOAA 太陽計算）、氣溫（情境逐時剖面）、相對濕度，都是時間的純函式 |
| 統計（玩家視角） | 各狀態逐時累計時間、逐時出巢／放棄／回巢次數、食物帳。**只供統計與守恆檢查，任何決策都讀不到** |

- 時間：整數毫秒，自實驗 Day0 00:00（當地時間）起算；沒有影格、沒有固定步長。
- 食物：整數微份（µP，遊戲份的 10⁻⁶），守恆檢查是整數相等。
- 空間：只有「巢內／巢口與巢內移動／巢外」三種位置；巢口到食源 2 m（情境），移動時間＝距離÷沿跡速度。二維空間、出口容量尚未模擬（#157、#158）。

### 2.3 過程與排程
- 事件依 `layered` 時間契約（`docs/p0a0-time-contract.md`）排序：（精確時刻、round、**種子決定的平手順序** `q = hash32(種子|t|ID)`、正規 ID）。同一時刻由某事件引發的事件放在下一個 round。ID 由實體 ID 與該實體自己的事件序號組成，不依陣列位置。平手順序只依種子、時刻與 ID，所以仍是決定性且與切分無關；它取代了先前「依 ID 字母順序」的作法（那會因延遲固定而系統性地讓 w001 先於 w030）。**這是過渡性的工程仲裁（Owner #193 Q4），不是宣稱的自然競爭規則**；公平性、切分不變與重播的驗證見 §9、§10。
- 每個事件從自己的亂數流抽樣：`rng(hash32(種子|事件 ID))`（與 `engine/scheduler/world-events.ts` 的 `rngStreamName` 原則相同：由內容導出，不共用循序亂數流），所以沒有需要保存的亂數狀態。
- `advanceTo(T)` 執行所有 `t ≤ T` 的事件。狀態只在事件發生時改變（代謝、時間預算都在事件時刻以整數運算結帳），推進的切法因此不影響結果。
- 世界事件：每日 `env_day` 排定該日的光照轉換（民用曙光、日出、日落、民用暮光）與 24 個逐時氣象取樣（只寫入紀錄，供觀察）；蜜露 `produce` 每 900 秒一次，固定、不依蟻群狀態。
- 工蟻事件：`bout_end`、`wake`、`at_entrance`、`back_in`、`arrive_source`、`feed_end`、`search_end`、`arrive_nest`。

### 2.4 設計概念
- **湧現**：出巢時間分布、休息比例、巢內工作量都是輸出。
- **感知（局部）**：
  - 自己：嗉囊飽足度、門檻、增益、CTmax、是否有路線記憶、最近 600 秒內**自己被滿載回巢者接觸**的次數、**自己碰到**的求食幼蟲數。
  - 巢口或巢外：**所在地**的溫度（氣溫＋地點偏移）與光照狀態。巢內工蟻收不到光與溫度。
  - 食源：只有**親身抵達**時才看到現場食物量。
  - 交哺：只看到實際接觸到的那隻同伴的嗉囊空間；育幼：只看到實際碰到的那隻幼蟲的求食訊號。
  - **沒有**全巢存糧、全巢飢餓、全巢幼體數、「現在幾點」。
- **互動**：回巢者在巢內與同伴相遇（每隻同伴各自的相遇機率）、交哺、傳遞招募訊號（路線），並可打斷被接觸者的休息（R233 的機制方向，非本種）。育幼者碰到幼蟲並餵食。
- **隨機性**：個體特質、段長（指數分布）、相遇、出巢判定、搜尋成功都是事件自己的亂數流。
- **觀察**：虛擬巢口落阱（3 小時一格，對應 R145 的取樣格）與逐時活動比例，由事件紀錄與統計副本計算，不回饋（測試：有無擷取紀錄，世界相同）。

### 2.5 初始化
Day0 00:00：所有工蟻在巢內休息；起始嗉囊與幼蟲腸內量在 [0, 容量] 均勻抽樣；第一次休息結束時刻由各自的亂數流抽樣（不同步）；食源存量 0；沒有工蟻有路線記憶。

兩個**合成**情境（`synthetic: true`、`assumption: true`），由臺中站 1991–2020 月平年值（`data/taichung-climatology-1991-2020.json`）手寫線性剖面產生：06:00＝月平均日最低溫、14:00＝月平均日最高溫，其間直線，每日相同。
| 情境 | 日期（情境） | 氣溫範圍 | 相對濕度 | 雨 |
|---|---|---|---|---|
| `taichung-march-ref` | 2026-03-26（月日對應 R145 都市取樣） | 16.4～25.2°C | 74.6%（日均） | `null`（未知，不產生雨事件、不當作無雨） |

### 2.7 子模型
| 子模型 | 規則 |
|---|---|
| 代謝 | 嗉囊以常數速率消耗（0.1 份／日）；嗉囊空了，缺額記為 `debt`（不是食物）。巢溫未模擬，不套用 Q10 |
| 自身取食經歷 | 每次自己在食源取到食物時記下時刻；`forage_interval_ms`＝自己最近兩次在食源取食的間隔（未滿兩次為 null）。只有 Q2 候選機制（預設關）會讀它 |
| 巢內選擇 | 覓食刺激 `s_f = (1 − 嗉囊飽足度) + 0.5 × 最近被招募接觸次數`；育幼刺激 `s_b = 最近碰到的求食幼蟲數`；`P_f = gain × hill(s_f; θ_f, 2)`，`P_b = gain × hill(s_b; θ_b, 2)`（嗉囊空時 `P_b = 0`）。以一個均勻數決定是否開始工作、再依 `P_f : P_b` 選工作；都不做時，0.3 機率巢內走動、否則休息 |
| 出巢（M1） | 巢口所在地溫度 T：`T ≥ CTmax`（42°C，R145 本種）→ 不出（`heat`）；否則以機率 `f_T(T)` 出巢。**參考 `ft-flat`：錨點 null → `f_T ≡ 1`**（暫定、未校準；Owner #193 Q1＝B）；敏感度情境 `ft-r190`：10°C 為 0、24°C 為 1、46°C 為 0，直線（R190 *Pheidole pallidula*，非本種）。`f_light ≡ 1`（M2 關）。溫度 `null` → `temp_unavailable`。不出巢者走回巢內（`from_entrance`，位置 `nest_transit`，30 秒），抵達（`back_in`）後才算在巢內、才能被同伴接觸，然後休息 |
| 路線與搜尋 | 有路線記憶 → 沿跡到食源；沒有 → 搜尋一段（平均 600 秒），0.2 機率找到並記住路線 |
| 食源 | 抵達時看到現場存量，取 `min(嗉囊空間, 存量)`；取食時間依載量比例；`T ≥ CTmax` 時立即返巢。放棄開關（參考情境關）：連續 K 次親身抵達都沒有食物就忘掉路線 |
| 回巢 | 與巢內每隻同伴各以 0.1 機率相遇，隨機順序取前 3 隻；每次交哺 `min(0.28 份, 自己嗉囊 − 自身保留量, 對方空間)`，參考情境的自身保留量為 0（Q2 候選機制關，與先前完全相同）。這趟載量 ≥ 50% 容量者是招募者：被接觸者得到接觸紀錄與路線，休息或走動中者被喚醒並立即重新決策 |
| Q2 候選：自身保留量（**預設關**） | 只在 `q2_retention_variants` 隔離實驗開啟。保留量＝`ceil(自己的代謝率 × 預期間隔)`；`horizon`：預期間隔為固定 H 小時（1／6／24，遊戲假設）；`own_interval`：預期間隔＝k ×（自己最近兩次在食源取食的間隔），k＝1／2（遊戲假設），尚無兩次經歷時保留 0（不補值）。只讀自己的狀態（`decision.ts` `ownReserve`，局部視圖）。開啟時 `arrive_nest` 事件另記 `reserve` 與 `crop_left`，供測試由事件紀錄驗證規則 |
| 育幼 | 每隻幼蟲各以 0.5 機率被碰到；感知求食訊號 `1 − 腸內量／腸容量`；≥ 0.3 才餵，每口 `min(0.025 份, 自己嗉囊, 幼蟲空間)` |

- 自身代謝缺額（`debt`，飢餓的代理量；飢餓死亡尚未模擬）：每一種公式、每一個種子都下降。固定預期間隔 6 或 24 小時幾乎消除缺額，有缺額的工蟻也幾乎歸零；1 小時與「自己取食間隔」公式約減少 60～70% 的缺額總量，但有缺額的工蟻數幾乎不變（原因尚未分析：可能是每隻都仍有短暫缺額、只是量變小；未驗證）。
- 幼蟲：2 天內所有情境的幼蟲缺額都是 0，餵幼蟲量差異 ≤ 0.003 份（各種子方向不一）。也就是說在這個短期、幼蟲需求小的設定下，候選機制**沒有看得出的**幼蟲餵食影響；這不代表長期或幼蟲較多時也沒有影響（尚未測）。
- 交哺：次數下降（1693 → 1317～1617），交哺總量多數略降但各種子方向不一；出巢次數上升（覓食者保留較多後，巢內其他工蟻較常因自己嗉囊空而出巢——這是模型內的推論，未驗證）。
- 敏感度基底 `ft-r190`（R190 非本種錨點）兩季不同，但所有方向與參考相同（完整表見 `out/q2-retention-sensitivity.md`）。
- 限制：30 隻工蟻、8 隻幼蟲、單一情境蜜露源、2 天、10 個種子；代謝為常數、沒有脂肪體、沒有飢餓死亡、沒有巢內工蟻之間的交哺、沒有本種的保留量資料。結果只說明候選公式在**這個模型**中的方向，不能外推為本種行為，也不能用來選擇「讓蟻群較好」的公式。

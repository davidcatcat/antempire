## 1. 做了什麼（摘要）

1. 一個小實驗群（30 隻小工蟻、8 隻幼蟲）與一個情境食源（半翅目蜜露 `hemiptera-A`），在**連續事件時間**上運行任意天數。
2. 每隻工蟻有自己的生理（嗉囊量、代謝、未滿足的代謝需求）、個體特質（覓食／育幼門檻、反應增益、CTmax）、路線記憶與**自己實際經歷的接觸紀錄**；在巢內休息、巢內走動、育幼、到巢口、出巢（沿路線或搜尋）、取食、回巢之間轉換。
3. 每個決策只讀「這隻個體＋它所在位置」的資訊；活動時間分布是**輸出**。程式中沒有「時段 → 活動」的表，沒有把本種設成日行或夜行。
4. 環境（日出日落、逐時氣溫、相對濕度）是時間與情境的純函式，不讀任何蟻群狀態。
5. 決定性：同種子＋同參數 → 事件紀錄的 sha256 相同；任意切分推進時間、或快照／還原，事件紀錄與狀態**逐位元組相同**（這是第三階段「FPS／速度／鏡頭不改命運」的證明基礎）。

## 2. ODD 摘要（ODD Protocol 精簡版，R330、R332）

### 2.1 目的
檢驗：在只用個體生理與局部訊號的規則下，加上隨時間變化的環境，**活動的日夜分布能否、以及如何湧現**；並建立一個可在 Web Worker 中持續運算、可重播的核心（第三階段）。**不是**為了重現某個觀測型態而設計，也沒有為此調參。

### 2.2 實體、狀態變數與尺度
| 實體 | 狀態變數 |
|---|---|
| 工蟻 | `state`（resting、idle、brood_care、to_entrance、from_entrance、outbound、searching、feeding、returning）、`loc`（nest、nest_transit、outside）、`crop`（µP）、`consumed`、`debt`（未滿足的代謝需求，診斷用）、`theta_forage`、`theta_brood`、`gain`、`thermal_offset_c`（0）、`ctmax_c`、`route`（路線記憶）、`trip_loaded`、`empty_streak`（連續空手抵達次數，只供放棄開關）、`contacts[]`（自己經歷的接觸）、`begging[]`（自己碰到的幼蟲與當時感知的求食訊號）、飢餓診斷 `empty_since`／`empty_ms`／`max_empty_ms`（嗉囊空的起點、累計與最長連續時間；只供統計，不在任何決策視圖）、唯一的待執行事件 |
| 幼蟲 | `gut`（µP）、`consumed`、`deficit`、`received`（從照護者得到的食物，生長代理量）；飢餓診斷 `empty_since`／`empty_ms`／`max_empty_ms`（只供統計）；不發育、不死亡（尚未模擬） |
| 食源 | `stock`、`produced`、`taken`（帶來源 ID） |
| 環境 | 不是狀態：光（NOAA 太陽計算）、氣溫（情境逐時剖面）、相對濕度，都是時間的純函式 |
| 統計（玩家視角） | 各狀態逐時累計時間、逐時出巢／放棄／回巢次數、食物帳。**只供統計與守恆檢查，任何決策都讀不到** |

- 時間：整數毫秒，自實驗 Day0 00:00（當地時間）起算；沒有影格、沒有固定步長。
- 食物：整數微份（µP，遊戲份的 10⁻⁶），守恆檢查是整數相等。
- 空間：只有「巢內／巢口與巢內移動／巢外」三種位置；巢口到食源 2 m（情境），移動時間＝距離÷沿跡速度。二維空間、出口容量尚未模擬（#157、#158）。

### 2.3 過程與排程
- 事件依 `layered` 時間契約（`docs/p0a0-time-contract.md`）排序：（精確時刻、round、**種子決定的平手順序** `q = hash32(種子|t|ID)`、正規 ID）。同一時刻由某事件引發的事件放在下一個 round。ID 由實體 ID 與該實體自己的事件序號組成，不依陣列位置。平手順序只依種子、時刻與 ID，所以仍是決定性且與切分無關；它取代了先前「依 ID 字母順序」的作法（那會因延遲固定而系統性地讓 w001 先於 w030）。**這是過渡性的工程仲裁（Owner #193 Q4），不是宣稱的自然競爭規則**；公平性、切分不變與重播的驗證見 §9、§10。
- 每個事件從自己的亂數流抽樣：`rng(hash32(種子|事件 ID))`（與 `engine/scheduler/world-events.ts` 的 `rngStreamName` 原則相同：由內容導出，不共用循序亂數流），所以沒有需要保存的亂數狀態。
- `advanceTo(T)` 執行所有 `t ≤ T` 的事件。狀態只在事件發生時改變（代謝、時間預算都在事件時刻以整數運算結帳），推進的切法因此不影響結果。
- 世界事件：每日 `env_day` 排定該日的光照轉換（民用曙光、日出、日落、民用暮光）與 24 個逐時氣象取樣（只寫入紀錄，供觀察）；蜜露 `produce` 每 900 秒一次，固定、不依蟻群狀態。
- 工蟻事件：`bout_end`、`wake`、`at_entrance`、`back_in`、`arrive_source`、`feed_end`、`search_end`、`arrive_nest`。

### 2.4 設計概念
- **湧現**：出巢時間分布、休息比例、巢內工作量都是輸出。
- **感知（局部）**：
  - 自己：嗉囊飽足度、門檻、增益、CTmax、是否有路線記憶、最近 600 秒內**自己被滿載回巢者接觸**的次數、**自己碰到**的求食幼蟲數。
  - 巢口或巢外：**所在地**的溫度（氣溫＋地點偏移）與光照狀態。巢內工蟻收不到光與溫度。
  - 食源：只有**親身抵達**時才看到現場食物量。
  - 交哺：只看到實際接觸到的那隻同伴的嗉囊空間，以及自己的 `DonorView`（自己的嗉囊、自己的取食間隔）；育幼：只看到實際碰到的那隻幼蟲的求食訊號，以及自己的 `CarerView`（自己的嗉囊、嗉囊飽足度、取食間隔）。
  - **沒有**全巢存糧、全巢飢餓、全巢幼體數、「現在幾點」。
- **互動**：回巢者在巢內與同伴相遇（每隻同伴各自的相遇機率）、交哺、傳遞招募訊號（路線），並可打斷被接觸者的休息（R233 的機制方向，非本種）。育幼者碰到幼蟲並餵食。
- **隨機性**：個體特質、段長（指數分布）、相遇、出巢判定、搜尋成功都是事件自己的亂數流。
- **觀察**：虛擬巢口落阱（3 小時一格，對應 R145 的取樣格）與逐時活動比例，由事件紀錄與統計副本計算，不回饋（測試：有無擷取紀錄，世界相同）。

### 2.5 初始化
Day0 00:00：所有工蟻在巢內休息；起始嗉囊與幼蟲腸內量在 [0, 容量] 均勻抽樣；第一次休息結束時刻由各自的亂數流抽樣（不同步）；食源存量 0；沒有工蟻有路線記憶。

### 2.7 子模型
| 子模型 | 規則 |
|---|---|
| (1) 自身代謝 | 嗉囊以常數速率消耗（0.1 份／日）；嗉囊空了，缺額記為 `debt`（不是食物）。巢溫未模擬，不套用 Q10。`decision.ts` `ownNeed`：自己在某保留公式下的預期代謝需求，只讀自己的代謝率與自己的取食間隔；交哺與育幼**各自**決定要不要用它、用哪個公式（§12） |
| 自身取食經歷 | 每次自己在食源取到食物時記下時刻；`forage_interval_ms`＝自己最近兩次在食源取食的間隔（未滿兩次為 null）。只有 Q2 候選機制（預設關）會讀它 |
| 巢內選擇 | 覓食刺激 `s_f = (1 − 嗉囊飽足度) + 0.5 × 最近被招募接觸次數`；育幼刺激 `s_b = 最近碰到的求食幼蟲數`；`P_f = gain × hill(s_f; θ_f, 2)`，`P_b = gain × hill(s_b; θ_b, 2)`（嗉囊空時 `P_b = 0`）。以一個均勻數決定是否開始工作、再依 `P_f : P_b` 選工作；都不做時，0.3 機率巢內走動、否則休息 |
| 出巢（M1） | 巢口所在地溫度 T：`T ≥ CTmax`（42°C，R145 本種）→ 不出（`heat`）；否則以機率 `f_T(T)` 出巢。**參考 `ft-flat`：錨點 null → `f_T ≡ 1`**（暫定、未校準；Owner #193 Q1＝B）；敏感度情境 `ft-r190`：10°C 為 0、24°C 為 1、46°C 為 0，直線（R190 *Pheidole pallidula*，非本種）。`f_light ≡ 1`（M2 關）。溫度 `null` → `temp_unavailable`。不出巢者走回巢內（`from_entrance`，位置 `nest_transit`，30 秒），抵達（`back_in`）後才算在巢內、才能被同伴接觸，然後休息 |
| 路線與搜尋 | 有路線記憶 → 沿跡到食源；沒有 → 搜尋一段（平均 600 秒），0.2 機率找到並記住路線 |
| 食源 | 抵達時看到現場存量，取 `min(嗉囊空間, 存量)`；取食時間依載量比例；`T ≥ CTmax` 時立即返巢。放棄開關（參考情境關）：連續 K 次親身抵達都沒有食物就忘掉路線 |
| (2) 回巢交哺 | 與巢內每隻同伴各以 0.1 機率相遇，隨機順序取前 3 隻；每次交哺 `min(0.28 份, 自己嗉囊 − 自身保留量, 對方空間)`，參考情境的自身保留量為 0（Q2 候選機制關，與先前完全相同）。這趟載量 ≥ 50% 容量者是招募者：被接觸者得到接觸紀錄與路線，休息或走動中者被喚醒並立即重新決策 |
| Q2 候選：自身保留量（**預設關**） | 只在 `q2_retention_variants` 隔離實驗開啟。保留量＝`ceil(自己的代謝率 × 預期間隔)`；`horizon`：預期間隔為固定 H 小時（1／6／24，遊戲假設）；`own_interval`：預期間隔＝k ×（自己最近兩次在食源取食的間隔），k＝1／2（遊戲假設），尚無兩次經歷時保留 0（不補值）。只讀自己的狀態（`decision.ts` `ownReserve`＝`ownNeed` 套用交哺自己的保留設定；`DonorView`，局部視圖）。開啟時 `arrive_nest` 事件另記 `reserve` 與 `crop_left`，供測試由事件紀錄驗證規則 |
| (3) 成蟻對幼體餵食 | 每隻幼蟲各以 0.5 機率被碰到；感知求食訊號 `1 − 腸內量／腸容量`；參考：≥ 0.3 才餵，每口 `min(0.025 份, 照護者可給量, 幼蟲空間)`，照護者可給量＝自己的嗉囊（育幼保留關、自身飽足門檻關，與先前完全相同）。`decideFeedLarva`／`broodGivable` 只讀 `CarerView` 與 `LarvaView`；參數 `brood_*` 與交哺的 `transfer_max`／`forager_retention` 完全分開（§12） |

## 4. 參考情境、敏感度變體與診斷輸出（**不是目標**，CLAUDE.md §7）

## 7. 已知限制

- 同一精確時刻、同一 round 的不同個體事件（例如同時被喚醒的多隻工蟻）依**種子決定的平手順序**處理（不再依 ID 字母順序）；Owner #193 Q4：這是**過渡性的工程仲裁**，**不是**宣稱的生物學同時競爭規則（設計 §4.1、P0-A1 §7，自然規則仍未決），統計 `same_instant_events`。已驗證：首位處理不偏向任何 ID、切分與快照不變、重播決定性（§9、§10）；這些驗證只說明仲裁公平且可重播，不說明它符合自然。ID 改名會改變結果（個體特質與平手順序由 ID 導出）；陣列順序不影響。
- 相遇用「每隻同伴各自的機率」代替空間；巢內位置、擁擠度沒有模擬。
- 代謝是常數；嗉囊與代謝共用同一個池（沒有脂肪體）。
- 所有工蟻都是小工蟻、都能覓食（沒有年齡分工）。
- 活動型態診斷只做了種子 1、兩個合成情境、2 天、四個變體；不是正式的敏感度分析，不能下結論。Q2 的多種子敏感度分析見 §11。

**如何讀**（如實記錄，未調參；診斷不是目標）：
- **能量虧損集中在工蟻，不在幼蟲**：參考中 30 隻工蟻有 17.5 隻在 2 天內有未滿足的自身需求，最長連續空腹約 5.5 小時；幼蟲的最長連續空腹在 560 次執行中最多 1.35 小時（各格平均 ≤ 0.14 小時；8 或 24 隻、任何候選），沒有幼蟲連續空腹 ≥ 6 小時。沒有任何個體連續空腹 ≥ 24 小時；工蟻 ≥ 12 小時只出現在 `m-double`／24 隻幼蟲（單次最多 1 隻、最長 12.2 小時，平均 0.1 隻）。
- **(2) 是工蟻虧損的主要來源**：覓食者保留自身需求（`q2-h6`）幾乎消除工蟻虧損（1.607 → 0.011），對幼蟲得到的食物沒有可見影響（與 §11 一致）。
- **(3) 的候選在這個模型中幾乎沒有作用**：照護者自身保留、分級觸發、自身飽足門檻的工蟻虧損成對差都 ≤ 0.013 份、各種子方向不一；幼蟲得到的食物差 ≤ 0.018 份。`b-graded` 餵食次數增加（54.6 → 62.5；24 隻時 164 → 236），但每次份量受幼蟲腸空間限制，總量幾乎不變。原因（模型內推論，未驗證）：幼蟲需求小（每隻 0.025 份／日、腸容量 0.025 份），且只有嗉囊有食物的工蟻才會選育幼，所以照護者很少因育幼而把自己餵空。
- **(1) 自身代謝率**直接決定工蟻虧損量（×2 → +2.5 份），幼蟲不受影響。
- **24 隻幼蟲負荷**（`out/brood-feeding-sensitivity.md`）：方向相同；幼蟲得到的食物約 1.38 份，仍沒有幼蟲連續空腹 ≥ 6 小時。
- **限制**：30 隻工蟻、單一情境蜜露源、只有糖、2 天、10 個種子；常數代謝、沒有脂肪體、沒有巢內工蟻之間的交哺、沒有發育與死亡；幼蟲的代謝與腸容量是 species 檔既有遊戲假設。結果只說明候選公式在**這個模型**中的方向；「幼蟲不缺」很可能是幼蟲需求設定偏小的投影，不能外推為本種「育幼不受限」。

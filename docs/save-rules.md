# 存檔規則 v2｜科學啟發式蟻群世界

本 repo 專門保存《螞蟻帝國》的世界資料、規格和故事進度；**不是程式碼開發倉庫**。

## 權威資料與唯讀歷史
- `saves/main.json`：蟻后／工蟻／幼體數量、狀態、舊v1歷史、模式及模型版本。仍是蟻群狀態的唯一權威。
- `saves/world-state.json`：模擬時鐘、環境、空間節點、資源／掠食者／競爭者及未知參數；另保存西屯區真實天氣資料來源、有效時間、觀測／預報分類。世界狀態權威。
- `journal/chronicle.md` 與 `journal/chronicle_<range>.md`：舊v1故事歸檔，不修改過往結果，不把歷史糖單位當物理測量。
- 新v2回合紀錄建議 `journal/v2-day-0001.md`、`journal/v2-day-0002.md`，以遊戲生態日序編號；若短於一天則在同日檔累加帶時間標記事件。
- `docs/science-model.md`、`docs/ecosystem-world.md`、`docs/simulation-engine.md` 是 v2 模擬權威機制；參數來源看 `docs/references.md`、`docs/species-calibration.md`。

## v2 推進流程
1. 讀主存檔、世界狀態與最新文檔；核對模式、版本、世界時鐘、卵／幼蟲／蛹和累計死亡。
2. 使用者說「繼續／模擬」才推進。預設**科學世界1天**；不用每20分鐘強迫產卵／羽化／選A-D。未要求時不在背景自動更新。
3. 依 `docs/simulation-engine.md` 的順序，先環境後局部感知、自治工作、採食、代謝、幼體與傷勢進度。禁止從後果倒填沒有前因的事件。
4. 紀錄真實（敘事內）觀察與模型推論的差別。所有未知用 `null`，沒有發現他蟻≠絕無敵蟻。
5. 計算變化：`新存活數=舊存活數+成蟻羽化−死亡`、`累計出生−累計死亡=存活`，幼體分階段守恆；資源以採入−分配／消耗−腐敗結算。
6. 寫新v2日誌，更新 `saves/world-state.json` 再更新 `saves/main.json`；若其中任何寫入失敗，要指出已成功／失敗的檔案與可能不一致狀態，**不可宣稱已同步**。
7. 重新讀取兩份狀態和日誌，確認 `scientific_clock`、族群人數、資源與行為事件一致；git SHA與本回合日期記錄可追溯。
8. 若玩家提到舊A選項，視上下文判斷是否表示繼續自治；v2預設不製造必須選擇的事件，也不替使用者做永久的環境改造決定。

## 物理真實性與缺值規則
- v1的 `chapter.elapsed_player_minutes=1150` 僅供故事索引；新的 `scientific_clock` Day0 起算。二者不得以相同分鐘數相加作生物年齡。
- v1糖／蛋白質是抽象單位，沒有可支持的mg換算係數；水量未知不是0。
- 沒有分類鑑定時不得假定一定是黑園蟻 `Lasius niger`；該蟻的研究只能作參考尺度。
- 個體年齡、生理年齡、傷勢感染、環境實際溫度、蟻后產卵率等未知值必須以null或unknown表示。
- 事件中可能無任何新出生／採集成功，也可能發生死亡；不能為故事節奏強迫成果。
- 舊紀事不回溯修正；有衝突時用新檔提出校正說明，並標記何時開始適用。

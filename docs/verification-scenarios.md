# 科學生態模擬 v2｜驗收情境與反例

本文件是文字遊戲推演的**驗收案例**，不是宣稱已經有程式化單元測試；僅確定規格對極端情況有明確約束。觀察者不得預設每回合皆有獎勵。

| 案例 | 初始情況 | 必要行為／驗收 |
|---|---|---|
| T01 蟻后無指揮權 | 糖不足但巢內仍有幼體 | 工蟻可因食物與接觸刺激增加覓食；不得說蟻后發令 |
| T02 未成熟幼體 | Day0有兩隻幼蟲 | 一天後不因劇情節奏瞬間全部蛹化／羽化；缺物種資料時標示不確定 |
| T03 傷蟻自主 | W013有後足擦傷 | 可按個體能力做工作，也可能留巢；不必固定照顧蟻后 |
| T04 蟻后缺水 | 可用水源未知 | 必須顯示水源未建模／未知，不可推定無限水或立刻渴死 |
| T05 蜜露枯竭 | 小白花反覆大量採集 | 存量減少、補充需時間；不可每回合復活12糖 |
| T06 競爭者能動 | 北側介殼蟲與敵蟻 | 競爭者也有覓食與移動，不是永遠守在固定格子 |

| T14 新卵處理 | 蟻后生理資料未知 | 不得宣稱固定每20分鐘新生1蛋；可暫無產卵 |
| T15 空間知識 | W005看到敵蟻，W011遠在另一處 | W011不會立即同步得知；回巢接觸／氣味才可能更新 |
| T16 守衛非固定 | W010以前長期守巢 | 在新模式可依需求探索或育幼；不能只按編號派固定職位 |
| T17 歷史不變 | 既有敘事第1150分鐘14工蟻 | 遷移不重寫歷史、不自動成長到第1170分鐘 |
| T18 連續觀察 | 玩家只說「現在狀況？」 | 只讀狀態，不推進時間或製造事件 |
| T19 預設繼續 | 玩家說「繼續」 | 從科學Day0推進1個模擬日，產生可追蹤記錄 |
| T20 寫入中斷 | 世界存檔寫入成功，主存檔失敗 | 指明資料不一致並停止宣稱成功，下次恢復需核對各檔SHA／時鐘 |

## 每次模擬交付格式（建議）
1. **世界日與環境**：Day、微氣候或未知、資源點更新、局部風險。
2. **自主行為**：誰觀察到什麼、怎麼形成新路線，未觀察到的不要宣稱不存在。
3. **生理與生命周期**：蟻后狀態、幼體各階段、傷蟻活動與任何死因；可能完全沒變化。
4. **資源帳**：入庫、消耗、腐敗、剩餘；先標示是否仍為 legacy 抽象單位。
5. **證據及不確定性**：物種未確定、環境／數值未校準的限制。
6. **檔案回讀驗證**：主存檔、世界狀態及新日誌均已一致；若有失敗則明說。

## 推演品質判準
科學性不是「每回合平均增加工蟻」。符合規格的結果可以是：食物找不到、蟻后未產卵、工蟻停留不動、傷蟻照常工作、感染導致死亡、天敵沒有出現、集體搬幼體、甚至無新事件的一天。最重要的是機制與時間尺度一致、可追溯。

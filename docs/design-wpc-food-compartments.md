## 2. 單位政策
- `portion`（份）是**遊戲單位**，不是 mg，也不是熱量；參數檔與事件一律標 `unit: game_portion`。
- 目前沒有本種「份↔mg」的換算證據。唯一可比的本種量測是 Dejean et al. 2005（R132）在特定蜂蜜實驗中的搬運量（小工蟻 0.08 mg、大工蟻 0.26 mg；搬運量不是嗉囊最大容量）。
- 若日後要和 mg 比較，必須新增一個明確的換算參數（`assumption: true`、遊戲假設），並在報告中寫出；不得把份數直接寫成 mg。
- 守恆以**整數微份**（10⁻⁶ 份，與現行 `round()` 的六位小數一致）計算，避免浮點累積誤差；報表可四捨五入顯示。

### 2b. 本種證據與不可外推之處（Issue #49 N2 修正時重新核對）
- **R132 Dejean et al. 2005**（DOI 10.1007/s00114-005-0632-2，本種）：
  - 偵察蟻先裝滿嗉囊才回巢招募，有交哺；
  - 兵蟻除了嗉囊，還會在頭胸下攜帶**外部液滴**。嗉囊與外部液滴是兩個不同區室，不得合併：目前模型的 `in_transit` 只代表體內嗉囊負載（糖）或顎間固體（蛋白），外部液滴尚未建模；
  - 實驗中的搬運量（0.08／0.26 mg）是特定蜂蜜實驗的負載，不是嗉囊的生理最大容量。
- **R116 Tsuji & Win 2025**（DOI 10.1242/bio.061976，本種）：人工雙巢的營養互補實驗支持巢間資源交換的機制。它沒有提供自然巢距、交換率或母巢規模的通用數值；目前模型只有單一巢，巢間交換屬工作包 E。
- 遊戲份數不是 mg；沒有換算參數之前，不得把份數寫成 mg。
- 全巢庫存不得決定任何一隻工蟻或幼蟲是否攝食（CLAUDE.md §2.1b）。目前引擎仍這樣做（F01／A08），C1 只把它標為 `attribution: unknown`，不是修好。

## 3. 區室（compartments）
每一份食物在任何時刻都在且只在一個區室：
| 區室 | 持有者／位置 | 內容 | 備註 |
|---|---|---|---|
| `source:<site>` | 花園食源 | 糖（蜜露、花蜜）、蛋白（屍體批次） | 由生態模組產生，帶來源事件 ID（現有） |
| `crop:<worker>` | 每隻工蟻的嗉囊 | 液體糖 | 容量 `trophallaxis.crop_capacity`（遊戲假設）；外出時隨工蟻移動（＝搬運中） |
| `carried:<worker>` | 工蟻顎間搬運的固體 | 蛋白 | 新增；現在蛋白收集後直接進全巢帳 |
| `cache:<nest>:<chamber>` | 巢內實際存放處 | 蛋白（固體）。糖：**目前模型不設液體糖倉（模型假設，`assumption: true`）**，巢內糖都在個體嗉囊裡。這是建模選擇，不是生物學結論：本種沒有 replete 證據（#39），但缺乏 replete 證據不能證明其他液體儲存方式不存在，也不能反過來宣稱一定存在。replete 階級、一般嗉囊儲存、巢內液體 cache 是不同命題 | 巢室要等 P1-B；先只有一個 `cache:N00` |
| `body:<individual>` | 已同化的營養 | 工蟻、蟻后、幼蟲各自 | 用於代謝與生長；工蟻的脂肪體儲備沒有本種資料 → 只記帳，不設上限以外的生理參數（`null`） |
| `egg:<id>` | 卵的組成 | 產卵成本 | 由蟻后 `body` 轉入（現有 egg_laying_*_cost） |
| `corpse:<id>` | 死亡個體 | 死亡時嗉囊與身體內的食物 | 由生態模組處理（分解、被吃）；不得消失 |
| `loss` | 代謝消耗、腐敗、溢出 | — | 只能由明確的過程寫入 |

## 4. 轉移事件
每次轉移寫一筆事件：
```
{ type: 'food_transfer', event_id, day, minute | phase, location,
  source: { kind, id }, recipient: { kind, id }, amount_microportions, food_type: 'sugar'|'protein',
  cause: 'collect'|'trophallaxis'|'self_feed'|'feed_larva'|'feed_queen'|'cache'|'take_from_cache'|'lay_egg'|'metabolism'|'death'|'decay'|'overflow',
  contact_event_id? }
```
- **接觸要求**：`trophallaxis`、`feed_larva`、`feed_queen`、`take_from_cache` 都必須有同時同地的接觸（同一巢室、同一時段）；接觸本身有事件 ID。沒有接觸就沒有轉移。
- 現有事件（`food_collected`、`trophallaxis`、`protein_cached_at_nest`、`food_delivered`）保留，並加上 `food_transfer` 的對應 ID，以便觀察器與報表追蹤每一份食物。

## 5. 個體生理（取代全巢分配器）
1. **工蟻**：每日代謝需求 `d_i`（現有參數 × Q10）。先由自己嗉囊支付；不足時，在巢內才可向接觸到的同伴求食（交哺）或到 `cache` 取蛋白；仍不足則記為**個體缺口**（`hunger_days_i`）。外出能量成本（F05）由自己的嗉囊支付。
2. **幼蟲**：只能由保育工蟻實際餵食（接觸機率、每口量；機制：非本種 *S. invicta* R210；數值遊戲假設）。生長速率依自己的攝取量（第三階段設計 #38 的營養係數）；求食訊號依自己的缺口；死亡風險依自己的連續缺口。
3. **蟻后**：只能由工蟻餵食；`body:queen` 的儲備決定產卵能力（候選模型見 #38 §3：批次與暫停）。**移除**以全巢幼體數歸零產卵的上限；是否有密度依賴，以「有來源的局部接觸」候選模型比較，不宣稱自然界沒有密度依賴。
4. **飢餓死亡**：每隻個體依自己的 `hunger_days_i` 計算風險（現有風險曲線形狀保留為遊戲假設，輸入改為個體量）。
5. **全巢帳**：`stores.sugar`／`stores.protein` 變成**由區室加總計算的唯讀統計值**，不再被任何個體決策讀取（靜態檢查＋反事實測試）。

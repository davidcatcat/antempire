## 0. 結論先講

1. **本種有直接證據的只有「存在」與少數「型態／時程」**：
   - 雄蟻、gyne、多蟻后都確實存在；
   - 28°C 下繁殖蟻的前蛹 4.16 日、蛹 12.31 日（雌雄合併）；
   - 蟻后成批產卵後暫停；
   - 同巢多隻產卵蟻后（實驗室每群 2～7 隻；野外單巢最多 71 隻）。
2. **以下全部沒有本種定量資料**（本輪擴大搜尋後仍找不到同儕審查的一手研究）：
   - 怎樣的雌性幼蟲變成 gyne；蟻后何時產未受精卵；
   - 交配發生在哪裡、成功率；雄蟻壽命；精子量；
   - 婚飛的觸發條件與季節；分巢的頻率、組成與距離；
   - 臺灣（臺中）的繁殖季節與方式。
3. 因此**現在不能做出「會自己生雄蟻、新后並分巢」的引擎而仍宣稱有本種依據**。可以做、而且應該先做的是：
   - 讓**資料結構與事件帳**能正確表示多蟻后、性別、繁殖路徑、交配與巢的關係（行為不變）；
   - 讓每一個繁殖機制都是**獨立開關**，沒有證據就預設關閉；
   - 關閉時的行為與現行引擎**逐位元組相同**；
   - 打開時只在 Day0 實驗世界、搭配敏感度範圍運作。
4. **依賴很深**。繁殖子系統必須排在下列各項之後：
   - 個體營養（工作包 C2～C4）、生命史（P3-1、P3-4）、兵蟻分化框架（P3-5）；
   - 巢穴空間（P1-B）、24 小時時鐘（P0-A，婚飛需要逐時天氣）、多群共用時間軸（A09／A10）；
   - 以及**陣列順序不變性**：PR #52 的獨立審查發現工蟻陣列順序仍會改變個體命運。
   - 先做繁殖會讓「全巢平均」與「陣列順序」的缺陷放大到繁殖蟻身上。
   - 這和現行 Roadmap 把繁殖排在第 7 位一致。
5. **PR #53 的報告整體正確、措辭謹慎**。本輪找到 **14 項需要更正或補充**（§1.2），其中較重要的是：
   - Yuan 2026 的繁殖蟻發育時程是「組合值」；
   - Fournier 2012 的「有效 1～4 隻蟻后」建立在**未測量的單次交配假設**上；
   - UF/IFAS 引用 Vanderwoude 2000 的「澳洲只分巢、無婚飛」在原文摘要中查不到；
   - 漏列了 repo 已有的 R137～R140、R167、R216 等直接相關文獻，其中包括本種**單后創巢（haplometrosis）的實驗室證據**，與「只靠分巢」的印象相反。

## 2. 機制依據矩陣（PR #53 §10 第 3、9 項）

三類：**可實作**＝本種有資料，數值可用並附外推限制；**候選機制**＝機制有本種或他種支持，但沒有本種數值，只能開關＋敏感度範圍；**暫不啟用**＝缺乏證據或與證據衝突。

### 4.4 設計概念

- **湧現**：「大巢才產繁殖蟻」只能由「每隻幼蟲實際被餵的量」湧現，**不寫成以人口數為條件的 if**（與 P1-A §5.1 相同原則）。不能讓個體讀全巢人口。
- **感知**：雄蟻與 gyne 只感知所在巢室與出口的局部環境；交配對象只能是實際接觸到的個體；婚飛只看自己所在出口的逐時天氣。
- **隨機性**：每個抽籤都用以**個體 ID 為名**的串流（例如 `mating:<gyne_id>:<minute>`），從候選集合中抽出時，候選依 ID 正規化（PR #52 的作法），不依陣列位置。
- **觀察**：觀察器可顯示 `fertilized`、`caste_path`；`sire = 'unknown'` 要顯示為未知，不顯示成「無父」。

### 4.5 初始化
- Day14 正式世界：Q001 的 `spermatheca.mated = null`；既有幼體 `fertilized = null`、`caste_path = 'undetermined'`；**不回填**（CLAUDE.md §1）。
- Day0 實驗世界：蟻后數只能由**有本種依據的情境**指定（例如 2～7 后的南寧巢片段，R94）。不能為了測試多后而選「最好看」的數字。
- 新版正式 Day0 的創巢方式是 Owner 的 D4 決策，本文不決定。

### 4.6 事件與守恆（PR #53 §10 第 4 項）

**每日人口帳**（每巢、每殖群；分開檢查，不得合併）：

```
工蟻(期末)     = 工蟻(期初)     + 羽化(worker)                  − 死亡 − 遷出 + 遷入
雄蟻(期末)     = 雄蟻(期初)     + 羽化(male)                    − 死亡 − 離開模擬區域 − 遷出 + 遷入
未交配gyne     = 期初 + 羽化(gyne) − 交配 − 死亡 − 離開模擬區域 − 遷出 + 遷入
已交配gyne     = 期初 + 交配 + 由外返回 − 去翅/接納 − 死亡 − 離開模擬區域 − 遷出 + 遷入
產卵蟻后       = 期初 + 接納                                    − 死亡 − 遷出 + 遷入
幼體(各路徑)   = 期初 + 產卵 − 羽化 − 死亡 − 被吃 − 遷出 + 遷入
Σ遷出(巢 A→B)  = Σ遷入(巢 B←A)                                   # 分巢搬運守恆
```

- **ID**：每類成蟲用參數提供的前綴與計數器；羽化時依來源蛹 ID 順序分配（沿用 v2-review.21）；唯一性檢查涵蓋所有類別與所有巢。
- **事件必填**：`id`、`day`、`minute`（有 24 小時時鐘後）、`location`（巢室或地點）、`source_event`（例如 `eclosion.source_brood_id`、`mating.male_id`）。
- **營養**：雄蟻、gyne 的 `body` 與 `crop` 納入工作包 C 的區室帳；離開模擬區域的個體連同其體內食物一起記為 `exported`，不是消失。
- **族譜**：`mother_id` 由產卵事件得到；`sire` 只能由模擬中實際發生的 `mating` 事件得到，否則為 `'unknown'`。**不捏造族譜**。

## 5. 候選架構（PR #53 §10 第 7 項）

| | **方案 A：全個體** | **方案 B：等價世代群（cohort）** | **方案 C：混合** |
|---|---|---|---|
| 內容 | 每隻雄蟻、gyne、蟻后都是一筆個體紀錄（與現行工蟻相同） | 同日、同巢、同路徑、狀態相同的幼體或成蟲合成一群；發生個體事件時分裂 | 成蟲（蟻后、gyne、雄蟻）全個體；卵與早期幼蟲用世代群，進入敏感期時展開成個體 |
| 局部因果 | 直接，與現行工蟻一致 | 需要證明「群內抽籤等價於逐隻抽籤」 | 成蟲部分直接；幼體部分同 B |
| 守恆與 ID | 簡單 | 群的分裂與合併要另外守恆；ID 延後分配 | 中等 |
| 計算量 | 隨個體數線性；繁殖蟻只在大巢出現（R167），大巢時工蟻本來就多 | 最小 | 中等 |
| 驗證能力 | 最好：每隻都可追蹤 | 必須另寫「A 與 B 的統計等價」測試（不是逐位元組） | 中等 |
| 資料缺口的影響 | 同 | 同 | 同 |
| 風險 | 大巢時存檔變大 | 等價性證明若失敗，會讓群平均偷偷取代個體生理（違反 §2.1b） | 兩套邏輯的邊界錯誤 |

**建議：先做方案 A。**
- 理由一：現行引擎所有工蟻都是個體，維持一致。
- 理由二：在目前的人口尺度下沒有效能問題。
- 理由三：等到 A 的測試完備後，B 或 C 可以作為「必須證明統計等價」的效能最佳化另案處理，而不是起點。

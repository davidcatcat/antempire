# 可視化技術設計

> 工作四。第一版（MVP）已在 #35 實作；本文件說明技術選擇與之後的擴充方式。
>
> **2026-11-02 修訂（科學真實性最高原則）**：
> - 可視化的任務是**觀察，不是創造事件**：畫面上的每隻螞蟻、每次移動、搬運、築巢、死亡都來自引擎狀態與事件；插值只改善流暢度。
> - 與科學正確性衝突時，**科學優先**：沒有引擎資料的行為（例如巢室、戰鬥）不畫；蟻群沒出巢就呈現沒出巢。
> - 畫面與引擎**共用同一套世界空間資料**（§5）；不由畫面決定距離。
> - 玩家**只觀察**；玩家干預已移出產品需求，介面不提供任何改變世界的操作。
> - 正式資料來源：Day14 是舊版過渡資料；未來讀取**新版正式 Day0 世界**的時間軸格式（§3），不再以 Day15 日誌為目標。

## 1. 分層與責任
| 層 | 位置 | 責任 | 不可以 |
|---|---|---|---|
| **模擬引擎** | `engine/` | 世界演化、螞蟻行為、生態、亂數種子、事件、守恆 | 知道畫面的存在 |
| **世界狀態／事件時間軸** | Node 匯出：`cli/web-export.ts` → `web/data/*.json`；未來加上新版正式世界的時間軸讀取器 | 把引擎實際產生的狀態與事件，原樣交給畫面 | 新增事件、修改數值 |
| **畫面渲染** | `web/src/main.ts` | 把狀態與事件畫出來 | 決定螞蟻行為、產生事件、執行模擬 |
| **玩家介面** | `web/index.html`、`web/src/main.ts` | 選取、鏡頭、時間軸、圖層、資訊 | 寫回存檔；在正式世界改變任何狀態 |

### 1.1 三種資料必須分清楚
1. **真實引擎事件**：例如 `worker_activity` 片段、`route_step` 到達時刻、`food_collected`。原樣顯示。
2. **由已知事件推得的顯示插值**：例如兩個 `route_step` 之間的位置、巢口附近的排列位置。只用於畫面，被選取時標示，不寫回引擎（`tests/web.test.ts` 驗證）。
3. **示範用假資料**：MVP **沒有**使用。日後若需要（例如教學動畫），必須在畫面上明確標示「示範」，而且不能和真實世界放在同一個模式。

## 2. 技術選擇
| 方案 | 優點 | 缺點 | 結論 |
|---|---|---|---|
| **Canvas 2D** | 零依賴；手機瀏覽器全支援；可直接重用 TypeScript；易於測試與維護 | 上萬個物件時效能有限 | **MVP 採用** |
| **PixiJS**（MIT） | WebGL 批次繪圖，可畫大量螞蟻；有 Canvas 退路；AntSim V2 的實作可參考 | 多一個依賴；版本升級成本 | 螞蟻上千隻、要做貼圖與動畫時加入，只換渲染層 |
| Phaser | 完整遊戲框架 | 物理、場景系統與我們的引擎重疊；較重 | 不採用 |
| Godot | 編輯器強、3D 與體素 | 不能直接用我們的 TypeScript 引擎；網頁輸出大；anthill 的 GPL 程式不可借用 | 不採用 |
| 3D（three.js 等） | 立體感 | 目前不需要 | 暫不考慮 |

## 3. 資料介面
- **`web/data/index.json`**：列出正式快照與實驗世界。
- **`official-day14.json`**（`antempire.web.official-snapshot.v1`）：
  - 地點：方位、約距離、推得的示意座標；
  - 紀錄的路線；
  - 每隻工蟻的狀態、死因、地點序列與紀錄活動；
  - 蟻后、幼體；
  - 讀取的存檔雜湊。
- **`experiment-<id>.json`**（`antempire.web.experiment-replay.v1`）：
  - 情境、種子、引擎版本、規則指紋；
  - 地圖：地點、路段與已知長度；
  - Day0 狀態，以及每一天的天氣、任務、收支、事件（含 `worker_activity`、`route_step`）與日終狀態。

**之後要加的**：
- **新版正式世界的時間軸讀取器**：新版正式 Day0 由科學引擎初始化後，每日事件以機器可讀格式保存（格式在正式 Day0 規格中定義），觀察器直接讀取。原本規劃的「Day15 以後讀 `journal/v2-day-NNNN.md`」已不是目標（Day14 為過渡資料）；
- 正式與實驗資料**分開的檔案、分開的 schema 名稱與畫面標示**，測試確認不混用；
- 大量資料時，每日事件分檔，依需要載入。

## 4. 事件重播
- 畫面不跑模擬，只讀已提交的時間軸。
- 時間軸有「日」與「分鐘」兩層。播放速度只影響畫面；同一份資料永遠重播出同一個結果。
- **個體位置** `poseAt(day, worker, minute)`：
  - 在 `route_step` 記錄的到達時刻，位置正好在節點上；
  - 兩個紀錄點之間線性插值（顯示用）；
  - 沒有外出紀錄的工蟻畫在巢內。
- **事件清單** `eventsUntil(day, minute)`：只篩選已有的事件。沒有分鐘的事件（死亡、羽化等日終處理）在時窗結束後才顯示。

## 5. 座標與比例尺
- 世界目前只有「方位文字（8 方位）＋約距離（cm）」，並註明「敘事近似值非實測」。
- 示意座標：x＝sin(方位)×距離、y＝cos(方位)×距離，原點是主巢入口。畫面標示「示意比例：方位＋約距離，非測量」。
- 沒有方位或距離的地點（U00、U01、N01、N02）放在畫面角落的「位置未記錄」區，不放進比例尺內。連到它們的路線畫成虛線。
- 同一方位的多個地點會落在同一條線上（例如東南的 F05、F06、F09）。這是資料的真實樣子，不加入虛構的偏移；只有文字標籤可以錯開。
- **共用空間資料（P1-B 第一部分，規劃中）**：建立一份**明確標示為情境假設**的花園空間資料（cm 座標、地點、路徑折線、障礙、地表、遮蔭與排水介面、來源標示），引擎與畫面讀同一份。路徑長度必須與引擎已記錄的路段長度一致；**不為美術效果改變既有移動距離**；位置未知的地點維持「未知」並標示。

## 6. 目錄
```
cli/web-export.ts        Node 唯讀匯出（引擎 → web/data）
cli/web-serve.ts         本機靜態伺服器（只回應 GET）
web/index.html           頁面與樣式
web/src/model.ts         純函式資料模型（Node 可測）
web/src/main.ts          Canvas 2D 畫面與介面
web/data/*.json          已提交的匯出資料（引擎版本改變時重新匯出）
web/dist/                編譯輸出（不進 git；由 `npm run web:build` 產生，見 §9）
tests/web.test.ts        CI 測試
tests/browser/*.cjs      本機瀏覽器檢查（Playwright）
```

> 非正式實驗模式（Owner 決策 #39）：持續運作的實驗世界由獨立的 Web Worker 執行，`web/src/` 只經 Worker client 以訊息連接；邊界與白名單見 [`experimental-worker-boundary.md`](experimental-worker-boundary.md)。正式觀察模式的規則不變。

## 7. 測試策略
- **CI**（`tests/web.test.ts`）：
  - 匯出可重現；已提交資料＝重新匯出；
  - 正式快照＝存檔個體；
  - 事件全部來自引擎；
  - 插值在紀錄點上準確且不產生事件；
  - 畫面不匯入引擎、不執行模擬、不寫入、不用亂數；
  - 存檔與日誌雜湊不變。
- **本機瀏覽器**（`tests/browser/web-viewer.check.cjs`）：
  - 桌面與手機視窗、觸控、高 DPR；
  - 點選、移動中工蟻的選取、巢內視角、無頁面錯誤；
  - 截圖保存在 PR 證據。
- **之後**：視覺回歸（截圖比對）、無障礙檢查、效能（上千隻螞蟻的幀率）。

## 8. 引擎需要額外提供的狀態與事件（依可視化 Roadmap 排序）
1. **巢的空間結構**：巢室、通道、深度與容量；挖掘與修繕事件；個體在巢內的位置。
2. **花園布局情境**：所有路段的長度與幾何，至少要明確標示為情境。
3. **逐時天氣與日夜**（第二階段設計 A）。
4. **其他生物的個體**：掠食者、其他蟻群工蟻，以及相遇事件。
5. **幼體的位置與照護事件**：哪隻工蟻在什麼時候餵了哪隻幼蟲（目前只有接觸訊號）。
6. **新版正式世界的完整事件保存格式**：讓觀察器能可靠讀取正式世界的每一天（屬於新版正式 Day0 規格）。

## 9. 建置與部署
- `web/dist/` 是 `web/src/*.ts` 的編譯產物，**不進 git**（`.gitignore`）。曾兩次被 `git add -A` 誤加入提交（#34 已移除；#36 本次移除），原因是本機建置後未被忽略。
- 產生方式：`npm run web:build`（`tsc -p web/tsconfig.json`）；`npm run web` 先建置再啟動本機伺服器。
- CI：型別檢查涵蓋 `web/`；瀏覽器 smoke test 在 CI 中自行建置後執行（#35）。
- 部署（尚未啟用，是否公開由 Owner 決定，統一需求 D5）：建議由 CI 在 main 合併後建置 `web/` 並上傳為靜態網站（例如 GitHub Pages 的 Actions 部署），建置產物只存在於部署流程，不提交到 repo。

## 10. 觀察尺度
整體生態、蟻群、巢穴、單隻螞蟻、特定生態事件。所有尺度讀同一份世界狀態與事件；切換尺度只改變鏡頭與篩選，不產生不同的結果。巢穴尺度要等引擎有巢穴空間（P1-B）。

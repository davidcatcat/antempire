## 0. 缺陷重現（#144 第 1 項；先寫測試，3cad90e 上失敗）

`tests/wp5-camera-invariance.test.ts`（初版 commit 13b32cd，斷言「有無鏡頭結果相同」，在 3cad90e 上**失敗**）：

| 重現 | 做法 | 3cad90e 結果 |
|---|---|---|
| R1 `lifetime.ts` | 40 隻成蟲的格（8 個已知 ID）；第 3 日鏡頭升級一隻已知 ID、第 6 日降級；同種子、同參數、同流入 | 10 個種子共 **38 個已知 ID 的死亡日不同**；例：`issue144-r1-1 K0` 無鏡頭第 20 日死、有鏡頭第 16 日死 |
| R2 `ledger.ts`（OD-1 v1） | 6 隻名冊成員；每日一次自然的群組死亡；第 2 日升級、第 3 日降級 | **4／10 個種子**後續自然死亡帶走的 ID 不同；例：`[A3,A2,A1,A0]` 對 `[A3,A1,A2,A0]` |

**原因**：舊表示中，個體以 ID 為亂數鍵，群組成員以「格鍵＋格內序號」為鍵（`lifetime.ts`），或以「命令鍵＋名冊排序位置」抽選（`ledger.ts`）。表示一改變，同一隻生物就換了一條亂數路徑；只在**分布**上一致——Owner 不接受。

目前測試把 R1／R2 改為**釘住缺陷**（以自然原因升降級，差異必須仍存在），並驗證退路（§4）。

## 1. 解法：逐成員連續性（#144 第 2 項）

**核心**：每一隻生物都是有**穩定 ID** 的成員；所有隨機性以 `(種子, 過程, 日, 成員 ID)` 命名；群組只是**壓縮儲存**；「以個體顯示」是**玩家視角**，不屬於權威狀態。

| 元素 | 內容 |
|---|---|
| 成員 ID | 已知 ID（如 `X-moth-1`），或**潛在 ID** `<群組ID>#<序號>`：在成員產生（出生、初始、遷移）時就固定，與之後如何儲存無關。卵的序號依同日同區同群組的**親代 ID 排序**決定 |
| 每成員亂數 | `draw(seed, process, "日|ID")`，`process ∈ {feed, lay, develop, death, age-bin, migrate}`；計數器式雜湊（無狀態、與順序無關）。成員不論單獨存放或在群組裡，抽到的數都相同 |
| 有競爭的過程 | 進食（存量有限）與自然遷移（選 n 隻）：所有合格成員依自己的具名亂數排序，取前 k 隻（同值以 ID 決勝）——結果只取決於成員集合，不取決於分組 |
| 群組列（group） | 同一群組身分、權威狀態完全相同（區、齡期、子期、年齡模式、年齡、**每隻精確儲備**）的成員；只是壓縮 |
| 紀錄 | 依「事件種類＋事件前的權威狀態鍵」彙總，成員以壓縮 ID 範圍列出——也與分組無關 |
| 玩家視角 `view.individual` | 哪些成員被畫成個體。**沒有任何規則讀取它**；它只改變單日步驟內的儲存配置（被看的成員以單獨一列處理，確實走「個體」路徑） |

**證明（構造＋測試）**：
1. 每條規則對每個成員的結果只依賴「該成員的權威狀態＋以其 ID 命名的亂數」，競爭過程只依賴「合格成員集合及其各自亂數」。這兩者都是**成員多重集合**的函數，與分組無關；紀錄以權威狀態鍵彙總、期末依狀態鍵正規化合併，所以輸出也是成員多重集合的函數。視角只改變分組 ⇒ 有無視角、任何升降級序列的**權威輸出逐位元組相同**。
2. 測試 C1：3 情境 × 6 種子 × 2 個隨機鏡頭（每日 0～5 次隨機升級／降級，自己的種子）× 30 日，含兩區之間的自然遷移：**36 對、2 656 次視角操作、5 797 個成員的命運**；每日紀錄、每日權威狀態、逐成員命運表全部**逐位元組相同**；每日都通過獨立稽核。
3. C3：把儲存列隨機切碎（任意個體／群組配置）→ 逐位元組相同。C4：輸入陣列順序反轉 → 相同。對照：換種子則不同（比較不是空的）。
4. C1 內每次視角操作後，權威部分逐位元組不變、身分集合不變（升降級身分守恆）。

**代價（如實）**：路徑層級不變要求每個成員每個過程每日一次抽樣：計算量 O(N)，與逐隻個體相同（`lifetime.ts` 的群組原本也是逐隻抽 Bernoulli，所以沒有變慢）。群組只省下共享狀態與紀錄的儲存；在 rich 情境一次 60 日示範執行中 411 隻分在 217 列（儲備與年齡很快分化，壓縮有限）。比「抽計數」更省的方法在數學上無法保證逐個體路徑不變。

## 2. 單一權威帳本（#145 第 12 題）

`unified.ts`（schema `antempire.wp5-unified-ledger.v2`，`authoritative: true`）＝OD-1 帳本第 2 版：

- **穩定群組身分** `CohortIdentity { cohort_id, taxon, colony_id, origin }`：出生群組為 `K.<日>.<區>.<分類群>.<蟻群>`；**不含齡期**。齡期是群組列的欄位；轉換由 `transition` 紀錄（`stage_change`、To/Ti 數量帳、體內質量轉帳）。稽核 U7：群組身分一旦建立不可改變或消失；新群組只能來自出生紀錄。
- **人口、食物、物質同一帳本**：數量帳 B/D/I/E/Ti/To（區×分類群×齡期×蟻群）；質量帳 `stock:<區>`、`body:<區>:<齡期>`、`sink:respiration`、`corpse:<區>`、`producer:inflow:<區>`。
- **`lifetime.ts` 只負責計算**：`canFeed`、`devProb`、`canLay`、`hazardOf` 由 `lifetime.ts` 匯出，`unified.ts` 呼叫並記帳，自己不保留副本（測試 L2 掃描原始碼）。`lifeDay`／`LifeState` 降為**比較引擎**，不再是權威人口帳。
- **同一個體不得存在於兩套模型**：同一帳本內，一個 ID 只能在一列（U1）；跨帳本由 §3 的遷移與 `checkSingleAuthority` 把關。
- **獨立稽核** `unified-audit.ts`（不呼叫步進）：U1 形狀／重複 ID／存活又退休／視角只顯示存活且精確的成員；U2 數量；U3 每個質量帳戶與全世界總量；U4 身分（無紀錄消失、無紀錄出現、復活、ID 重用）；U5 逐成員（精確年齡每日 +1、粗格 +0/+1、不倒退、群組不變）；U6 老化紀錄；U7 群組身分。故意破壞的 9 種版本全被抓到（測試 A）。

## 3. 相容與遷移（舊群組逐步淘汰）

| 來源 | `unified-migrate.ts` | 無法得知的量 |
|---|---|---|
| OD-1 v1 `ledger.ts`（群組 ID `C|區|分類群|齡期|蟻群`） | 每個舊群組 → `K.v1.<n>`（`alias` 記錄舊 ID）；名冊 ID 保留為已知成員；匿名成員得潛在 ID；個體 → `K.v1.i.<id>` 的已知成員；合計區室依 OD-1 規則（逐隻 floor 份額、最後一隻拿餘數）拆成每隻儲備，紀錄註明為**近似** | 年齡：v1 沒有 → 必須由呼叫者提供並附依據，否則 `MIGRATION_AGE_UNKNOWN`；Erlang 子期：記為 0（遷移假設）；其他非零區室：拒絕 |
| `lifetime.ts` `LifeState` | 個體保留 ID；名冊保留精確年齡；匿名格成員得潛在 ID；`exact` 模式無損 | `pooled`／`mean-field` 拒絕（沒有每隻精確儲備） |

遷移時檢查數量與質量守恆；回傳的舊狀態加上 `superseded_by`，舊步進（`runDay`、`lifeDay`）拒絕執行（`SUPERSEDED_BY_UNIFIED_LEDGER`）；新狀態的 `migrated_from` 記錄舊狀態指紋。`checkSingleAuthority` 對沒被取代的舊狀態回報 `DUAL_PRESENCE <ID>` 與 `UNMIGRATED_LEGACY_POPULATION`（測試 L3：17 隻各出現一次、各齡期數量一致、質量一致；L4：lifetime 狀態無損遷移）。

## 4. 退路（#144 第 3 項）：仍依表示而變的部分不准由畫面觸發

- `ledger.ts` 與 `lifetime.ts` 的 `promote`／`demote` 若原因來自觀察者（`camera`、`view`、`zoom`、`follow`、`observer`、`player` 或驅動事件以 `view:`、`camera:` 開頭）一律拒絕：`VIEW_CANNOT_CHANGE_RESOLUTION`（測試 R1、R2 釘住）。
- 統一帳本中，視角不能提高精度：粗年齡格成員不能被「看成個體」（`VIEW_CANNOT_CHANGE_PRECISION`）；觀察者原因也不能當成自然遷移（`VIEW_IS_NOT_A_NATURAL_EVENT`）。

## 5. 精度（#145 第 11、14 題）

- **exact 是預設**（`defaultPrecision()`：精確儲備、日齡）。**pooled 不是權威精度**：`PRECISION_POOLED_NOT_AUTHORITATIVE`。儲備直方圖另開 Issue。
- **已知 ID 與粗年齡格共存**：同一群組內，已知 ID 保持精確年齡（每日 +1，U5 檢查），匿名成員可用 W 日的粗格（每日以 1/W 機率進下一格，以 ID 命名抽樣）；`exact_age_colonies` 中的蟻群新生個體一律精確年齡。這取代了 OD-1b 的永久拒絕（`ROSTER_NEEDS_DAILY_AGE_BINS` 仍在舊 `lifetime.ts`，只作比較引擎）。不會為了壓縮刪除已知 ID 或其精確年齡。
- **自然原因把粗格成員升為精確年齡**（需要抽一個格內年齡）**尚未實作**；目前只能維持粗格。

## 7. 三類未驗證數量（#145 第 10 題）

保持「**未驗證**」，不得視為已通過驗證，也不為了帳本閉合而編造來源。本原型中它們仍是命令輸入或明列的規則：

| 數量 | 本原型現況 | 負責提供驗證規則的模型 |
|---|---|---|
| 生產量 | `inflow` 是情境輸入（`free_input`） | 世界生態與物種生產模型 |
| 轉移量 | 進食一餐、遷移的質量隨成員移動（規則明列）；其他轉移未建模 | C2／OD-1 統一事件帳本 |
| 出生時的食物分配 | 每卵 `egg_cost`（遊戲假設） | C3／C4／C5 個體營養與生命史模型 |

## 8. 四類結果（分開陳述）

4. **使用者可見**：沒有。原型未接到觀察器或正式世界。

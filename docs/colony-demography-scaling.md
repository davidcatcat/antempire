# 蟻群人口、完整生命史與大規模自治模擬｜科學規格 v1

> **這是跨14隻、100隻、1000隻乃至更多個體的統一規則，不是14隻限定的劇本。** 本文件為機制設計及未來存檔契約，並不代表已有執行中的軟體引擎。研究更新只影響往後的模擬，不推進Day6／144h，不修改既有14隻工蟻或E001/L001/L002的生理年齡。

## 1. 核心科學依據與界限
- **物種**：本世界使用熱帶大頭家蟻 `Pheidole megacephala`；2026年廣西直接研究R94記錄28±1°C、70±5%相對濕度下，非繁殖型卵→成蟻平均28.73±2.83天，雄蟻／gyne等繁殖型37.60±3.20天；非繁殖幼體的發育有明顯不同步。
- **成年工蟻壽命**：R94新羽化小工蟻n=104平均26.25日，大工蟻n=14平均56日；Kaplan–Meier中位數分別28與70日。這是特定實驗條件、右設限及樣本資料，不是每隻工蟻的死期，也不能當成台中N00精確風險率。大工蟻樣本小，不宣稱精密外推。
- **物種成群擴張**：R94觀察到批次產卵、多個世代重疊與多蟻后殖群；R116的P. megacephala研究使用含數千工蟻的實驗存量殖群。因此「14隻即設計上限」、「100隻會停止繁殖」都不具科學基礎。主巢現只有**已確認Q001**，不能因工蟻超過100就自動加一位蟻后。
- **分工**：R115討論形態階級與年齡分工如何受任務效率、外勤死亡風險影響；R107描述本種major/minor功能差異。分工可以因勞力缺口、社會刺激改變，成年major不會變minor，巢內育幼者也不保證是minor。
- **證據標籤**：`direct_taxon_lab`、`other_ant_mechanism`、`model_assumption_uncalibrated`、`simulation_event`、`unknown`。模型比率不能冒充野外實測。物理mg、卵受精狀態、巢溫、真實未知年齡都不能強行填值。

## 2. 不限人數的群體帳本（唯一人口權威）
- `colony_id` 可以有一個或多個巢節點；每個殖群用權威聚合帳追蹤 `queens_alive`、`workers_minor_confirmed`、`workers_major_confirmed`、`workers_subcaste_unknown`、`males_alive`、`gynes_alive`、`eggs`、`larvae_by_instar_or_unknown`、`prepupae`、`pupae`、`dead_cumulative`、`emigrated`、`immigrated`。總工蟻以**已確認minor + 已確認major + 未鑑定形態**相加，不可再把major重算成額外「兵蟻」。
- 每個個體有**穩定且唯一**的生涯ID；卵→幼蟲→蛹→成蟻可關聯到同一生命紀錄，既有E001/L001/L002/W004–W017保留原ID及既有寫法，遷移時用不可逆對映而非重編。新增子群需要獨立 `colony_id`、`nest_id`、移入/移出事件，不能跨群重複計算。
- 計數與個體不平行各自發明：`aggregate_count = tracked_alive_explicit + compact_cohort_alive`；任何ID只屬於其中一方。總巢群與各巢/子巢統計必須由相同權威記錄投影，不能把巢間移動當出生。
- 發生真實新增、離巢、死亡時必須有唯一事件ID、原因與時間窗；未知死因記 `unknown`，不能推成「老死」。死亡個體不可再出勤，已死個體歷史事件永久可查。

## 3. 儲存策略：小群逐一、成長後個體+世代批次混合
- **1–100/數百隻**：可保留每隻已知成體精簡ID／出生日期／形態／健康／位置／任務記憶參照；只記發生改變者或值得觀察者的事件，不為每一隻每天編造出勤故事。
- **數百至數千**：活躍出勤、有接觸/傷病、被研究的工蟻保留詳細個體狀態；其他依**同一產卵批次、相似發育階段、形態證據、巢區與環境暴露**暫做`cohort`批次表，記 `count`、日齡或未知齡分布、營養/照護需求區間。批次中的個體是邏輯存在，而非無ID的虛構加成；需個體互動時才按穩定規則展開 `cohort_id+slot` 索引，展開前後總數不變。
- **數千～更多**：世界與資源仍按地圖/巢節點獨立更新，交通/分工/活動用有限容量的局部流量與各群落計數；重要碰撞、被捕食、分食、特殊個體可在合法時窗解包逐一模擬。儲存採稀疏欄位、事件分片與聚合快照，**不能把上千個體的逐分鐘行為塞進單一超大JSON**。
- **不是按數量硬切生物學規則**：模式切換只為計算/儲存效率，必須可逆地把指定個體展開，並維持總量、身分、活動時間與因果關係。100、1000僅為效能測試情境，不是生物階段/強制招募/死亡/分巢閾值。實際門檻依存檔大小與可驗證性調整。

## 4. 生物時鐘：從卵到死亡的狀態與風險
- `egg → larva_instars_1_2_3_or_unknown → prepupa → pupa → adult_minor/major/male/gyne_or_unknown → dead_or_emigrated`。在缺少實際辨識能力時，可以保留 `larva_unknown` 或 `adult_worker_subcaste_unknown`，但不能跳過階段。
- 每筆卵/批次保留母后ID（若無法辨識則null）、產卵時間（如果未知則null）、形態/性別命運（未證實則null）、已過的**可確定模擬日數**與無法回溯的真實生理年齡null。跟蹤同批個體的**發育分布**，不是全部到第29天突然一起羽化；R94同批化蛹可跨約9天。
- 有適當巢室微氣候、營養供給與發育資料時，根據條件式階段轉換分布抽樣；無現場溫濕或孵化時點不得從城市預報代算巢內degree-days。可設定標示清楚的假設情境，但需避免假裝是測得的發育率。
- 成年工蟻死亡採 **年齡／形態／傷勢／接觸風險／飢餓或缺水／感染證據** 分層。年齡風險建議從有來源的分階段生存函數 `S(age | caste, environment)` 估條件期間風險 `p=1-S(a+Δt)/S(a)`，而不是拿1/26.25或1/56直接當每日死亡率，也不是達到平均天數就處死。**這個函數目前未校準：不得填一條假精準曲線。**
- `age_unknown` 不是 `age=0`、不是永遠不老。對現有14隻只記**從目前存檔開始的已知觀察時間**與已知暴露；老化的未知過往要以可辨識的不確定性/敏感度情境處理，未驗證不得回填年齡。
- 死亡兩段因果：實際場域接觸→攻擊/中毒/逃脫/傷病或疾病發展；基底自然生存/老化另算。**同一個體同一時窗最多死亡一次**。未發生接觸不能宣稱被蜘蛛吃掉；一日死亡0也是有效輸出。

## 5. 不只是工蟻：蟻后、出生、資源、巢室、外界
- 產卵不是「現在14隻→每天只下一顆」，而是由**每一位已確認產卵蟻后**的生理/營養/微氣候/批次週期決定，可能一批很多顆、也可能連日0顆。R94引用舊實驗單后31天97–292顆，**不能直接換算N00每日固定3–9顆**。
- 同時存在不同齡幼體與新羽化工蟻。生殖分化/雄蟻/新后要有季節、巢群營養、個體發育與性別證據；100隻不是「自動出雄蟻/新后」的開關。多蟻后與分巢是有條件的後續事件，不因殖群長大而憑空生成Q002。
- 成長需要食物、飲水、氧氣、幼體照護能力、巢室空間、衛生/垃圾場與足夠採集路線。容量限制影響產卵/發育存活/挪動與出勤，可能出現飢餓、停止成長、擁擠、分巢或衰亡；缺物理量時不得用固定「每隻每天糖−1」判死。
- 各巢工蟻依**局部刺激/接觸/招募**決定採食、育幼、守衛、清潔與休息；彙總任務人數是行為結果，不是中央蟻后分派。人口增加時，流量、食源耗竭、擁擠、病原接觸網與生態競爭自然變動，但不強迫每一天有戰爭。

## 6. 多尺度模擬順序、隨機性及效能
1. **外界**：依有來源的天氣/季節，獨立更新植物、蜜露、天敵、他巢、土壤與虛構人類事件（即使本巢整天不出門）。
2. **巢區/勞動**：依現有工蟻局部可及性與需求決定休息/照護/採食/警戒/工程。高密度群體先解局部容量/交通，再安排真實可行的時窗；不讓同一隻在同時出現在兩個位置。
3. **接觸與活動**：重要對外移動、敵我接觸、取食、搬運、口對口分食由唯一事件ID記錄；其餘無需逐隻生成無意義文本。
4. **食物與環境結算**：外部收入只入帳一次，分食/倉庫挪動只屬內部轉移；依實際可用資料或明確標註的未知值評估成本和幼體需求。
5. **生命更新**：蟻后可能批次產卵；各已存在卵/幼蟲/蛹依階段/條件/齡級異步轉換；成蟻年齡及健康風險結算；死亡/離巢/分巢/移入各記唯一事件。
6. **稽核與存檔**：依殖群、巢節點、形態、幼體階段逐級守恆，保存種子/模型版本/條件抽樣/不確定性。日誌只突出代表性可證因果事件，完整總量與匿名批次摘要記錄在權威人口帳。
- 20分鐘分格適用**需要接觸與位置驗證的事件**，不必讓成千上萬隻每日72次全員逐隻寫行為。對沒有接觸/位置變化的個體可採有界聚合推進；抽樣分流基於**獨立事件/個體/批次ID衍生seed**，避免總數增加就改寫已存在工蟻的既有隨機結果。
- 對同質批次的階段轉換/死亡可做**有條件二項分布**抽樣，但僅在有合法的分層機率資料、獨立性前提或經驗校準時。共通災害、傳染及社會接觸具關聯性，不可當成獨立伯努利硬抽。
- 長期運行使用**快照＋增量事件日誌＋種子/版本**；必須可從已封存的快照推算當天數量。不要每天把幾千個沒有改變的個體完整複製到日誌。

## 7. 必測擴張案例（規格與未來模擬器的驗收）
| 情境 | 期待結果 |

| Day6目前14工蟻 | Q001=1、活工蟻14、E001卵1、L001/L002幼蟲2、六隻舊傷；不回填成年形態/真實年齡，不推進時鐘 |
| **假設**100成蟻，40卵/35幼蟲/25蛹 | 各巢/形態分帳、連續生命階段與死亡風險可算；沒有因跨100而額外生后/婚飛 |

## 8. 與當前Repo的相容性及實際落地順序
1. **本次只寫規格，不更動主存檔/世界狀態/Day6日誌；下次被命令「繼續」才會推進。** 目前`saves/main.json#/colony/workers/individuals`為17個歷史成體（14存活/3死亡）的逐一名冊；`#/colony/brood/individuals`為3幼體。舊資料保持唯一權威。
2. 未來若開始大量產卵：先增加`population_demography`新權威分帳與`cohorts`層，將舊名冊視為`explicit_individuals`，用明確遷移版本升級，而不是另做一份重複計數的成人群。全群大於100後也不要反覆擴寫`foraging_economy.worker_states`等每工蟻全欄位字典；將必要場景狀態搬到稀疏個體／巢區事件索引。
3. 只有**實際新卵事件**才能新增出生批次；僅當合法羽化事件才增加成蟻。保存出生、孵化、蛹化、羽化、死亡、遷入/遷出及形態分帳事件；生命史可追蹤到`cohort_id+slot`。保留已有ID外觀並避免ID撞號。
4. `main.json`維持殖群生命與人口唯一權威；`world-state.json`僅放生態、跨巢活動、人群模型衍生索引；日誌突出影響。進入儲存模式切換前須先做14→100→1000→10000**純測試情境**，不得拿假設數量寫到當前劇情。
5. 本repo目前是文檔/存檔，**沒有已實作大量人口模擬執行引擎**；本規格是未來每回合推演/將來開發引擎共同遵守的資料契約，不宣稱通過效能壓測。
